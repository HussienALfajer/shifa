# Backlog

Status: Living · Last updated: 2026-11-09 · Owner: product owner

Non-blocking findings from reviews and small follow-ups. Each item names its source; remove it when done.

- **CI pub cache** (0.2-04 review): cache `~/.pub-cache` in the `verify` job, keyed on `pubspec.lock`, with a SHA-pinned `actions/cache`. Speed only.
- **Dart vulnerability scanning** (0.2-04 security review): nothing scans `pubspec.lock` for advisories; Dependabot alerts are off. Turn on Dependabot alerts (owner, repo settings) or add a checksum-pinned OSV-Scanner step to the `audit` job.
- **pub minimum release age** (0.2-04 security review): pub has no 24-hour guard like pnpm; add a CI check that fails when a `pubspec.lock` entry changed against the base was published on pub.dev less than 24 hours ago.
- **Dart format scope** (0.2-04 review): package `lint` scripts check `lib test`; use `.` once a package has `bin/`, `tool/` or `integration_test/`.
- **Health probe off the admin path** (0.2-06a security review L2): `/health/ready` and the startup check use `withPlatformAdmin('health-check', …)`. Before the audit slice gives that path its own role and audit rows, add `db.ping()` to `@shifa/db` (role check kept, no admin context) and switch both callers; also keep `/health/*` off the public route at the proxy.
- **Client-chosen request ids** (0.2-06a security review L7): any client may pick its `x-request-id` (strictly formatted). Once the reverse proxy exists, accept it only from the proxy or log the client's value under a separate key.
- **Bundled driver version** (0.2-06a review): the API bundles `@shifa/db` but resolves `pg` and `drizzle-orm` from its own pins. Add a check that `apps/api` and `packages/db` pin the same versions.
- **tsdown's `yuku` dependency** (0.2-06a security review): `rolldown-plugin-dts` pulls `yuku` (single maintainer, native binaries) though `dts: false` never loads it; watch it at each tsdown upgrade.
- **Bind the checked scope to the handler** (0.2-06c security review M1, before Phase A routes): the guard checks the principal's active tenant/branch, then drops it. Store `{ principal, scope }` on the request, expose it with a `@CurrentScope()` param decorator, require `withTenant()` to take its tenant only from there, and add a test that fails when a handler's tenant differs from the checked scope.
- **Routes outside the guard** (0.2-06c security review L3): raw Fastify routes (`fastify.get`, `@fastify/static`, Swagger UI in 0.2-07, CORS `OPTIONS`) skip the Nest guard and look like `@Public` rows in the matrix. Add a test comparing Fastify's route list with controller routes from `DiscoveryService`, and a rule against raw routes; consider a written reason per public row.
- **Permission catalogue at start-up** (0.2-06c security review L5): inject a `PERMISSION_CATALOGUE` (production `PERMISSIONS`, tests add test keys), refuse unknown keys in `AccessCheck`, test that `PRODUCTION_GRANTS` uses catalogue keys only; optionally lint `src/**` against importing `test/**`.
- **Explicit HEAD before GET** (0.2-06c security review L8): `routeList()` drops a HEAD route whenever a GET exists on the same URL; compare handlers instead so an explicit `@Head()` declared first keeps its matrix row.
- **Matrix for body-validated routes** (0.2-06c review 4): the matrix knows only 200/401/403 and sends no body; Phase A POST routes need a sample body per route or "any non-401/403 status = allowed".
- **Vacuous assertion in the matrix test** (0.2-06c review 7): `expect(NoAuthAdapter).toBeDefined()` in `route-matrix.test.ts` proves nothing; assert `app.get(AUTH_PORT) instanceof NoAuthAdapter` instead (locked test in 0.2-06c).
- **AuthPort contract** (0.2-06c security review, Phase A): document that `branchId` belongs to `tenantId`, roles come from server-side membership, `userId` is an opaque UUID (it is logged), adapter errors never carry tokens or phone numbers; validate the principal with Zod.
- **Cross-module table access** (0.2-06d plan): once modules own Drizzle schema files, extend `module-imports.test.ts` so a module reads and writes only its own tables (no import of another module's schema, no raw SQL naming its tables).
- **Subpath import aliases** (0.2-06d review 5): `boundaryViolation` resolves relative, absolute and `@/` specifiers only. If `apps/api/package.json` ever defines `imports` (`#modules/...`), resolve them too, or the alias becomes a loophole.
- **Parent rows for child isolation cases** (0.2-06b review N3, before the first table with a tenant FK): `seed` may write only its own table, so a child table cannot seed its parent. Add `prepare(tx, tenantId)` to `defineIsolationCase` (runs before `seed` for both tenants, never in the forged-insert step).
- **Joined read paths** (0.2-06b review N6): the runner checks only the `tenant_id` the path returns. A path joining a second tenant table should return that table's `tenant_id` too (e.g. `patientTenantId`), and the runner should check every `*tenant_id`/`*TenantId` column.
- **Append-only tenant tables** (0.2-06b security review B7, before signed notes, payments or the audit log): the presence check requires UPDATE and DELETE policies and the runner treats `permission denied` like an RLS refusal. Add an `appendOnly` class option: no UPDATE/DELETE privilege for `shifa_app`, and the runner expects both refused with "permission denied".
- **Policy roles** (0.2-06b security review B1): count only policies whose `polroles` include PUBLIC or `shifa_app` as coverage (fails closed today: default deny).
- **Grants beyond PUBLIC** (0.2-06b security review B2): require that only `shifa_owner` and `shifa_app` hold privileges on `public` tables, at table and column level.
- **SECURITY DEFINER functions and rules** (0.2-06b security review B3, B4): allow-list definer functions (each with `SET search_path`), fail on any rule other than `_RETURN` in `public`, and check triggers that write into global tables.
- **Personal data in global tables** (0.2-06b security review B5, before PLT-07): global tables with personal data (global patient account, practitioner) need their own policy on `app.user_id`; flag global tables with a foreign key to a tenant table.
- **Sequences** (0.2-06b security review B6): a shared sequence or serial column shows other tenants' volume; prefer uuid keys and per-tenant counters (SCH-16 queue numbers), and list sequences in the presence check.
- **Pin `current_tenant_id()`** (0.2-06b security review B8): assert its body, volatility, `SECURITY INVOKER` and settings match the baseline, since every policy depends on it.
- **Runtime-created objects and large objects** (0.2-06b security review B9, B10): partitions created by jobs never reach the CI catalog; check `pg_largeobject_metadata` ownership, or revoke large-object use from `shifa_app`.
- **Newest main for the migration order rule** (0.2-07a review 4): `check-drift` reads `main` before `origin/main`; a stale local `main` can hide a rebase that slipped an older migration under a merged one. Compare against the newer of the two refs. In CI (shallow checkout, no `main`) the rule is skipped; fetching `main` in the `verify` job would enable it there.
- **Schema drift test against the real schema** (0.2-07a review 5): `drift-migrations.test.mjs` replaces `src/schema/index.ts` with a new table; once Phase A adds tables that becomes drop + create. Append a column to the real schema instead (locked test in 0.2-07a).
- **`--full --fix` for Dart outputs** (0.2-07a review 5): `--fix` skips `full` checks unless `--full` is passed; 0.2-07c documents `--full --fix` for the Dart client.
- **Contract check: global prefix and RouterModule paths** (0.2-07b review N3): the start-up check compares contract paths with controller + handler paths only. Before `app.setGlobalPrefix()`, `RouterModule` or `enableVersioning()` is used, include them (or refuse to start when present); `@Version()` is already refused.
- **Real OpenAPI 3.1 validation** (0.2-07b review N4): `openapi.test.ts` checks the document by shape and the builder refuses unresolved `$ref`s, but no OAS 3.1 schema validator runs. Add one with 0.2-07c (the client generators parse the document anyway).
