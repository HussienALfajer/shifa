# Spec 0.3-S6: Voice — TTS listening test and kiosk playback (spike)

Status: Approved (owner, 2026-11-18) · Date: 2026-11-18 · Risk tier: T1 (vendor API keys in a public repository; no patient data, no schema; throwaway code) · Owner: product owner
Requirements: VOX-01, VOX-02, VOX-03 (name clips only), VOX-06, VOX-08 (tashkeel step only), VOX-09, VOX-10, VOX-11, VOX-12, VOX-13, VOX-16, VOX-17, VOX-18 · Decisions: [ADR-0020](../../adr/0020-voice-calling-voice-packs.md), OD-11, OD-50; result in a new ADR-0037 amending ADR-0020

## Goal
ADR-0020 names Azure `ar-SY` as the primary voice without anyone having heard it next to the alternatives, and assumes a cached kiosk page can play announcements unattended. This spike generates the same Arabic test set with Azure `ar-SY`, Google Chirp 3 HD `ar-XA` and self-hosted SILMA TTS behind one throwaway `TtsProvider` interface, lets the owner rate it blind in a static listening page, and builds a minimal display page that caches a pack and plays a serial queue, tested in Chromium and on an Android TV emulator. Owner decisions (2026-11-18, OD-50): the owner is the only listener and the result is final for vendor and voice; no physical TV box (emulator and Chromium only; a real box before the first pilot); cloud free tiers only; SILMA on the owner's machine; 100 public first names; no Turkish; 50 chosen numbers.

## User stories
- Owner (المالك) → rates anonymous clips in the listening page (صفحة الاستماع) → learns which vendor and voice to use for the first voice packs, and why.
- Receptionist (موظف الاستقبال), later → presses "التالي" → the waiting-room screen plays chime, number and room once, with no overlap and no tap on the TV.
- Developer → swaps the provider → regenerates the pack with one command; nothing else changes.

## Acceptance criteria
1. **Provider interface (VOX-09):** `TtsProvider.synthesize(text, voice) → audio` with adapters for Azure (`ar-SY-LaithNeural`, `ar-SY-AmanyNeural`), Google Chirp 3 HD `ar-XA` and SILMA TTS v1 (pinned weights, Apache-2.0, run in a pinned container on the owner's machine). One command generates the whole test set per provider into an untracked folder with a manifest (text, voice, provider, SHA-256, duration, characters billed).
2. **Voices:** a short pre-round (5 phrases × 6 Chirp 3 HD voices, 3 male and 3 female) lets the owner pick one male and one female Google voice; SILMA uses its own default reference voice (no cloning of a real person). The blind test therefore has five voices.
3. **Test set:** chime; "الرقم {N}" for 50 numbers covering the grammar cases (1, 2, 3–10, 11, 12, 13–19, 20, 21, 99, 100, 101, 102, 110, 111, 200, 300, 999 and others); "إلى العيادة {1–5}" and two synthetic "عيادة الدكتور {X}" phrases; 100 Syrian first names (male and female, with Kurdish and Turkmen names common in Azaz and hard cases), each in a diacritised form, plus 20 of them also undiacritised; 10 full announcements (chime → name → number → room, VOX-01/VOX-03). Numbers are written as Arabic words by one normaliser; the same text goes to every provider.
4. **Names list:** compiled from public name lists, never from patients; committed as `spikes/s6-voice/data/names.json` with tashkeel; the owner reviews the tashkeel before generation.
5. **Listening page:** a static page (no server) shows clips in random order under a random code, never the provider or voice; per clip the owner gives naturalness 1–5 and, for numbers and names, "correct / wrong" with an optional note; ten full announcements are also compared in pairs. Progress survives a reload; at the end the page downloads a results JSON. The code-to-voice key is a separate file, joined only by the analysis script.
6. **Analysis:** a script turns the results JSON and the key into the report table: mean naturalness per voice and category, wrong numbers and names per voice, pair preferences, diacritised vs undiacritised error rate. Decision rule (OD-50): the voice with the best mean naturalness among those with no wrong number wins; a tie goes to fewer wrong names. A voice with a wrong number may win only if a corrected text fixes it in a regeneration the owner confirms.
7. **Display page (VOX-11, VOX-12, VOX-13, VOX-16, VOX-18):** a minimal kiosk page caches a pack (manifest + clips) through a service worker, plays each call by Web Audio with clips decoded once and scheduled back-to-back, keeps a FIFO queue with a 1.5 s gap, ignores a duplicate or older-than-60 s `call_id`, and falls back to chime plus visual flash when a clip or the pack is missing.
8. **Autoplay and wake (VOX-17):** in Chromium with the default autoplay policy the page shows "اضغط لتفعيل الصوت" until one tap and then plays every later call without a tap; with the kiosk autoplay setting it plays with no tap. Wake Lock is requested and re-acquired after the page is hidden and shown.
9. **Android TV emulator:** the same page runs on an Android TV emulator image (version recorded) in Fully Kiosk Browser's free version (downloaded from its official site only after the owner's yes at that step) and, where present, the emulator's own browser or WebView; recorded per runtime: autoplay without a tap, service-worker cache surviving a restart with the network off, Wake Lock, gapless joins (audible gap measured by recording the output).
10. **Measurements (report only):** generation time per clip per provider; SILMA on the owner's CPU and on the GPU if present; pack size at two Opus or MP3 bitrates; characters billed per provider for this run and an estimate per clinic per month; first-call latency on the display page after reload.
11. **Vendor terms (VOX-10, domain §7.2):** the report quotes the relevant public terms of Azure, Google Cloud and SILMA's licence on generating audio for Syrian end users from a non-Syrian account, with links and dates.
12. **Result:** `docs/spikes/s6-voice.md` answers the questions below with the versions tested; ADR-0037 (Accepted on owner approval) records the primary provider and voice, the fallback order, text normalisation and the display playback rules; ADR-0020 gets only `Status: … · Amended by ADR-0037`. OD-11's vendor and voice part closes; name-calling default and Turkish stay open. Roadmap and voice-calling domain doc updated.

## Questions the spike must answer
- Which provider and voice does the owner prefer, by how much, and does any make number-grammar or name errors?
- Does tashkeel change name pronunciation enough to keep the receptionist preview step (VOX-08)?
- Is SILMA fast enough on a CPU-only server to be a real fallback?
- Can a cached kiosk page play calls unattended on Android TV (Fully free vs PLUS), and what must a clinic set once?
- What does a full 1–999 pack cost and weigh per voice?

## Edge cases
- A provider rejects or rate-limits a request: the generator retries with backoff, then records the failure in the manifest; it never silently skips a clip.
- SSML differences: plain text only, so all providers get the same input.
- A call arrives while the pack is still downloading, while another call is playing, and twice with the same `call_id`.
- The page reloads mid-queue; the network drops after the pack is cached.
- Offline: the display plays from cache with no network; generation needs the network and runs only on the owner's machine.
- Permissions per role: not modelled (single owner; the display page has no login in the spike).

## Money, abuse and privacy
- No patient data (ADR-0023): only public first names and synthetic doctor names; no surnames, specialty or diagnosis (VOX-29).
- API keys live in an untracked env file, never committed (ADR-0026) or logged; a check fails if a key pattern appears in the spike folder or logs. Generated audio is not committed (size and vendor terms); the manifest with hashes is.
- Money: free tiers only (OD-50). The generator counts characters before calling and refuses a run that would pass Azure F0 (500,000 characters per month) or Google Chirp 3 HD's free 1,000,000; the expected run is about 50,000 characters per provider.
- The results JSON holds only clip codes, scores and notes; no listener identity.

## Out of scope
Listening by receptionists and a physical TV box (OD-50: a real box before the first pilot); Turkish voices and wording (OD-11 stays open on that); human-recorded packs; the full 1–999 pack and its native-speaker sign-off (Phase A); the automatic tashkeel model; name-calling default (OD-11); realtime delivery, BroadcastChannel local mode, reception controls and the real `display-web` app (Phase A); Fully Kiosk PLUS purchase; paid vendors such as ElevenLabs.
