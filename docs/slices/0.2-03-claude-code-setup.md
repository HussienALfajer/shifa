## Goal
Every Claude Code session in this repository starts with short project instructions, cannot touch secrets, generated files or protected docs, cannot bypass formatting through the shell, keeps working until `verify` is green, and has reviewer agents and the slice-loop skills at hand.

## Plan
1. `.claude/settings.json`: model, `effortLevel` medium, attribution, deny rules (env, keys, secrets, dumps), ask rules (merge, migrate, deploy), `disableBypassPermissionsMode`, sandbox with a network allowlist (effective under WSL2), hooks.
2. Hooks in Node (`.claude/hooks/`), policy in `lib/policy.mjs`:
   - `guard-edits` (PreToolUse Edit/Write/MultiEdit/NotebookEdit): secrets and dumps, generated files and lockfiles, `docs/research/archive/`, tracked ADRs, tracked migrations, locked tests from `.claude/state/locked-tests.txt`.
   - `guard-bash` (PreToolUse Bash/PowerShell): redirection, `tee`, `sed -i`/`perl -i` and PowerShell writes into source folders; reading `.env` or keys; `--no-verify`; force push; push to `main`; permission bypass.
   - Both guards fail closed on an unreadable event.
   - `format-after-edit` (PostToolUse): Biome or `dart format` on the edited file.
   - `stop-verify` (Stop): `verify fast` when code changed; blocks the stop with the summary on failure; skips on `stop_hook_active` or a held lock.
   - `session-end`: warns about uncommitted work.
3. Agents: `reviewer` (Opus, high), `security-reviewer` (Opus, xhigh), `checker` (Haiku, low).
4. Skills (user-invoked only): `/spec`, `/slice-plan`, `/build-slice`, `/audit-phase`.
5. Rule `.claude/rules/patient-data.md` scoped to `apps/**` and `packages/**`.
6. Full root `CLAUDE.md` (commands, slice loop, non-negotiables, what hooks enforce, gotchas).

Tests written first: `scripts/test/claude-hooks.test.mjs` (policy, 50 cases).
Estimated hand-written lines: ~750.
