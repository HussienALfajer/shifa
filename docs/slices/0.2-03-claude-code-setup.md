## Goal
Every Claude Code session in this repository starts with short project instructions, cannot touch secrets, generated files or protected docs, cannot bypass formatting through the shell, is sent back to work when `verify` fails on uncommitted code, and has reviewer agents and the slice-loop skills at hand.

## Plan
1. `.claude/settings.json`: model, `effortLevel` medium, attribution, deny rules (named `.env` files, keys, secrets, dumps; `.env.example` stays editable), ask rules for Bash and PowerShell (merge, migrate, deploy), `disableBypassPermissionsMode`, sandbox with a network allowlist (effective under WSL2), hooks.
2. Hooks in Node (`.claude/hooks/`), policy in `lib/policy.mjs`:
   - `guard-edits` (PreToolUse Edit/Write/MultiEdit/NotebookEdit): secrets and dumps, generated files and lockfiles, `docs/research/archive/`, ADRs accepted on `main` (Status-line edits allowed), migrations merged to `main`, locked tests from `.claude/state/locked-tests.txt` (paths normalised).
   - `guard-bash` (PreToolUse Bash/PowerShell): writes into source folders by redirection, `tee`, `sed -i`/`perl -i` or PowerShell (`Set-Content`/`sc`, `Add-Content`/`ac`, `Out-File`), with relative, absolute or backslash paths; reading `.env` or keys (incl. `grep`, `Select-String`); `--no-verify`; force push; push to `main`; permission bypass. Commit messages, PR bodies and heredoc bodies are ignored.
   - Both guards fail closed on an unreadable event or an internal error.
   - `format-after-edit` (PostToolUse): Biome or `dart format` on the edited file.
   - `stop-verify` (Stop): one `verify fast` attempt when code changed; skipped when the tree matches the last green run, during the red phase (`.claude/state/red-phase`) or when the lock is held; `verify` time-limited below the hook timeout.
   - `session-end`: warns about uncommitted work.
3. Agents: `reviewer` (Opus, high), `security-reviewer` (Opus, xhigh), `checker` (Haiku, low).
4. Skills (user-invoked only): `/spec`, `/slice-plan`, `/build-slice`, `/audit-phase`.
5. Rule `.claude/rules/patient-data.md` scoped to `apps/**` and `packages/**`.
6. Full root `CLAUDE.md` (commands, slice loop, non-negotiables, what hooks enforce and what they cannot see, gotchas).

Tests written first: `scripts/test/claude-hooks.test.mjs`.
Estimated hand-written lines: ~900.

## Accepted gaps
- The shell guard reads command text: `cd apps && echo > x`, `cp`/`mv`, `node -e writeFileSync` and `git checkout --` into source folders are not caught. `CLAUDE.md` says not to use them; CI catches unformatted or failing code.
- `locked-tests.txt` itself can be edited; the reviewer agent checks that locked tests were not weakened.
- A bare `git push` while on `main` is not caught by the hook; branch protection refuses it.
