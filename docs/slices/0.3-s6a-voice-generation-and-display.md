# 0.3-S6a Voice spike: test set, TTS providers, generator, kiosk display page

Status: In review (owner review of names and numbers pending) · Tier: T1 (vendor API keys in a public repository; no patient data, no schema, throwaway code). The key-leak check, the SILMA image and the new workflow also get a `security-reviewer` pass. · Branch: `chore/0.3-s6a-voice-generation-and-display`
Spec: [0.3-S6 Voice](../specs/spikes/0.3-s6-voice.md) criteria 1, 3, 4, 7, 8 and the generation half of 10 · Requirements: VOX-01, VOX-02, VOX-03 (name clips only), VOX-06, VOX-08 (tashkeel step only), VOX-09, VOX-10, VOX-11, VOX-12, VOX-13, VOX-16, VOX-17, VOX-18 · Decisions: ADR-0020, ADR-0023, ADR-0026, OD-11 (stays open), OD-31, OD-50

The spike is split in two (owner, 2026-11-18): this slice builds all the machinery that CI can prove with a fake provider (audio generation and the kiosk display page); [0.3-S6b](0.3-s6b-voice-listening-and-result.md) builds the listening page and analysis and holds the owner's real run, the emulator run, the report and ADR-0037. This slice is about **5,200 hand-written lines, over the ~4,000-line budget of [ADR-0032](../adr/0032-slice-size-budget-4000-lines.md) by the owner's choice** of two PRs. It is built in seven checkpoints (A–G); each ends green and committed, so a session can stop at any checkpoint and the next one resumes from "Stopped at". Generation (A–D) and display (E–G) depend only on the manifest format fixed in C.

## Goal
A developer runs one command per provider and gets the whole S6 test set (chime, 50 numbers, rooms, 100 names in two forms, 10 full announcements) as audio files in an untracked folder, with a manifest that records text, voice, provider, SHA-256, duration and characters billed; every provider sits behind one `TtsProvider` interface, and CI never calls a vendor. A minimal kiosk page caches such a pack through a service worker and plays calls gaplessly through a serial queue with dedupe, stale-call, fallback, autoplay-gate and Wake Lock rules, each proven by Playwright in Chromium.

## Choices made by this plan

### Generation
- **Plain text only:** every adapter sends the same normalised string; no SSML (spec edge case). Azure's REST endpoint needs a minimal `<speak>` wrapper with the voice name only (no prosody tags); Google Chirp 3 HD gets `text` input, not `ssml`.
- **Number words:** one normaliser `numberToArabicWords(n)` for 1–999, Modern Standard Arabic, nominative, masculine counting form as read after "الرقم" (e.g. 3 → ثلاثة, 11 → أحد عشر, 21 → واحد وعشرون, 102 → مئة واثنان, 200 → مئتان). The vectors for all 50 chosen numbers are shown to the owner with the tashkeel review; a wrong vector is fixed before any generation.
- **Names:** `data/names.json` (100 entries: 50 male, 50 female; Arabic, Kurdish and Turkmen names common in Azaz, and hard cases: hamza, shadda, long vowels, foreign-origin names), each with `id`, `diacritised`, `plain`, `gender`, `origin`, `hard` and `source` (public name lists, cited by URL); 20 flagged `alsoPlain` for the undiacritised clip. Compiled by Claude from public lists, never from patients (ADR-0023); the owner reviews the tashkeel at checkpoint B before any real generation.
- **Doctor phrases:** two synthetic "عيادة الدكتور {X}" phrases with first names from `@shifa/testing` that are not in `names.json`.
- **Full announcements (VOX-01, VOX-03):** 10, each a list of clip ids (chime → name → number → room), joined at play time as the display does; never synthesized as one string.
- **Chime:** a synthetic two-tone chime (~1 s) from a small deterministic WAV writer (no downloaded sound); the same file for every provider.
- **SILMA:** SILMA TTS v1 (Apache-2.0) in a container built from `spikes/s6-voice/silma/Dockerfile`: Python base pinned by digest, the official inference package pinned by version and hash, weights from the official Hugging Face repository by commit revision, checked by SHA-256 at build time; a small HTTP wrapper `POST /synthesize {text} → audio/wav` bound to `127.0.0.1`. Default reference voice only, no cloning. Built and run only on the owner's machine (OD-50); the licence file in the image is recorded.
- **Audio format:** providers return lossless output (Azure `riff-24khz-16bit-mono-pcm`, Google `LINEAR16`, SILMA WAV) for listening; Opus/MP3 packs for the size measurement are made in 0.3-S6b.
- **Budget guard (OD-50):** before any call the generator sums the characters of the planned requests (each vendor's billing rule) plus this month's earlier runs from a local ledger in the untracked output folder, and refuses a run that would pass Azure F0's 500,000 or Google Chirp 3 HD's 1,000,000 free characters. `--dry-run` prints the count and exits.
- **Retries:** exponential backoff with jitter on 429 and 5xx (max 5 attempts, honouring `Retry-After`); a clip that still fails is written to the manifest as `failed` with status and vendor error code, and the run exits non-zero; never a silent skip. A re-run regenerates only missing or failed clips.
- **Keys (ADR-0026):** read from `spikes/s6-voice/.env.local` (git-ignored; `.env.example` with empty values committed); never in logs, errors or the manifest (HTTP errors logged as status + vendor code). `scripts/check-no-keys.ts` scans the spike folder and the output/log folder for Azure (32 hex), Google (`AIza…`, service-account JSON markers) and generic `key=` patterns; it runs in `test:spike` and at the generator's exit.
- **Output:** audio in `spikes/s6-voice/.out/<provider>/<voice>/` (git-ignored; size and vendor terms); real manifests are committed in 0.3-S6b; the fake provider's manifest is a test fixture.

### Display page
- **Spike only, not `display-web`:** no realtime server. Calls arrive through a test hook (`window.__s6.call({callId, number, room, nameClipId?, issuedAt})`) and a small local control page that posts the same object over `BroadcastChannel` in the same browser profile, for manual and emulator runs.
- **Pack:** `pack/manifest.json` (the generation manifest plus a `packVersion` hash) and clips on the same origin; the service worker precaches every listed clip (Cache Storage, cache per `packVersion`), answers cache-first, and when online compares the manifest with the network copy (VOX-11 diff, reported only). No third-party SW library.
- **Playback (VOX-12, VOX-13):** one `AudioContext`; every clip decoded once into an `AudioBuffer` map at pack load; a call becomes a buffer list scheduled from `ctx.currentTime + 0.05`, each `start(t)` at the previous end; the next call waits for the last end + 1.5 s.
- **Dedupe and stale (VOX-16):** seen `call_id`s kept in `sessionStorage` (a reload mid-queue does not replay); calls older than 60 s by `issuedAt` dropped with a logged reason; `played` acknowledgements go to the console and an in-page log only.
- **Fallbacks (VOX-18):** missing name clip → number-only; missing number or room clip, or no pack → chime (an `OscillatorNode` tone if even the chime is missing) + full-screen flash of number and room for ~8 s. The flash runs for every call (VOX-14 shape only; no "last 5 calls" strip).
- **Autoplay gate and Wake Lock (VOX-17):** if the `AudioContext` stays `suspended` after `resume()`, the page shows "اضغط لتفعيل الصوت" full-screen until one tap; with `--autoplay-policy=no-user-gesture-required` the gate never shows. `navigator.wakeLock.request('screen')` on start and on every `visibilitychange` → visible; failure shown in the status line.
- **First-call latency:** call arrival → first `start()`, and page load → pack ready, shown in the status line and exposed to Playwright; 0.3-S6b records them after reload on each runtime.
- **Test audio:** the fake-provider pack (tones of known length); gaplessness checked from the schedule and, in one test, by rendering it in an `OfflineAudioContext` and measuring silence.

### Both
- Suites are `test:spike` only (OD-31), run by the manual workflow; typecheck and lint run in `verify`.

## Tests written first
Generation (A–D):
- `tts/test/numbers.test.ts` (3): every entry of `data/numbers.json` matches; 0 and 1000 refused; output has no digits and no tashkeel.
- `tts/test/testset.test.ts` (3, 4): category counts (1 chime, 50 numbers, 5 rooms, 2 doctors, 100 + 20 names, 10 announcements); announcements reference existing clips in the order chime → name → number → room; ids unique; `names.json` valid (100 entries, 50/50, every `diacritised` has tashkeel and strips to `plain`, 20 `alsoPlain`, every entry has a `source`); no name collides with the doctor phrases.
- `tts/test/manifest.test.ts` (1): a fake run covers every clip with SHA-256 matching the file, duration > 0 and `status: ok`; a missing clip fails the completeness check.
- `tts/test/retry.test.ts` (edge case): 429 with `Retry-After` then success; five 503s → `failed` in the manifest and non-zero exit; a re-run regenerates only that clip.
- `tts/test/budget.test.ts` (money): a run past the free limit (count + ledger) is refused before any provider call; `--dry-run` makes no call.
- `tts/test/providers.test.ts` (1): each adapter sends the documented request shape (voice, output format, plain text, auth header) to a mock server and maps 429/5xx to retryable errors; the same text reaches every adapter byte for byte.
- `tts/test/no-keys.test.ts` (privacy): a planted fake key fails the check; errors and the manifest of a failing adapter run contain no key.

Display (E–G):
- `display/test/queue.test.ts` (7): FIFO order; next call ≥ 1.5 s after the previous end; duplicate `call_id` dropped; call older than 60 s dropped (boundary recorded); seen ids survive a simulated reload.
- `display/e2e/cache.spec.ts` (7): after first load every clip is in Cache Storage; offline reload still plays from cache; a call during the pack download waits, then plays (or falls back if the pack fails).
- `display/e2e/queue.spec.ts` (7): 5 calls within 1 s play in order, never overlapping, gaps ≥ 1.5 s; the same `call_id` twice plays once; a stale call does not play; a reload mid-queue does not replay finished calls.
- `display/e2e/gapless.spec.ts` (7, VOX-12): joins within a call are back-to-back (± 1 ms in the schedule; no silence over 10 ms in the offline render).
- `display/e2e/fallback.spec.ts` (7, VOX-18): missing name → number-only; missing number → chime + flash; no pack → oscillator chime + flash for ~8 s.
- `display/e2e/autoplay.spec.ts` (8): default policy → gate, no audio until one click, then three later calls play with no click; kiosk-autoplay project → no gate.
- `display/e2e/wakelock.spec.ts` (8): lock requested on start and again after hidden → visible (API stubbed where headless Chromium lacks it; recorded as a limit for the emulator run).
