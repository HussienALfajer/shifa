## Goal
One command, `node scripts/check-drift.mjs`, re-runs every registered generator into a temporary directory and fails, naming each stale file, when the committed output differs. It runs inside `verify` (fast and full) and therefore in CI. The first registered check is migrations: the Drizzle schema in `packages/db/src/schema` must match the latest committed migration snapshot, and migration folders must be well-formed and in order.

## Plan
1. **Contracts / API / web / Flutter.** None.
2. **Runner** (`scripts/check-drift.mjs` + `scripts/lib/drift.mjs`):
   - Registry `scripts/drift.config.mjs`: `{ name, inputs, outputs, generate(outDir), full? }` per check. `generate` writes into a fresh temp dir; the runner compares byte-for-byte (after LF normalisation) with the committed files listed in `outputs`, reporting `stale`, `missing` and `extra` paths, never file contents.
   - `--fix` regenerates in place (the documented way to update generated files; the edit guard already refuses hand edits under `generated/`).
   - `full: true` checks run only in `verify:full` (for slow toolchains such as Dart codegen in 0.2-07c).
   - Exit codes: 0 clean, 1 drift, 2 generator crashed (log path printed).
3. **Migration check** (registered as `migrations`):
   - Schema vs snapshot: run `drizzle-kit generate` (pinned rc.5) against `drizzle.config.ts` with `out` pointed at a temp copy of `packages/db/migrations`; any new migration folder = drift ("schema changed without a migration: run /db-migration").
   - `drizzle-kit check` on the committed folder (snapshot chain and collisions).
   - Folder rules: name `YYYYMMDDHHMMSS_<snake_name>`, strictly increasing, each has `migration.sql` + `snapshot.json`; on a branch, every new folder sorts after the newest folder on `main` (catches a rebase that slipped an older timestamp under a merged one).
   - Needs no database (Drizzle diffs snapshots offline). Confirm at build; if rc.5 needs a connection, use the harness container under `acquireDbTestLock()`, as the boot check does.
4. **Wiring.** `verify.mjs` gains a `drift` step after `file-length` (fast and full). CI needs no change (it runs `verify:full`). `/db-migration` skill and `packages/db/CLAUDE.md` mention the check and `--fix` does not apply to migrations (a migration is written with `/db-migration`, never regenerated).
5. **Docs.** Roadmap checklist note; `docs/process/development-workflow.md` names `check-drift` where it lists the checks.
