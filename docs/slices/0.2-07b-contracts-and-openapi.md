## Goal
`packages/contracts` holds named Zod 4 schemas, the error envelope and the central error-code catalogue. Every API route declares its contract; the API validates requests with it and refuses to start if a route has none. An OpenAPI 3.1 document is generated from the routes and contracts, committed, and checked for drift in CI.

## Decisions made while building
- **Own interceptor, not Nest's `StandardSchemaValidationPipe`** (present in 12.4.0): the pipe validates one parameter at a time with a schema per decorator and answers with Zod's messages (some quote the input). One interceptor per contract runs after the guard (anonymous callers get 401, never a schema hint), validates params → query → body, reports every issue at once as `{ path, code }` and hands the handler the parsed values.
- **Start-up check goes further than planned**: besides missing contract and method/path mismatch it refuses unnamed request/response schemas, a `params` object whose keys differ from the path's `:names` (OpenAPI needs them declared), a success status the contract lacks (POST defaults to 201), non-camelCase and duplicate `operationId`s. `operationId` became a required contract field (07c turns it into client method names).
- **Document**: components are every named schema reachable by `$ref` from the paths (test-only schemas never leak into the production document); `$schema`/`$id` stripped; params/query expand into OpenAPI parameters from their named object; 400 (when the route has a request schema) and 401/403 (protected routes) with `ErrorEnvelope` are added automatically; `x-public: true` or `x-permission: <key>` per operation; no `securitySchemes` until auth exists (Phase A).
- **Generator**: `apps/api/scripts/generate-openapi.ts` bundled by `apps/api/tsdown.openapi.config.ts` into `apps/api/node_modules/.cache/openapi/` (decorator metadata needs a bundle, as for `main.ts`), run by `scripts/lib/drift-openapi.mjs` (fast mode, fixable). `generated/` is excluded from Biome so the committed text is exactly the generator's.
- **Reviewer round (blocking B1–B3 fixed)**: 400 detail paths keep only keys the schema declares and array indexes, other segments (record, catchall keys) become `*` (`schema-walk.ts`); the check refuses `@Body`/`@Query`/`@Param` without the matching schema, `@Req`/`@RawBody`/own param decorators, `@Version`, method-less routes, wildcard/optional path syntax and a non-object query; components render per contract (`components.ts`): request schemas in Zod's input mode, responses in output mode without `additionalProperties: false`, only schemas reachable from contracts, and the builder throws on two schemas sharing an id, a schema whose input and output shapes differ, an unnamed reused/recursive schema or an unresolved `$ref`. Regression tests: `apps/api/test/contract/hardening.test.ts` (7 of 9 fail on the pre-fix source).
- Test-only routes use `testContract(method, path)` (`apps/api/test/support.ts`: string params per `:name`, any body for POST/PUT/PATCH); every existing test controller got one.
- Locked-test change: `openapi.test.ts` hoisted `expect.any`/`expect.objectContaining` into `unknown`-typed constants to satisfy `no-unsafe-assignment` (type-only, assertions unchanged).
