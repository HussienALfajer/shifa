# 0.4-03 `packages/ui` scaffold, Storybook, lint rules, test harness and CI checks

Status: Planned · Tier: T0 (changes the required CI gate, adds a beta base dependency with an agent bridge, vendors an upstream agent skill into `.claude/`) · Branch: `feat/0.4-03-ui-scaffold`
Spec: [0.4 Design system foundations](../specs/design-system/0.4-design-system-foundations.md) criteria 6, 9 (machinery), 11 (vendored skill, upgrade rule), 12 (bundle, first sync) · Requirements: none · Decisions: ADR-0039, ADR-0040, ADR-0011

After [0.4-02](0.4-02-design-directions-and-fonts.md). Split from the spec's proposed 0.4-03: the eight gate components are [0.4-04](0.4-04-rtl-gate-components.md). Four checkpoints (A–D); B starts with the owner's approval of the Button sheet.

## Goal
A developer can add a component to `packages/ui` and get, without extra set-up: semantic-token styling, stories in RTL/LTR × light/dark × both densities, interaction and axe tests in a real browser, and screenshot comparison in CI. Forbidden patterns fail lint. Button proves the whole path.

## Choices made by this plan
- **Stack:** React 19, `@ui-sdk/react` and `@ui-sdk/core` at one exact version (the newest at least 24 hours old; recorded here), Tailwind v4 reading `@shifa/tokens` generated CSS, Storybook (pinned major) with its Vitest addon and a11y addon, Vitest browser mode on Playwright Chromium.
- **Lint rules** in `tooling/eslint-config/rules/` (plugin `shifa`), each with failing fixtures: `no-physical-direction` (Tailwind `ml-*`, `left-*`, `text-left`… and CSS `left`/`right` properties), `no-hardcoded-design-values` (hex/rgb/hsl colours, arbitrary `[..px]` spacing, font families), `ui-sdk-only-in-ui` (`@ui-sdk/*` and `@base-ui/*` outside `packages/ui`), `no-ui-sdk-agent` (`@ui-sdk/react/agent` anywhere).
- **Story matrix:** one decorator renders a story in the eight combinations (direction × theme × density); `storyStates()` adds the text states from the spec's edge cases (long Arabic label, mixed direction, 200 % zoom, reduced motion).
- **Test helpers** (`packages/ui/test/`): `renderDir()`, `expectArrow()` (which arrow moves forward in each direction), `expectPopupSide()`, `typeArabic()`, digit helpers for both styles, `expectAxeClean()`. 0.4-04 uses them for the gate.
- **Screenshots:** Playwright against the built Storybook inside the pinned Playwright image (digest), baselines committed under `packages/ui/screenshots/`. Baselines are produced only in that image (`pnpm ui:screenshots --update`, needs Docker; in the sandboxed WSL2 session this runs in CI through a manual `ui-baselines` workflow that uploads the new baselines).
- **CI:** new part `ui` of `verify full` (`--part ui`: Storybook build, Storybook test run with axe, screenshots) as a job behind the required `verify (full)` aggregator; `scripts/test/ci-verify-jobs.test.mjs` extended.
- **Design sheet first (ADR-0040):** Button is drawn in the proposals canvas (variants, sizes, all states, light and dark, RTL and LTR, both densities) and approved by the owner before its code.
- **Design-system bundle:** `packages/ui/scripts/bundle-design-system.ts` builds the one classic script (global `Shifa`), its stylesheet, a preview and guidelines per component into `packages/ui/design-system/` (generated, git-ignored), with React 19 carried beside it; `/design-sync` pushes it. Tried on Button first. If it cannot work (React 19, Tailwind v4 or UI SDK in a classic script), switch to static previews from Storybook as ADR-0040 allows, record it here and in the design doc, and tell the owner before 0.4-04.
- **Vendored skill:** upstream `ui-sdk` skill copied to `.claude/skills/ui-sdk/` at a pinned commit after the security reviewer reads it for instructions that reach outside development help; `scripts/test/vendored-skill.test.mjs` checks the tree hash against `VENDORED.json`.
