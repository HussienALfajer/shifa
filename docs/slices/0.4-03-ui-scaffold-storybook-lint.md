After [0.4-02b](0.4-02b-design-system-project-and-guide.md). Split from the spec's proposed 0.4-03: the eight gate components are [0.4-04](0.4-04-rtl-gate-components.md). Four checkpoints (A–D); B starts with the owner's approval of the Button sheet, D needs the owner for the sync.

## Goal
A developer can add a component to `packages/ui` and get, without extra set-up: semantic-token styling, stories in RTL/LTR × light/dark × both densities, interaction and axe tests in a real browser, and screenshot comparison in CI. Forbidden patterns fail lint. One command rebuilds what the Shifa Design System holds from the repository. Button proves the whole path, from the approved sheet to the design system.

## Choices made by this plan
- **Stack:** React 19, `@ui-sdk/react` and `@ui-sdk/core` at one exact version (the newest at least 24 hours old; recorded in Evidence), Tailwind v4 reading `@shifa/tokens` generated CSS, Storybook (pinned major) with its Vitest addon and a11y addon, Vitest browser mode on Playwright Chromium. Licences recorded with each dependency (UI SDK Apache-2.0, Storybook MIT, Phosphor MIT).
- **Lint rules** in `tooling/eslint-config/rules/` (plugin `shifa`), each with failing fixtures: `no-physical-direction` (Tailwind `ml-*`, `left-*`, `text-left`, `rounded-l-*`… and CSS `left`/`right`/`margin-left` properties), `no-hardcoded-design-values` (hex/rgb/hsl colours, arbitrary `[..px]` values, font families, Tailwind spacing steps that are not tokens), `ui-sdk-only-in-ui` (`@ui-sdk/*` and `@base-ui/*` outside `packages/ui`), `no-ui-sdk-agent` (`@ui-sdk/react/agent` anywhere, `packages/ui` included).
- **Tailwind spacing (backlog):** the Tailwind entry resets `--spacing-*` and maps the spacing scale to the `space.*` tokens only, so `p-14` or `p-0.5` do not compile to a value, and `space.0-5` gets a clean utility name. Radius (`rounded-sm/md/lg` = 8/12/16) and shadows by job only, as 0.4-01 and 0.4-02b left them.
- **Density on touch (backlog):** `DensityProvider` refuses `compact` on a coarse pointer (`(pointer: coarse)`) and falls back to `comfortable` with a development warning; compact stays for pointer devices (design doc).
- **Component colour pairs (backlog, `packages/tokens`):** the contrast test also checks the `fg`/`bg` siblings of every component group and requires a declared pair for every semantic colour outside `bg` and `border`. Button's component tokens are the first to pass it.
- **Plex font name (OD-59, owner 2026-11-20: rename):** `scripts/fonts-subset.mjs` renames the family inside the web subsets of IBM Plex Sans Arabic (name `Shifa Sans Arabic`, final name recorded in Evidence), keeping the copyright notice and the licence file; the CSS, the tokens' font family, the font test and the design system follow. Done in checkpoint A, before Storybook serves the fonts. Noto Naskh Arabic keeps its name (no reserved name).
- **Icons (backlog):** `@phosphor-icons/react` (exact pin, duotone by default) behind one `Icon` component that accepts a curated name list; a small Healthicons set kept as SVG files in `packages/ui/src/icons/health/` with its licence. Icons that point a direction (arrows, chevrons, "back") flip under `dir="rtl"`; the list is tested.
- **Story matrix:** one decorator renders a story in the eight combinations (direction × theme × density); `storyStates()` adds the text states from the spec's edge cases (long Arabic label, mixed direction, 200 % zoom, reduced motion). Synthetic names from `@shifa/testing` only.
- **Test helpers** (`packages/ui/test/`): `renderDir()`, `expectArrow()` (which arrow moves forward in each direction), `expectPopupSide()`, `typeArabic()`, digit helpers (typed Arabic-Indic digits are accepted and stored as Western ones, OD-20), `expectAxeClean()`. 0.4-04 uses them for the gate.
- **Design sheet first (ADR-0040, design doc "Designing in the project"):** the "Shifa Components (proposals)" canvas is created with the Shifa Design System installed (found by name, its README read first) and the Shifa Guide's rules kept. The Button sheet shows variants (primary, secondary, ghost, danger), sizes, every state (default, hover, focus, pressed, disabled, loading), with and without an icon, light and dark, RTL and LTR, both densities. No Button code is committed before the owner approves it.
- **Screenshots:** Playwright against the built Storybook inside the pinned Playwright image (version equal to the `@playwright/test` pin, by digest), one screenshot per story in the matrix; baselines committed under `packages/ui/screenshots/` and produced only in that image (`pnpm ui:screenshots --update`, needs Docker). In the sandboxed WSL2 session (OD-24) a manual `ui-baselines` workflow produces them and uploads them as an artifact; the workflow never pushes.
- **CI:** new part `ui` of `verify full` (`--part ui`: `packages/ui` browser tests, Storybook build, Storybook test run with axe, screenshots) as a job behind the required `verify (full)` aggregator; `verify full` without a part runs it too; `verify` fast stays without a browser. Workflows keep the `ci.yml` rules: actions pinned by commit SHA, `permissions: contents: read`, no secrets.
- **Vendored skill:** upstream `ui-sdk` skill copied to `.claude/skills/ui-sdk/` at a pinned commit after the security reviewer reads every file for instructions that reach outside development help (network calls, installs, the agent bridge, editing settings or hooks); a file that does is removed, or the vendoring stops and the owner is told. `VENDORED.json` records source, commit, licence and tree hash; `scripts/test/vendored-skill.test.mjs` checks it. The design doc gains the "UI SDK upgrade rule": an upgrade is its own PR, runs the whole `ui` part, and its PR body lists the upstream changes read. *Amended in checkpoint C (ADR-0041): the vendoring stopped at the security read; the guidance lives in our `/ui-component` skill instead (Notes from checkpoint C).*
- **Design-system producer (backlog) and bundle:** `packages/ui/scripts/design-system/` holds the brand-book README source, the cover and an assembly script that writes `packages/ui/design-system/` (generated, git-ignored): the README, `tokens.json` and a compiled `tokens.css` from `packages/tokens/generated/design-system/`, the six static fonts (renamed as above), the logo files, an Icons asset group (a representative Phosphor and Healthicons set) and the component bundle. `pnpm design-system:build` runs it. The bundle is one classic script (global `Shifa`, no `import`, no network call), its stylesheet, a preview and guidelines per public component, with React 19 carried beside it; `/design-sync` pushes it (the owner starts it). If React 19, Tailwind v4 or UI SDK cannot work in a classic script (after one try with React and Tailwind as separate globals), switch to static previews from the built Storybook as ADR-0040 allows, record it here and in the design doc, and tell the owner before 0.4-04.
