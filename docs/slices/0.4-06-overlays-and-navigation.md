## Goal
A screen can confirm, notify, reveal and switch: every overlay and navigation part the Phase A screens need, with correct focus, direction and motion.

## Components (7)
Alert dialog, drawer, tooltip, accordion, toast, segmented control, command palette.

## Choices made by this plan
- **Alert dialog** reuses Dialog (0.4-04) with `role="alertdialog"`, focus on the least destructive action, and no dismissal by outside click.
- **Drawer** opens from the logical end by default (`side="start" | "end" | "bottom"`); bottom is the tablet and phone form.
- **Toast:** one region per app, polite by default and assertive for errors; pause on hover and focus; a queue limit of three visible; status toasts carry icon and text, never colour alone (principle 7).
- **Tooltip:** never the only carrier of information; opens on focus as well as hover; none on touch.
- **Command palette** on UI SDK Command: Arabic search uses a `normalise` prop so Phase A can pass the name normaliser (ADR-0034); this slice ships a simple default (case and diacritics).
- **Motion:** durations from the motion tokens (120–240 ms); every animation off under `prefers-reduced-motion`; no blur or large shadow needed to read an overlay (low-end PCs).
- Follows the `/ui-component` skill; fallback procedure from 0.4-04 where a part fails in RTL.
