## Goal
A screen can confirm, notify, reveal and switch: every overlay and navigation part the Phase A screens need, with correct focus, direction and motion.

## Components (7)
Alert dialog, drawer, tooltip, accordion, toast, segmented control, command palette. UI SDK 0.1.0-beta.13 ships each one (`alert-dialog`, `drawer`, `tooltip`, `accordion`, `toast`, `segmented-control`, `command`), so none is hand-rolled.

## Choices made by this plan
- **Alert dialog** on UI SDK `AlertDialog` (re-planned 2026-11-22: the dedicated part exists, so it no longer wraps our Dialog), sharing Dialog's panel styles; focus on the least destructive action; no dismissal by outside click; the destructive action uses Button's danger variant.
- **Drawer** opens from the logical end by default (`side="start" | "end" | "bottom"`); bottom is the tablet and phone form, with UI SDK's grabber named; no snap points in this slice.
- **Toast:** one region per app (`<ToastProvider>` beside the existing providers), polite by default and assertive for errors; pause on hover and focus; a queue limit of three visible; status toasts carry icon and text, never colour alone (principle 7); messages are i18n keys or caller text, never built by the component.
- **Tooltip:** never the only carrier of information; opens on focus as well as hover; none on touch; Icon button (0.4-05) gets its tooltip from here only where its accessible name already says the same.
- **Segmented control** on UI SDK `SegmentedControl`: a single choice of two to five options, arrows follow reading direction, Home and End.
- **Command palette** on UI SDK `Command` inside our Dialog: Arabic search through a `normalise` prop passed to UI SDK's `filter` so Phase A can pass the name normaliser (ADR-0034); this slice ships a simple default (case, diacritics, tatweel, alef forms). Match highlighting uses UI SDK's `<mark>`.
- **Motion:** durations from the motion tokens (120–240 ms); every animation off under `prefers-reduced-motion`; no blur or large shadow needed to read an overlay (low-end PCs). Tests wait for running animations before axe (`expectAxeClean`, fixed in 0.4-05).
- Follows the `/ui-component` skill; the 0.4-04 fallback procedure applies where a part fails in RTL.

## Differences from the sheet and the plan (explained, not fixed)
- The bottom drawer is at most 5/6 of the screen (83 %), the palette sits 1/6 from the top (17 %): the nearest fractions on the token scale; OD-63 said 85 % and 15 %.
- The command palette runs on UI SDK's Dialog parts, not our Dialog: ours has a title row and close button the sheet's palette does not have; the dialog's name is a visually hidden title.
- The accordion's count badge sits outside the header button, over its end, so the button's visible text is its name (WCAG 2.5.3); it is read as the header's description.
- Toasts: when a fourth comes, UI SDK takes the oldest out of sight to wait, not the fourth (backlog: an error toast can step out of sight).
- Tooltip padding 12 × 4 px and the segmented items 8 px radius: token steps for the sheet's 10 × 6 px and 10 px.
- Focus rings of the segmented control are drawn inward (the track scrolls on a narrow screen).
