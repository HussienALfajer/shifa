## Goal
A dentist enters a full six-site perio exam by keyboard or on-screen keypad, an orthopedic surgeon selects sites with an explicit side and draws pain on the skeleton, and the owner holds everything needed to run the five sessions: the fixed build, the printed perio sheet, the moderator script and a checked way to serve the build to the tablet with the network off.

## Choices made by this plan
- **Perio path (one fixed path, spec 5):** 28 teeth, third molars not charted: upper buccal 17→27 (three sites per tooth in reading order), upper palatal 27→17, lower lingual 37→47, lower buccal 47→37. The session asks each dentist whether this is the path they expect (a rating question).
- **Entry:** one digit advances; `1` followed by a digit within 600 ms enters 10–19 (keyboard), and the keypad has a "10+" key; margins are entered in a second pass with a sign key; bleeding is a tap or the space bar on the current site. Backspace and tapping a cell correct a value without breaking the path.
- **Skeleton art:** public-domain Wikimedia anterior and posterior skeleton SVG if one passes a licence check recorded in `SOURCE.md` (file, author, licence, URL, retrieval date, edits); otherwise self-drawn. Hand, foot and spine panels are self-drawn schematics. The vendored file is marked `linguist-generated`; hit regions are hand-written and keyed by the site ids of `@shifa-spike/s8-rules`.
- **Side chips:** behaviour as in the direction picked in 0.3-S8a; in both, the selection is pending (dashed, not saved, "انتهيت" disabled) until a chip is chosen, midline sites offer only "خط المنتصف", and the anterior/posterior captions name the patient's right and left.
- **Pain marks:** SVG pointer strokes; point = tap, radiating = drag; six symptom types by colour and pattern (never colour alone); intensity 0–10 picked per mark; marks are kept per view and shown when switching views.
- **Serving to the tablet:** `pnpm --filter @shifa-spike/s8-web serve:lan` (`vite preview --host`) prints the address; the laptop and tablet share a network with no internet. Which network works on the owner's machines (a router without uplink, or a phone hotspot with mobile data off) is found in the dry run and written into the moderator script.
- **Moderator script is Arabic for speaking, English for instructions:** the sentences read to the doctor are in Arabic; it states that no real patient's findings may be entered, that consent is verbal and that only the participant code is recorded.

## Plan

## Tests written first
- `e2e/tests/perio.spec.ts` (5, 8): the correct path of D5 (168 depths from the sheet, margins and bleeding for one quadrant) scores success by keyboard; 3 wrong cells pass, 4 fail; a two-digit depth, a negative margin, a correction after auto-advance and a missing tooth in the path behave as specified; CAL cells equal PD + GM; cells at 4 and above are highlighted.
- `e2e/tests/skeleton.spec.ts` (3, 6, 8): the left knee's hit region is on the viewer's right in the anterior view and on the viewer's left in the posterior view; O1–O3 correct paths score success; right knee for O1, index finger or DIP for O2, L5–S1 for O3 score fail and raise the wrong-side or wrong-level count; a selection without a chip cannot be finished; a spine level offers no right or left; changing the side after selection.
- `e2e/tests/pain.spec.ts` (6, 8): O4 correct path scores success; right leg, anterior view, "sharp" instead of "burning" and intensity 5 score fail; a radiating mark across regions; marks survive a view switch.
- `e2e/tests/tablet.spec.ts` (7, extended): target sizes in perio and skeleton; D6 (D2 and one sextant of D5 by keypad) and O5 (O1 and O4) finished with touch events only.
- `e2e/tests/offline.spec.ts` (2, extended): all eleven tasks with the network blocked, no request outside the origin, storage empty after export.
- `e2e/tests/sheet.spec.ts`: the printed sheet's values equal the expected state of D5.
