# 0.3-S3 Arabic output spike: PDF, thermal raster, name search

Status: Done (merge pending; CI dispatch after merge) · Tier: T1 (output and search code on synthetic data; no tenancy, auth or money logic, no real-schema migration; the throwaway search table has RLS in its own schema). The new manual workflow and the derived PDF-tools image also get a `security-reviewer` pass. · Branch: `chore/0.3-s3-arabic-output-spike`
Spec: [0.3-S3 Arabic output](../specs/spikes/0.3-s3-arabic-output.md) criteria 1–12 · Requirements: PLT-38, BIL-30, SCH-28, SCH-30, CLN-22, PAT-14, PLT-01, PLT-50; "Arabic-normalised search" in [Release 1 scope](../product/scope-release-1.md) (no requirement ID yet) · Decisions: ADR-0021, OD-20 (open: both digit styles), OD-39, OD-40

One slice for the whole spike (owner, 2026-11-16), about 4,900 hand-written lines: over the ~4,000-line budget of [ADR-0032](../adr/0032-slice-size-budget-4000-lines.md) by the owner's choice. It is built in ten checkpoints (A–J); each ends green and committed, so a session can stop at any checkpoint and the next one resumes from "Stopped at". Checkpoints A–F (output) and G–I (search) do not depend on each other; J (report and ADR) needs both.

## Goal
The owner sees, for all four document types and both digit styles, Gotenberg PDFs and thermal images whose Arabic is shaped, in logical order and at the right size, proven by text extraction, embedded-font checks, page-size checks, committed goldens and a browser-print parity test. One Arabic name normaliser, in TypeScript and Dart and held equal by a shared vector file, finds realistic spelling variants of synthetic patients in PostgreSQL 18 inside `withTenant()`. The spike report answers every question of the spec, and ADR-0034 records the PDF, font, thermal and normaliser decisions.

## Layout
- New throwaway package `spikes/s3-arabic-output/output/` (`@shifa-spike/s3-output`), linted and typechecked by `verify` through the existing `spikes/*/*` workspace glob; its suites are `test:spike` (OD-31), run by the new manual workflow, not by `verify`.
- Kept for Phase A: `output/goldens/` (PDF page PNGs and 1-bit thermal PNGs), `vectors/name-search-vectors.json` and the template CSS conventions recorded in the report.
- Fonts: the four candidates (Noto Naskh Arabic, Amiri, Vazirmatn, Cairo) from their `@fontsource/*` npm packages (OFL; lockfile-pinned, 24-hour release age), uploaded with the HTML as multipart files and referenced by `@font-face` relative URLs. No derived Gotenberg image, no web fonts, no CDN.
- New throwaway package `spikes/s3-arabic-output/search/` (`@shifa-spike/s3-search`): TypeScript normaliser, PostgreSQL tests and bench; `test:spike` only (OD-31).
- New standalone Dart package `spikes/s3-arabic-output/normaliser_dart/` (outside the pub workspace, own lockfile, like `flutter_probe`), run through `node scripts/dart.mjs dart test`.
- Spike tables live in their own schema `s3` (`search/sql/schema.sql`, applied as owner), never in `packages/db/migrations`; each table has `tenant_id`, ENABLE + FORCE RLS and policies on `current_tenant_id()`, reached only through `withTenant()` as `shifa_app` (as in 0.3-S1). The `search` job joins the `s3-arabic-output` workflow from checkpoint F.

## Plan

### A. Gotenberg harness and the no-network proof (criterion 1)
1. `src/gotenberg.ts`: `GOTENBERG_IMAGE` = latest stable `gotenberg/gotenberg:8.x` at least 24 hours old, `name:version@sha256:<digest>`; Testcontainers start with `--chromium-allow-list=^file:///tmp/.*` (and the matching deny list), `--api-timeout`, log level `info`; `renderPdf(html, assets, options)` posts multipart to `/forms/chromium/convert/html` (paper size and margins from options, `preferCssPageSize=true`, `printBackground=true`); `screenshot(html, assets, widthPx)` posts to `/forms/chromium/screenshot/html` (PNG, `optimizeForSpeed=false`). HTML is always uploaded; the client never sends a URL.
2. Logs carry document type, byte size and timings only (no HTML, names or amounts).
3. Canary: a tiny HTTP container on the same Testcontainers network counts requests.

### B. Templates and fixtures (criterion 2)
1. `src/templates/`: one shared stylesheet (`dir="rtl"`, `lang="ar"`, `@page` per size, `unicode-bidi: isolate` / `<bdi>` for Latin drug names, doses and phone numbers, `font-variant-numeric: tabular-nums`) and four typed template functions returning escaped HTML:
   - prescription A5 (CLN-22): patient, doctor, Latin drug name + dose ("Amoxicillin 500 mg") inside Arabic instruction lines, a very long drug name that wraps;
   - receipt 80 mm and 58 mm (BIL-30): lines, tender per currency, change, rounding, balance, rate footer; amounts from fixtures only, formatted, no money logic; a long receipt that runs past one "page" with no cut;
   - report A4 (PLT-38): table over at least two pages, repeating `thead`, page numbers `صفحة X من Y` via Gotenberg header/footer templates (and the CSS counter in browser printing);
   - queue ticket 58/80 mm (SCH-28, SCH-30): number, practitioner, time, QR (`qrcode` package → inline SVG; payload is a synthetic ticket URL string, never fetched).
2. `src/digits.ts`: `formatNumber(n, style: 'latn' | 'arab')` via `Intl.NumberFormat` (`ar-SY-u-nu-…`); every template takes the style (OD-20 stays open).
3. `src/fixtures.ts`: deterministic fixtures from `@shifa/testing` (`createRandom`, Arabic person names, `Money`/`CURRENCIES`, clinic names) with a fixed seed; nothing hand-typed resembling a real person.

### C. PDF checks (criteria 2–3)
1. `docker/pdf-tools.Dockerfile`: `debian:trixie-slim@sha256:<digest>` + `poppler-utils` (version recorded in the report); built by Testcontainers `GenericContainer.fromDockerfile`. `src/pdf-tools.ts` runs `pdftotext -enc UTF-8` (logical order), `pdffonts`, `pdfinfo` (page size in pt) and `pdftoppm -r 150 -png` on an uploaded file.
2. Assertions per document × digit style: expected Arabic strings present in logical order (no isolated presentation forms U+FE70–FEFF, no reversed words); Latin drug names, doses, phone numbers and amounts intact; every font in `pdffonts` is embedded (`emb yes`) and one of the uploaded families (no fallback; the shared CSS sets no generic fallback that could hide tofu); page size equals the `@page` size within 1 mm; report has ≥ 2 pages and the header text on each.

### D. Goldens and browser-print parity (criteria 4–5)
1. `src/golden.ts`: rasterised pages vs `goldens/pdf/<doc>-<digits>-p<n>.png` with `pixelmatch` (threshold 0.1) and at most 0.5 % differing pixels; on failure the diff PNG goes to `.verify/s3/diff/`. `pnpm --filter @shifa-spike/s3-output goldens:update` writes candidates to `.verify/s3/candidates/` only; copying into `goldens/` is a manual step after the owner's eye check (recorded under Evidence).
2. Font comparison sheet: prescription A5 and receipt 58 mm in each of the four fonts → `.verify/s3/fonts/` for the owner's choice; goldens and the remaining checks use the chosen font only.
3. `test/parity.test.ts`: the same HTML (same fonts as local files) printed by Playwright Chromium `page.pdf({ preferCSSPageSize: true })` → same page count, page size within 1 mm and the same `pdftotext` output as Gotenberg (whitespace-normalised). Differences (e.g. page-number footer) are listed in the report, not hidden.

### E. Thermal raster and ESC/POS (criterion 6)
1. `src/thermal.ts`: Gotenberg screenshot of the receipt and ticket at exactly 576 px (80 mm) and 384 px (58 mm) wide; luminance → 1-bit by threshold and by Floyd–Steinberg (both kept; the report picks one); `encodeRaster(bits) → Uint8Array` as ESC/POS `GS v 0` (mode 0, `xL xH yL yH`, MSB-first rows), split into bands of ≤ 255 rows with no cut command between them; `decodeRaster(bytes)` in the test helpers parses the stream back.
2. Goldens `goldens/thermal/<doc>-<width>-<dither>.png` (1-bit), exact match after decode, ≤ 0.2 % differing pixels against the golden; owner eye check for 58 mm legibility at the chosen font size (the sheet renders 58 mm at two sizes).

### F. Measurement, workflow, docs (criterion 11 PDF half)
1. `scripts/bench-render.ts` (`bench:render`): warm-up, then N renders per document type, sequential and 5 concurrent; p50/p95 per type; peak container memory from the Docker stats stream; writes `.verify/s3/render-bench.json` (versions, CPU, RAM; no content). Report only, no threshold.
2. `.github/workflows/s3-arabic-output.yml`: `workflow_dispatch` only, `permissions: {}`, actions pinned by SHA like `s1-offline.yml`; job `output` installs Playwright Chromium, runs `test:spike` and `bench:render`, uploads `.verify/s3/` (diffs, candidates, bench JSON) as an artifact.
3. Docs: "As built" and Evidence in this file (incl. the owner's eye check and font choice); numbers feed the report in checkpoint J.

### G. Normaliser in TypeScript and the shared vectors (criteria 7–8)
1. `search/src/normalise.ts`: `normaliseName(input: string): string`, pure, in the spec's order: NFC → remove tashkeel (U+064B–065F, U+0670, Quranic marks U+06D6–06ED) and tatweel (U+0640) → fold أ إ آ ٱ → ا, ؤ → و, ئ → ي → word-final ة → ه and ى → ي → Arabic-Indic (U+0660–0669) and Persian (U+06F0–06F9) digits → Western → Latin lower-cased → whitespace (incl. NBSP, ZWNJ/ZWJ and other Unicode spaces) collapsed and trimmed → particles عبد، أبو، أبي، أم، ابن، بن، بنت (matched after folding, so ابو/أبو alike) joined with the next word; a particle at the end is left alone. `ال` is never stripped (OD-40).
2. `vectors/name-search-vectors.json`: `{ version, rules[], cases: [{ id, rule, input, key, note? }] }`, ≥ 200 cases: every rule alone, rule interactions (diacritic on a final ة, particle after tatweel, hamza on a particle), mid-word ة/ى untouched, Latin and mixed input, digits in names, empty, whitespace-only, diacritics-only and tatweel-only input → `""`. Inputs are synthetic name parts from `@shifa/testing` lists plus hand-made fragments; no real person.
3. `search/test/vectors.test.ts`: every case passes; idempotence over every vector key and over 5,000 seeded random strings drawn from an Arabic + Latin + marks + spaces alphabet (`createRandom`, fixed seed, no new dependency): `n(n(x)) === n(x)`.

### H. Dart port (criteria 7–8)
1. `normaliser_dart/lib/normalise.dart`: the same function, same order, no package dependency beyond the SDK.
2. `normaliser_dart/test/vectors_test.dart` reads the shared JSON by relative path; the same idempotence check with a fixed-seed `Random`.
3. Parity proof: `search/test/parity-vectors.test.ts` asserts the JSON's case count and rule coverage (each rule id has ≥ 5 cases), so a port cannot pass on a trimmed file. Negative evidence: change one Dart rule (e.g. drop ى folding) → the Dart test fails on the named cases; reverted.

### I. PostgreSQL search (criteria 9–10, search half of 11)
1. `search/sql/schema.sql`: `create extension if not exists pg_trgm`; `s3.patient_a` (stored key column `name_key text not null`, written by the application through `normaliseName`) and `s3.patient_b` (`name_key text generated always as (s3.normalise_name(display_name)) stored` from an `IMMUTABLE`, `PARALLEL SAFE` SQL function using `normalize(…, NFC)`, `translate` and `regexp_replace`); both with `display_name` untouched, GIN index `(tenant_id, name_key gin_trgm_ops)` via `btree_gin`, RLS as above.
2. Seed: the `load` preset (`DEFAULT_LOAD_PARAMS`, 50 tenants × 1,000 patients, fixed seed) into both tables as owner, then `ANALYZE`.
3. Search query inside `withTenant()` as `shifa_app`: `where name_key % $key order by similarity(name_key, $key) desc, id limit 5` (threshold recorded; `word_similarity` compared in the report).
4. Variant generator (`search/src/variants.ts`): for a sample of seeded patients, one variant per rule (add tashkeel, swap alef forms, ة↔ه / ى↔ي at word end, split or join a particle, Arabic-Indic digits, extra spaces, tatweel).
5. `scripts/bench-search.ts` (`bench:search`): p50/p95 of the search query at the `load` volume for both tables; `EXPLAIN` shows the GIN index; writes `.verify/s3/search-bench.json` (versions, machine; no names or search terms).

### J. Workflow, spike report and ADR-0034 (criteria 11–12)
1. `.github/workflows/s3-arabic-output.yml`: job `search` next to `output` (pnpm `test:spike` for `@shifa-spike/s3-search`, Dart vectors through `scripts/dart.mjs` with the Dart/Flutter pins of `ci.yml`, `bench:search`, artifact upload).
2. `docs/spikes/s3-arabic-output.md`: answer per spec question and per criterion 1–12 with test names and run ids; Gotenberg, Chromium, poppler, PostgreSQL and font versions; the chosen font and 58 mm size; dither choice; render and search numbers (local and CI dispatch) with machine details; variants still missed and false matches added by the OD-40 rules; stored column vs generated column with the drift risk and a recommendation; risks left (real printer before the pilot, OD-39; OD-20 still open).
3. `docs/adr/0034-arabic-output-and-name-search.md` (Proposed; Accepted on owner approval): PDF engine settings, font, template conventions, thermal raster settings, normaliser rules and where the key is computed. ADR-0021: only its `Status:` line gains `· Amended by ADR-0034`. ADR index, roadmap (S3 result), `docs/README.md` map if needed.
4. Contracts, API, web, Flutter app, end-to-end: not applicable.

## Tests written first
Output (checkpoints A–E):
- `test/gotenberg.test.ts` (1): image constant matches `name:8.x.y@sha256:<64 hex>`; the running container reports that version; rendering every template leaves the canary at 0 requests; a probe HTML with `<img src="http://canary/…">` is blocked by the allow-list (canary still 0).
- `test/pdf-text.test.ts` (2, 3): for each of the 4 documents × 2 digit styles (receipt and ticket × 2 widths): expected strings, Latin runs, no presentation forms, all fonts embedded and from the uploaded set, page size ± 1 mm, report ≥ 2 pages with header and `صفحة` numbering.
- `test/golden.test.ts` (4): every page matches its golden within the threshold; a deliberately shifted template fails with a diff file (negative evidence, then reverted).
- `test/parity.test.ts` (5): Playwright vs Gotenberg page count, size and text.
- `test/thermal.test.ts` (6): image widths 576/384; encode → decode round-trip equals the 1-bit image; header bytes `1D 76 30 00`; bands ≤ 255 rows; no `GS V` cut inside a long receipt; decoded image vs golden.
- `test/digits.test.ts`: `latn` and `arab` outputs for integers, decimals and grouping.

Search (checkpoints G–I):
- `search/test/vectors.test.ts` (7–8): every vector case; idempotence (vectors + 5,000 seeded strings); empty, whitespace-only, diacritics-only → `""`; Latin passes through lower-cased; trailing particle untouched; display name unchanged after keying.
- `normaliser_dart/test/vectors_test.dart` (7–8): the same vectors and idempotence in Dart.
- `search/test/search.test.ts` (9, PostgreSQL 18 Testcontainers via `@shifa/db/testing`): per rule, the variant finds the intended patient in the top 5 inside `withTenant()` on both tables; a tenant never sees another tenant's patient for the same key; the per-rule hit rate and the false matches (other patients ranked above the intended one) are written to `.verify/s3/search-quality.json` for the report, with no names in it.
- `search/test/key-drift.test.ts` (10): for every vector input, `s3.normalise_name()` in SQL equals `normaliseName()` in TypeScript; the cases where they differ (if any) are listed and fail the test until the report explains them.
- `search/test/schema.test.ts`: every `s3` table has FORCE RLS and policies; the GIN index exists and leads with `tenant_id`.

## As built
Deviations from the plan, each recorded in the [result](../spikes/s3-arabic-output.md) and [ADR-0034](../adr/0034-arabic-output-and-name-search.md):
- Gotenberg 9.x exists; the owner kept 8.40.0 (OD-41). Canary: `busybox:1.37.0` httpd, pinned by digest.
- Text extraction uses PDFium (`pypdfium2` 5.0.0, PDFium 143, pinned by hash, in the same pdf-tools image) instead of `pdftotext`: poppler splits Arabic words and adds bidi controls; PDFium 159 (`pypdfium2` 5.15.2) reverses some words. Poppler still does fonts, page sizes and rasters.
- The text comparison (`test/stack.ts` `squash`, both sides) drops tashkeel, bidi marks and bracket direction; dates are checked as day, month and year (RLM marks are not in the text layer). Lam-alef reversal in every reader is a recorded limitation.
- Templates: roll documents end with a 10 mm tear-off block (Gotenberg `singlePage` dropped the long receipt's last line); dates via `Intl.DateTimeFormat`; conversions wait for `document.fonts`.
- Dart has no NFC: `normaliser_dart` depends on `unorm_dart` 0.3.3 (pure Dart, no dependencies). The normaliser also removes bidi controls, lower-cases ASCII only, runs particle joining twice and NFC again at the end (all in the vectors).
- `bench:search` is a Vitest run (`vitest.bench.config.ts`) to get the @shifa/db harness; it measures the `load` volume and one 50,000-patient tenant and records the plan instead of asserting GIN (OD-42).
- Locked-test edits, plumbing only (owner approved, 2026-11-16): Dart string spread → `_splitChars`; Drizzle array parameter → `sql.param()`; string spreads → `Array.from` and a template literal (lint); `printer?.close()` → `printer.close()`; a void arrow body in braces; the presentation-forms regex written with `\u{…}` escapes. No assertion changed.
