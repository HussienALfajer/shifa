# 0.3-S2b Leak tests behind PgBouncer

Status: Planned · Tier: T0 (tenant context, RLS, patient-data isolation) · Branch: `chore/0.3-s2b-pooling-leak-tests`
Spec: [0.3-S2 tenant isolation](../specs/spikes/0.3-s2-tenant-isolation.md) criteria 4–9 · Requirements: PLT-01, PLT-50 · After 0.3-S2a

## Goal
Attack ADR-0004's claim through the real PgBouncer from 0.3-S2a: context left on a reused server connection, session-level settings, killed clients, named prepared statements, heavy concurrency, and session-only features. The tests stay in CI on every PR. A leak found here is fixed in this slice (code or PgBouncer setting) with the test that proves it; if no fix is possible, record it for the S2c report as "not safe".

## Plan
1. **Contracts:** none.
2. **Database tests** (`packages/db/test/pooling/`, all against PostgreSQL + PgBouncer):
   - `probe.ts`: a test-only `pool_probe` table (`tenant_id uuid`, `label`, FORCE RLS, policy on `current_tenant_id()`, index led by `tenant_id`), created by the owner with `create table if not exists`; seed helpers through `withTenant()`; a `serverPid(tx)` helper (`pg_backend_pid()`) so every reuse test first asserts it really got the same server connection (a test that never reused a connection proves nothing). Failure messages name tenant ids and row counts only.
   - `context-reuse.test.ts` (criterion 4): on `shifa_test_9994` (`POOLING_DATABASE`; 9996 belongs to the backup drill) (pool size 1), after a committed, a rolled-back and a failed-statement `withTenant()`, the next transaction on the same server pid sees empty `app.tenant_id`, `app.branch_id`, `app.user_id` and zero probe rows.
   - `session-leftovers.test.ts` (criterion 5): a raw `shifa_app` client through PgBouncer runs `SET app.tenant_id` and `set_config(..., false)` for tenant A, disconnects; on the same server pid `withTenant(B)` sees only B, `withPlatformAdmin` sees no tenant rows. A second variant runs with `server_reset_query_always = 1` (separate PgBouncer config or admin `SET` on a dedicated instance) and records the p50 overhead per transaction for the report. Write down which is enough and why (the wrapper overrides all three settings locally in every transaction; a raw session `SET` only survives where no wrapper runs).
   - `broken-clients.test.ts` (criterion 6): a client whose socket is destroyed after `set_config` and before COMMIT; the next client on that pool sees no context and `pg_stat_activity` shows no `idle in transaction` backend for `shifa_app`. Repeat with `idle_in_transaction_session_timeout` (set on the pooling database by the owner) firing.
   - `prepared-statements.test.ts` (criterion 7): a Drizzle `.prepare(name)` query on the probe, executed alternately for tenants A and B on the 2-connection pool, more than 5 executions per server connection (PostgreSQL's generic-plan switch; also with `plan_cache_mode = force_generic_plan` in a variant), returns only the current tenant's rows every time. This exercises PgBouncer's `max_prepared_statements` tracking.
   - `concurrency.test.ts` (criterion 8): 3+ synthetic tenants from `@shifa/testing` (`generateDataset` with the `load` preset, small params), 20 rounds of 50 concurrent `withTenant()` calls on the default 2-connection pool; each call checks `current_setting('app.tenant_id')` and every row's `tenant_id`; zero mismatches, mismatch count reported.
   - `session-features.test.ts` (criterion 9): `pg_advisory_xact_lock` blocks a second transaction and is released at COMMIT; `create temp table ... on commit drop` works inside `withTenant()`.
3. **Fixes (only if a test is red):** in `src/tenant.ts`, `src/admin.ts`, `src/transaction.ts` or the PgBouncer config from S2a; each with the red test kept.
4. **Rules:** `.claude/rules/db.md` and `packages/db/CLAUDE.md` forbid session advisory locks, `LISTEN`/`NOTIFY` listeners on the app pool, `SET` outside a transaction, session temp tables and `WITH HOLD` cursors; name the transaction-scoped forms. Stay inside the byte budgets.
5. **Findings for the report:** every criterion's result, server pids observed, the `server_reset_query_always` cost and the session-feature list go into this file's "As built" for S2c to compile.
6. **API / Web / Flutter / end-to-end:** not applicable.

## Tests written first
All files above, red first: they fail on the missing probe module, then each must be shown to catch a leak with a deliberate fault (negative evidence for the PR): `withTenant()` patched to `set_config(..., false)` fails `context-reuse`; dropping the wrapper's `app.branch_id` reset fails `session-leftovers`; a `pg_advisory_lock` (session form) is shown to survive the transaction (documents why it is forbidden).

Estimated hand-written lines: ~650 (probe + helpers ~100, six test files ~470, rules/docs ~40, fixes budget ~40).
