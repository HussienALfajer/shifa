# 0.4-01 Tokens pipeline, generated themes and contrast test

Status: In review · Tier: T1 (drift generator and `verify`; no patient data, no schema) · Branch: `feat/0.4-01-tokens-pipeline`
Spec: [0.4 Design system foundations](../specs/design-system/0.4-design-system-foundations.md) criteria 1–3 · Requirements: PLT-41 (brand slots only) · Decisions: ADR-0011, ADR-0039, OD-56

First of eight slices. Closes the "design tokens" drift item of the Phase 0.2 checklist.

## Goal
`packages/tokens` is the one source of design values. A token change regenerates the web theme (CSS, Tailwind v4) and the Dart theme file, `verify` fails when the outputs are stale, and a contrast test fails the build when a declared pair is below WCAG 2.2.

## Choices made by this plan
- **Source layout:** `packages/tokens/src/{primitive,semantic,brand,component}/*.tokens.json` (DTCG 2025.10). Semantic colours carry light and dark through `$extensions.shifa.modes`; locked tokens carry `$extensions.shifa.locked: true`.
- **Colour:** light values from the Damascene Jasmine tables in the design doc; dark derived from the same primitives (new dark steps added as primitives). The owner sees dark on real screens in 0.4-02 and may adjust it there.
- **Locked set built now:** status (success, warning, danger, info, neutral), saved/offline/syncing, alert severities, queue statuses. Odontogram, perio, laterality and pain colours arrive with their modules (Phases B–C, spike S8) under the same lock mechanism.
- **Design-language values are provisional:** type scale, radius, elevation, motion and density ship with neutral defaults; 0.4-02 replaces them with the owner's choice.
- **Contrast pairs are declared, not guessed:** `src/contrast-pairs.json` lists each text/surface and icon/surface pair with its class (`body` 4.5, `large` or `ui` 3.0). A semantic text or icon colour that appears in no pair fails the schema test.
- **Outputs (committed, `linguist-generated`):** `packages/tokens/generated/css/{tokens.css,tailwind-theme.css}` (light, `[data-theme=dark]`, `[data-density=compact]`) and `packages/shifa_ui/lib/src/generated/tokens.g.dart`. This slice creates `packages/shifa_ui` as a skeleton (pubspec in the pub workspace, the generated file, one analyse-and-load test) so the Dart output compiles from day one; widgets come in 0.4-08.

## Plan
1. Contracts, database, API: none.
2. **Tokens package:** `@shifa/tokens` with the four layers; `src/schema.ts` (layer rules, references resolve, both modes present, locked flags); `CLAUDE.md` (where a value goes, never edit `generated/`).
3. **Build:** `scripts/build.ts` on Style Dictionary v5 (exact pin): CSS custom properties, a Tailwind v4 `@theme` file, and a Dart format (`Color`, `double`, `Duration` constants grouped by light and dark). Pure `build(sources) → files` plus a thin CLI taking an output directory.
4. **Drift:** `scripts/lib/drift-tokens.mjs` exports `tokensCheck()`, registered in `scripts/drift.config.mjs`; hint names `check-drift --fix`.
5. **Contrast:** `src/contrast.ts` (WCAG 2.2 relative luminance and ratio) and the test over every declared pair in both themes.
6. **Docs:** design doc (dark table, locked list, pairs rule), roadmap, Phase 0.2 checklist item ticked.

## Deviations from the plan
- `packages/shifa_ui` tests use `package:test` under `flutter test`, not `flutter_test`: its pinned `test_api` cannot resolve in the workspace next to the Dart client's `build_runner` (backlog; must be solved before 0.4-08).
- Two locked tests were changed after the red phase without touching an assertion: `schema.test.ts` (typed access helper instead of non-null assertions, for typecheck and lint) and `tokens_test.dart` (the import above).
- `biome.json`: line width 160 for `packages/tokens/src/**/*.tokens.json`, so a token stays on one line.
- Provisional choices for the owner to confirm in 0.4-02: `danger` is brick (crimson only for `color.alert.critical`), alert severities `info`/`warning`/`critical`, the hue of each queue status, the dark palette.
- Review fixes added three schema rules beyond the plan: opaque colours in pairs, no token inside a token, crimson only for critical alerts.
