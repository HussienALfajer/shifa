## As built
- **Plan probe** (`scripts/plan-probe.ts`, shared by the test and the bench): `plan_probe (tenant_id, created_at, label)`, index `plan_probe_tenant_created (tenant_id, created_at desc)`, policy on `current_tenant_id()`; 50 tenant ids from `@shifa/testing` (`createRandom` + `IdRegistry`, fixed seed) × 1,000 generated rows (`DEFAULT_LOAD_PARAMS`), then `ANALYZE`. **Deviation:** RLS is ENABLEd, not FORCEd, so the owner can fill and count it; FORCE only affects the owner, and `shifa_app` is planned and filtered the same. The query filters `tenant_id = $1` explicitly (so the bench's BYPASSRLS run reads the same rows); under RLS the policy adds `tenant_id = current_tenant_id()`. `planScans()` walks `EXPLAIN (FORMAT JSON)` and describes each scan of the table (`Seq Scan on plan_probe`, `Index Scan using … on plan_probe`).
- **Plan check** (`test/pooling/plan-check.test.ts`, criterion 10): volume asserted (50,000 rows, 50 tenants); the plan as `shifa_app` in `withTenant()` through PgBouncer uses `plan_probe_tenant_created` with no sequential scan; the query returns 20 rows of the current tenant only; after `drop index` the walker reports `Seq Scan on plan_probe` (the negative evidence stays as a permanent test).
- **Harness:** `startHarnessContainer({ poolerUsers })` adds userlist entries to the shared PgBouncer only (harness role names refused); `HarnessContainer.loginUrl()` (guarded, via `urlForLogin()`, refuses harness roles) and `poolerConsoleUrl()`. Unit test in `guard-pooler.test.ts`.
- **Bench** (`scripts/bench-rls.ts`, `bench:rls`, criterion 11): under the DB test lock, its own harness; clones the template into `shifa_test_9990`; creates `shifa_bench_bypass` (LOGIN BYPASSRLS, per-run hex password, only in that container) and grants it SELECT on the probe; both roles run the same transaction (BEGIN, `set_config('app.tenant_id', $1, true)`, query, COMMIT) through the shared PgBouncer, interleaved with alternating order, one client each; 200 warm-up + 2,000 iterations (`BENCH_RLS_WARMUP`, `BENCH_RLS_ITERATIONS`); each transaction checks it got 20 rows of its tenant; the plan index of both roles is recorded. **Deviation:** the RLS side uses the raw transaction shape rather than `withTenant()`, so RLS is the only difference between (a) and (b). Report schema (`scripts/bench-report.ts`): strict; every string is refused when it looks like a URL, `host:port`, password or secret.
- **CI:** `.github/workflows/rls-bench.yml`, `workflow_dispatch` only, actions pinned like `backup-drill.yml`, uploads `report.json` (90 days). Dispatch needs the workflow on `main`, so the CI run happens after merge.
