## Goal
A screen can be built from a complete, accessible form: every field type the Phase A screens need, with labels, hints, errors and validation from shared Zod schemas.

## Components (11)
Icon button, input, textarea, password input, OTP input, checkbox, radio, switch, time input, field and form (the plan's "10" counted field and form as one).

## Choices made by this plan
- **Field** owns label, hint, error, required mark and the `aria-describedby` wiring; every input above works inside and outside it.
- **Form** is a thin layer over React Hook Form with a Zod resolver: `useShifaForm(schema)`, `<Form>`, `<FormField name>`; errors are i18n keys, never literal text; focus moves to the first invalid field on submit. `react-hook-form` and its resolver are pinned exactly.
- **Digits:** OTP and time input accept both digit styles and normalise to Western digits in the value (as Number Input does in 0.4-04).
- **Password input:** show/hide toggle with an accessible name; never logged or stored by the component.
- **Latin inside Arabic:** input and textarea take `dir="auto"` per field where the content may be Latin (phone, email, drug name), with the isolation rule from the design doc.
- Follows the `/ui-component` skill; where a UI SDK part fails in RTL, the 0.4-04 fallback procedure applies.

## Differences from the sheet (explained, not fixed)
- The password toggle keeps one name («إظهار كلمة المرور») and reports its state with `aria-pressed`; the sheet changed the name with the state. UI SDK's pattern, and the one screen readers expect (a name that changes and a pressed state would say it twice).
- A disabled Time Input's label is muted, not disabled-grey: axe exempts the label of a disabled native input but not of a group (backlog: the same inside an outer Field).
- Read-only fields keep the normal border colour and only take the raised background; a border colour there outranked the error and focus borders (review N7).
- Time Input in English uses `en-US` so the period reads "PM" as drawn (en-GB writes "pm").
- Spacing on the token scale: the sheet's 10 px gaps are 8, the Textarea starts at 88 px, not 104.
