# 0.2-09b1 API telemetry: traces, metrics, correlated logs, layer-one scrubbing

Status: Planned · Tier: T0 · Branch: `feat/0.2-09b1-api-telemetry`
Spec: [0.2-09b](../specs/foundation/0.2-09b-observability-skeleton.md) (criteria 1 OTel part, 2, 3, 4, 6 for spans/metrics/logs; edge cases) · Requirements: PLT-52, PLT-50
Depends on: 0.2-09a merged. Blocks: 0.2-09b2 (same bootstrap and `env.ts`, serialised), 0.2-09b3 (smoke check).

## Goal
`apps/api` emits OpenTelemetry traces, metrics and logs over OTLP when `OTEL_EXPORTER_OTLP_ENDPOINT` is set, and nothing at all when it is unset; every exported attribute passes an allowlist, and a leak test proves synthetic patient data never leaves in a span, metric or log line.

## Plan
1. **Contracts / database / web / Flutter.** None. No schema, no endpoint.
2. **Config** (`config/env.ts`): `OTEL_EXPORTER_OTLP_ENDPOINT` (http(s) URL, optional), `OTEL_TRACES_SAMPLER_ARG` (0–1, default 1), `DEPLOYMENT_ENVIRONMENT` (default `development`); added to `KNOWN_KEYS` so near-miss detection covers them. Create `apps/api/.env.example` (local placeholders only, no password literal the secret scan would flag).
3. **Bootstrap** `src/telemetry/instrument.ts`: second tsdown entry, loaded with `node --import ./dist/instrument.js dist/main.js` (ESM: instrumentation must patch `pg`, `fastify`, `http` before `main.ts` imports them; registers the `import-in-the-middle` hook). Reads config through `loadConfig`; when the endpoint is unset it returns before creating any SDK object. `package.json` `start` and `scripts/boot-check.ts` use the `--import` form.
   - SDK: `@opentelemetry/sdk-node` with explicit instrumentations only (no auto-instrumentations bundle): http, `@fastify/otel` (or the maintained Fastify instrumentation at build time), pg (`enhancedDatabaseReporting: false`), runtime-node (event-loop lag, memory). Resource `service.name=shifa-api`, `service.version` from `package.json`, `deployment.environment`. W3C trace-context propagator (incoming `traceparent` honoured). Sampler `ParentBased(TraceIdRatio(arg))`.
   - Bounded export: `BatchSpanProcessor` / log processor with fixed `maxQueueSize`; an OTel `diag` logger that reports export failures at most once per minute through pino.
4. **Route naming** (`src/telemetry/http.ts`): a Fastify `onRequest` hook sets the active server span's name to `METHOD routeTemplate` and `http.route` from `routeOptions.url` (`[unmatched]` otherwise); `onResponse` records `http.server.request.duration` (histogram) and a request counter with `http.request.method`, `http.route`, `http.response.status_class` only. Built-in HTTP metrics disabled or reduced by a View.
5. **Scrubbing layer one** (`src/telemetry/scrub.ts`, the PLT-52 core): `ALLOWED_SPAN_ATTRIBUTES`, `ALLOWED_METRIC_LABELS`, `ALLOWED_RESOURCE_ATTRIBUTES` constants; a wrapping `SpanExporter` that copies each span with only allowed attributes, drops span events except `exception` (keeping `exception.type` and stack frames, message replaced by `describeError` type/code), drops status messages and links' attributes. PostgreSQL spans keep `db.system`, `db.operation.name`, `db.collection.name`; the query text is dropped entirely (literals in raw SQL could hold values). Metric Views use `attributesProcessor` allowlists. `user-agent` and `content-type` are the only header attributes kept; `url.query`, `url.full`, `client.address`, `network.peer.*` are dropped.
6. **Logs** (`platform/logging.ts`): pino `mixin` adds `trace_id`, `span_id` from the active span (with or without the SDK: the API package is a no-op without a provider); `requestId` stays as today. When the endpoint is set, the pino instrumentation's log sending forwards the already-serialised lines (redaction and serializers unchanged) to the OTLP log exporter; stdout output stays.
7. **Docs.** PLT-52 already exists in `docs/domain/platform-and-configuration.md`; link the slice. `apps/api/CLAUDE.md` gets one line: new span/metric attributes go through `scrub.ts` allowlists.

## Risks
- ESM instrumentation with a bundled app: only npm dependencies are patched (they stay external in tsdown); workspace packages are bundled and are not instrumented, which is wanted.
- Fastify instrumentation package churn; pick the maintained one at build time and record it here.
- Package age rule (24 h) and exact pins: choose the newest OTel set that is older than 24 h and mutually compatible (`sdk-node`, `api`, instrumentations share one release train).
