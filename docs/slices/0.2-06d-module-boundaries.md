## Goal
Modules under `apps/api/src/modules/*` may import each other only through `index.ts`, and `src/platform/` and `src/access/` never import a module. A lint rule gives the fast feedback; an architecture test on the real source tree makes the rule impossible to silence.

## Plan
1. **Contracts / database / web / Flutter.** None.
2. **Lint rule** (`tooling/eslint-config/rules/module-boundaries.js`, plugin `shifa`, no new dependency, ~100 lines): for files in `<pkg>/src/modules/<a>/`, an import (static, `export … from`, dynamic `import()`) resolving into `src/modules/<b>/` with `b ≠ a` must target `src/modules/<b>/index.ts`; files in `src/platform/` or `src/access/` must not import from `src/modules/`. Resolves relative paths and the `@/` alias if the API tsconfig defines one (none today; handled so it cannot be added as a loophole). Enabled in `createConfig` for the API package via an option (`moduleBoundaries: { root: 'src' }`) so other packages are unaffected.
3. **Architecture test** (`apps/api/test/architecture/module-imports.test.ts`): walks `src/` with the TypeScript compiler API (`ts.preProcessFile` per file, no type check), applies the same rule (shared pure function exported from the rule file so both agree), and fails listing `file → import`. Also fails on any `eslint-disable` comment naming `shifa/module-boundaries` (the ban decided here: a grep in this test, since `@eslint-community/eslint-comments` would be a new dependency).
4. **Instructions.** `apps/api/CLAUDE.md` and `.claude/rules/api.md`: boundary rule (replace "enforced in 0.2-06c"). If `/add-endpoint` exists (0.2-06c), add one line; otherwise 0.2-06c adds it. `docs/backlog.md`: cross-module table access check once schema files exist per module. Roadmap: tick "Architecture tests" when 0.2-06b, 0.2-06c and this slice are all merged.

## As built
- Rule `tooling/eslint-config/rules/module-boundaries.js` (exported as `@shifa/eslint-config/rules/module-boundaries`, with a `.d.ts`): `boundaryViolation(srcRoot, file, specifier)` is the shared pure check. It resolves relative, absolute and `@/` specifiers and treats `\` as a separator. The lint rule covers `import`, `export … from`, `export * as`, `import()` (string or plain template literal), `import x = require()` and `typeof import()`.
- `createConfig({ moduleBoundaries: { root: 'src' } })` is used by `apps/api/eslint.config.js` only.
- The architecture test parses each file with `ts.createSourceFile`, not `ts.preProcessFile`, which misses `export * as ns from` and imports after a regex containing a backtick. It also refuses computed `import()`/`require()` in `modules/`, `platform/` and `access/`, any comment naming the rule, and blanket `eslint-disable` comments in `src/`. It runs in the `unit` project (no Docker).
- Locked tests were strengthened after review with the owner's approval (2026-11-08). Only cases were added: none was removed or weakened.
