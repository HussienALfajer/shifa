Status: Built · Tier: T0 · Branch: `feat/0.2-09b2-error-reporting`

Depends on: 0.2-09b1 merged (bootstrap, `env.ts`, leak test). Blocks: 0.2-09b3 (smoke check needs the failing route and events).

## Goal
Unhandled exceptions and 5xx responses reach GlitchTip through the Sentry SDK with route template, status, `requestId`, `trace_id` and release, and nothing else; 4xx are never sent; with `SENTRY_DSN` unset the SDK is not initialised.

## Plan
1. **Contracts / database / web / Flutter.** None. The error envelope is unchanged.
2. **Config** (`config/env.ts`): `SENTRY_DSN` (optional URL), `SENTRY_RELEASE` (optional, default `service.version`); `.env.example` gains a local `127.0.0.1` placeholder.
3. **SDK** (`src/telemetry/errors.ts`, initialised from `instrument.ts`): use the Sentry package that does not install its own OpenTelemetry setup (`@sentry/node-core`, or `@sentry/node` with `skipOpenTelemetrySetup: true`), so 0.2-09b1's tracer provider stays the only one; no tracing (`tracesSampleRate` unset), `sendDefaultPii: false`, default integrations off except the ones needed for stack frames and uncaught/unhandled capture; no request-data, local-variables, console or http breadcrumbs integrations.
   - `beforeSend` rebuilds the event from an allowlist: exception type, stack frames (`filename`, `function`, `lineno`, `colno`; no `vars`, no `context_line` source text), tags `route`, `status`, `request_id`, `trace_id`, `release`, `environment`. Exception `value` is replaced by `describeError` type and code (SQLSTATE for database errors). `beforeBreadcrumb` returns null. `request`, `user`, `extra`, `contexts` other than `trace` are dropped.
4. **API** (`platform/errors.ts`, `main.ts`): `GlobalExceptionFilter` captures when `status >= 500` with the route template and ids; HttpException 5xx with a cause captures the cause class; 4xx never. `crash()` in `main.ts` captures and `flush(2000)` before exit.
5. **Test-only failing route**: `GET /v1/_test/fail` in a `TestSupportModule` registered only when `NODE_ENV === 'test'`; throws an error whose message quotes a synthetic value. Excluded from the OpenAPI document (generator and drift run without it); the route matrix gets a `testOnly` marker and the expected matrix lists it; `/add-endpoint` steps followed.

## As built (deviations from the plan)
- **SDK package:** `@sentry/core` 11.11.0 alone (`ServerRuntimeClient` from `@sentry/core/server`, `integrations: []`, `traceLifecycle: 'static'`), not `@sentry/node-core`: node-core peers on `@opentelemetry/core` 1.x/2.x while the API runs 3.x, and core installs no OpenTelemetry, instrumentation or global handler at all. 11.12.0 was younger than pnpm's 24 h minimum.
- **No `sendDefaultPii` in v11:** `dataCollection` is set to collect nothing (user info, cookies, headers, bodies, query params); `maxBreadcrumbs: 0`, `beforeBreadcrumb` → null, `sendClientReports: false`.
- **Route path:** `GET /_test/fail`, not `/v1/_test/fail`: the API has no `/v1` prefix (routes are `/health/live`). Contract defined in `src/platform/test-support.ts` (never in `@shifa/contracts`); quoted synthetic marker `TEST_FAILURE_MARKER` for the 0.2-09b3 smoke check.
- **`NODE_ENV`** is read in `env.ts` outside the near-miss rule (hosts set `NODE_EXE`, `NODE_PATH`); `config.testRoutes` → `AppModule.register({ testRoutes })`, default off (OpenAPI generator, production).
- **Uncaught errors:** `crash()` in `main.ts` calls `reportError` and waits up to 2 s on `flushErrors` before exit (no Sentry global-handlers integration).
- **Trace id:** `reportError` copies the active OpenTelemetry span's ids into the Sentry scope's propagation context and the `trace_id` tag; `beforeSend` keeps `contexts.trace` (trace and span id, hex only).
- **Extra proof:** `boot-check` now runs the built bundle with `SENTRY_DSN` on a stub GlitchTip and `NODE_ENV=test`: `GET /_test/fail` → one event with route and status, without the marker.
- `openapi.test.ts` skips `TEST_ONLY_ROUTES` when matching the matrix to the document and asserts they are absent.
- The owner approved (2026-11-11) a lint-only fix to the locked `error-reporting.test.ts` (type → interface, a redundant cast) and the import order Biome applied to the locked leak test; no assertion changed.

## Review
- **Reviewer + security-reviewer B1 (blocking, fixed):** Sentry's stack parser reads every line of `error.stack` after the first and its pattern is unanchored, so a multi-line message (Drizzle's `params: …` line) containing ` at ` became a frame and its text was sent (reproduced: name and phone in `filename`). Fix: `reportError` hands the SDK a stand-in Error named by its class whose stack is `leadingStackFrames()` (frames only when the stack starts with the current message, and only the run of frame lines after it); `frameOf` keeps only frames with an absolute file and a line number. Proven red without the fix by `error-frames.test.ts`.
- **N1 (fixed):** `contexts.trace.span_id` is now the OpenTelemetry span (`propagationSpanId`). **N2 (fixed):** no trace context without an active span (crashes no longer carry a made-up trace id). **N4 (fixed):** the fetch transport logs one fixed-text warning per 60 s when GlitchTip is unreachable or answers ≥ 400 (`error-transport.test.ts`). **N6 (fixed):** the matrix test fails if 500 appears outside `TEST_ONLY_ROUTES`. **N7 (fixed):** 0.2-09b3 slice path, roadmap, `.env.example` release example.
- **Security R2 (fixed):** `SENTRY_DSN` must match what the SDK accepts (word-only key, no password, plain host, `/<id>`, no query), so the SDK never prints a rejected DSN to stderr. **R3 (fixed):** `crash()` runs once, closes the HTTP server first, then reports and flushes. **R4 (fixed):** `NODE_ENV=test` with `DEPLOYMENT_ENVIRONMENT` staging/production/prod is a `ConfigError`; startup logs a warning whenever test routes are on.
- **Deferred to `docs/backlog.md`:** R1 for the log forwarder and span events, R5 (relative file names), R6 (leak-test values with ` at `), N3 (crash test), N5 (vacuous assertion), N8 (DSN host).
