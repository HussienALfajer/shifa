Status: Planned · Tier: T0 (infrastructure, layer-two scrubbing, secrets generation) · Branch: `feat/0.2-09b3-local-observability-stack`

## Goal
`pnpm obs:up` starts a local stack bound to `127.0.0.1`, `pnpm obs:smoke` proves that one request's trace, log line, metric and error event all arrive and that the synthetic marker reaches none of them, and the Collector deletes denied keys again before storage.

## Plan
1. **Contracts / database / web / Flutter.** None. No change to API source (only `apps/api/scripts/`).
2. **Compose** `infra/observability/compose.yml`:
   - `otel/opentelemetry-collector-contrib` (the `redaction` and `attributes` processors live in contrib); host ports `127.0.0.1:4317`, `127.0.0.1:4318`.
   - `grafana/otel-lgtm` (Grafana, Loki, Tempo, Prometheus): its own OTLP ports stay on the compose network, never published; Grafana on `127.0.0.1:3300` (3000 is the API default); Tempo, Loki and Prometheus query ports on `127.0.0.1` for the smoke check.
   - GlitchTip web + worker (one pinned version), PostgreSQL 18 and Valkey for GlitchTip; only GlitchTip web is published (`127.0.0.1:8000`).
   - Every image `name:version@sha256:…`; every `ports` entry starts with `127.0.0.1:`; every secret is `${VAR:?}` from `infra/observability/.env` (git-ignored by the root `.env` rule); named volumes; healthchecks so `up --wait` works.
3. **Collector** `infra/observability/collector.yaml`:
   - OTLP receivers (gRPC, HTTP) inside the container, reachable only through the `127.0.0.1` host binding.
   - Traces, metrics and logs pipelines: `memory_limiter` → `attributes/deny` (resource, span, log record and data point attributes) → `redaction` (block-list patterns, no allow-all) → `batch` → OTLP exporter to otel-lgtm. No `debug` exporter.
   - Denied keys (spec criterion 6 and `scrub.ts`): `http.request.body*`, `http.response.body*`, `url.query`, `url.full`, `url.path`, old names `http.url`, `http.target`, `http.client_ip`, `net.peer.ip`, `net.sock.peer.addr`; `http.request.header.cookie`, `http.request.header.authorization` and every request/response header except `user-agent` and `content-type`; `client.address`, `client.port`, `network.peer.address`; `db.query.text`, `db.statement`, `db.query.parameter.*`; `exception.message`; `enduser.*`. None of `ALLOWED_SPAN_ATTRIBUTES` in `apps/api/src/telemetry/scrub.ts` may be on the list.
   - Log bodies are not transformed: logs are sanitised in the API.
4. **Grafana** `infra/observability/grafana/`: datasource provisioning (Prometheus, Loki, Tempo with fixed `uid`s; Tempo → Loki link on `trace_id`) and one dashboard `shifa-api.json` (request rate, 5xx error rate, p95 latency by `http_route`).
   *Checkpoint: config and its tests done; count lines here.*
5. **Scripts** (Node ESM, `node:` built-ins, `spawn` with argument arrays, never shell strings): `scripts/obs.mjs up|down|reset|smoke` over a pure core `scripts/lib/obs.mjs`.
   - `up`: on first run writes `infra/observability/.env` (mode `0600` where supported) with a random GlitchTip `SECRET_KEY`, admin password and DB password (`crypto.randomBytes`), never printed; an existing `.env` is never overwritten; `docker compose … up -d --wait`; bootstraps GlitchTip once through `manage.py` in the web container (superuser, organisation `shifa-local`, project `shifa-api`) and stores the project DSN and an API token in the same `.env`; prints the Grafana and GlitchTip URLs only.
   - `down` stops (volumes kept); `reset` refuses without `--yes`, then `down -v` and deletes the `.env`.
   - `smoke`: refuses when the `.env` or stack is missing, then runs `pnpm --filter @shifa/api obs-smoke` with endpoints and DSN in the child environment only.
6. **Smoke check** `apps/api/scripts/obs-smoke.ts` (beside `boot-check.ts`, because it needs `@shifa/db/harness`, an API dependency):
   - Move `freePort`, `startApi`, `waitReady`, `withTimeout` from `boot-check.ts` into `apps/api/scripts/api-process.ts`; `boot-check.ts` behaviour unchanged.
   - Start PostgreSQL through the harness; run the built API with `--import ./dist/instrument.js`, `NODE_ENV=test`, `OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318`, `SENTRY_DSN` from `.env`.
   - Call `/health/ready` and `/_test/fail` with a `traceparent` the script generates, so the trace id is known.
   - Poll up to 60 s: Tempo (trace by id with a server span `GET /_test/fail`), Loki (a line with that `trace_id`), Prometheus (`http_server_request_duration_seconds_count` for `http_route="/_test/fail"`), GlitchTip API (one new event tagged with that `trace_id`).
   - Assert `TEST_FAILURE_MARKER` is absent from the Tempo trace, the Loki lines and the GlitchTip event JSON.
   - One line per check, exit 1 on any miss or leak; the DSN key is masked in output.
   - `package.json`: root `obs:up`, `obs:down`, `obs:reset`, `obs:smoke`; `@shifa/api` `obs-smoke`.
7. **Docs**: `docs/process/observability.md` (run; where to look; following a `requestId` to logs, trace and event; the two scrubbing layers; how to add an attribute safely: allowlist in `scrub.ts` + leak-test string + Collector deny-list review; reset); short `infra/observability/README.md`; links from `docs/README.md`, data handling §1 and the PLT-52 line in `docs/domain/platform-and-configuration.md`; root `CLAUDE.md` Commands line for `obs:*`; roadmap 0.2-09b → Done. The CI gitleaks job scans every changed file, so `infra/` is covered without a config change.
8. **Digests**: looked up with `docker buildx imagetools inspect <image>:<version>` in a shell that reaches Docker (Windows fallback or the owner's WSL2 terminal; not the sandboxed session, OD-24). Only digests read from that output are written.

## Risks
- Image digests and the Collector run test need Docker, which the sandboxed WSL2 session cannot reach (OD-24): build from the Windows fallback or let CI run the test.
- `redaction` processor semantics changed across Collector releases: the run test on the pinned image is the proof, not the config shape.
- GlitchTip bootstrap through `manage.py` (and API token creation) may change between versions: pin the version; the smoke check proves it.
- Prometheus metric names depend on otel-lgtm's OTLP translation (`_seconds` suffix, `http_route` label): confirm against the running stack before locking the query.
- otel-lgtm is a development image; staging and production use separate components (OD-01, out of scope).
