# 0.4-12 Narrow width and small items before Phase A

Status: In progress · Tier: T1 · Branch: `fix/0.4-12-narrow-width-and-small-items`
Spec: [0.4 follow-up before Phase A](../specs/design-system/0.4-followup-before-phase-a.md) criteria 1–13 · Requirements: none · Decisions: OD-40, OD-61, OD-66, OD-67, ADR-0034, ADR-0040 · Backlog: OD-66 narrow-width fixes, P-N1, P-N2, P-N3, P-N7, C-5, C-6, C-7

Independent of [0.4-13](../roadmap.md) (date and time choosers): different files, so the two may run in parallel worktrees. The one shared file is `packages/ui/src/index.ts` (if a new export is added); whichever lands second rebases.

Builds from the approved sheet "Shifa Components (proposals)", page "Before Phase A · 0.4-12 and 0.4-13" (approved 2026-11-23): the header-tooltip, compact-pagination, toolbar-label and rows-per-page boards. No sheet checkpoint is needed; the slice ends with the design-system sync (ADR-0040).

## Goal
A Phase A list, table or form screen works at narrow widths (cut headers and labels with their full text in a tooltip, a pagination that fits at 320 px, a readable rows-per-page value), Arabic search finds a name whatever its hamza, harakat or final letter form and announces results in Arabic, staff fields store nothing in the browser, and the small 0.4 audit records (icon pairs, licences, dev-build history, hand-typed names) are closed with tests that keep them closed.

## Plan
No contracts, database, API, Flutter screens or end-to-end changes. Five checkpoints, each test first; checkpoints 2 to 4 are independent of each other and may be built in any order after checkpoint 1.

### Checkpoint 1 — tokens (criteria 4, 9)
- `packages/tokens/src/semantic/layout.tokens.json`: a size token for the rows-per-page Select, 88 px, compact mode 76 px (name it with the existing size tokens, for example `size.control.select-narrow`; check `packages/tokens/CLAUDE.md` for the naming rule). Regenerate the outputs (CSS, Tailwind, Dart, design-system output); the drift check must pass.
- `packages/tokens/src/contrast-pairs.json`: `color.icon.default` and `color.icon.muted` (whichever `icon.*` tokens exist) on `color.brand.primary-soft`, `color.brand.accent-soft` and `color.selection.subtle`, class `ui`.
- Schema rule in `src/schema.ts` (or the contrast test): every surface that has a `color.text.*` pair has a `color.icon.*` pair.
- Tests first: `test/contrast.test.ts` covers the new pairs; `test/schema.test.ts` fails on a fixture with a text surface and no icon pair, and on today's file before the pairs are added; `test/build.test.ts` (or `design-language.test.ts`) asserts the new size token in both densities.

### Checkpoint 2 — narrow width (criteria 1–4, 13; OD-66)
- Shared hook `packages/ui/src/lib/use-overflow.ts`: `true` when an element's `scrollWidth` exceeds its `clientWidth`, re-measured by a `ResizeObserver` and on text change. Used by the DataTable header and the Toolbar button.
- DataTable (`src/data-table/parts.tsx`, header cell): the label is one line with `text-overflow: ellipsis`; when `useOverflow` is true, the existing `Tooltip` opens on hover after 500 ms and on focus at once; the column's accessible name stays the full header text; the sort button and its `aria-sort` are unchanged.
- Pagination (`src/pagination/pagination.tsx`): the root becomes an inline-size container; below 430 px the compact form («الصفحة 3 من 13», two arrows, the summary on a second line) is shown by a container query, at or above it the numbers form. A container with no size falls into the compact form. Decide in the build whether both forms are rendered and one is hidden (`display: none`, so only one is in the accessibility tree) or the width is measured; prefer CSS only. `form="numbers" | "compact"` keeps forcing one form; the new default is `auto`. The rows-per-page Select uses the new size token (≥ 88 px, 76 px compact) and shows «100» and the chevron.
- Toolbar (`src/toolbar/toolbar.tsx`): a button label is one line, `max-width: 150px`, ellipsis; the icon has `shrink-0`; the full label is the accessible name and shows in the Tooltip when cut.
- Pagination `Zoom200` story in LTR·English uses English copy (criterion 13).
- Stories: `LongArabicLabel` (DataTable, already exists) and new narrow stories for Pagination (320, 429, 430, 600 px containers) and Toolbar (long label), in the RTL/LTR × light/dark × density matrix.
- Tests first (browser, both directions):
  - `data-table.test.tsx`: a header wider than its column is cut (`scrollWidth > clientWidth`) and has a tooltip on hover (after 500 ms, fake timers) and focus; a header that fits has none; the accessible name of the column header is the full text; resizing the column to fit removes the tooltip; sorting by click and keyboard unchanged.
  - `pagination.test.tsx`: at 320 and 429 px the compact form shows and every button's box is inside the region; at 430 and 600 px the numbers form; at 320 px with 200 % zoom (root font size doubled) every button stays inside; the rows-per-page Select is ≥ 88 px (76 px compact) and its value text is not clipped; a container without size shows the compact form.
  - `toolbar.test.tsx`: a long label stays one line (one line box), is ≤ 150 px, the icon keeps its size, the accessible name is the full label, and the Tooltip shows it.
  - `pagination.stories` LTR·English `Zoom200` copy is English (a story-level assertion in the matrix test or `pagination.test.tsx`).

### Checkpoint 3 — Arabic search (criteria 5, 6; OD-40)
- One folding function `packages/ui/src/lib/fold-arabic.ts` (`foldArabic`): NFC, harakat and tatweel removed, alef forms (آ أ إ ٱ) to ا, word-final ة → ه and ى → ي, Arabic-Indic and Eastern Arabic-Indic digits to Western, lower case. Compound-name joining from OD-40 stays out: it builds the stored search key in Phase A, not the word-start match. Note in the file that the Phase A name normaliser (ADR-0034, moved from `spikes/s3-arabic-output/search/src/normalise.ts`) must give the same result on the shared vectors.
- Combobox: `matchesWordStart` folds both sides with `foldArabic`.
- Select: typeahead matches through `foldArabic`. Check first how UI SDK's Select typeahead reads text (`select.d.ts`); if it takes only a label string, pass the folded text as the typeahead text, as `typeaheadText` already does for titles, and confirm the visible label is unchanged.
- Command palette: `normaliseForSearch` in `command-palette/normalise.ts` is replaced by `foldArabic` (the `highlight` helper keeps working: every rule is one unit to one unit, except removals, which it already handles; word-final ة → ه is one to one).
- Combobox announcements: a polite live region says «3 نتائج», «نتيجة واحدة», «نتيجتان», «لا نتائج» in RTL (Arabic plural forms) and "3 results", "1 result", "No results" in LTR, after the list settles (debounced, so not every keystroke). Check whether UI SDK already announces a count (in English); if so, turn it off or replace it, never both.
- Tests first:
  - `src/lib/fold-arabic.test.ts`: the OD-40 vectors that apply (copy the relevant cases from `spikes/s3-arabic-output/search/test/vectors.test.ts`, not import: spikes are throwaway), including «احمد» = «أحمد», «فاطمه» = «فاطمة», a name with harakat and tatweel, ى/ي at word end only, ة inside a word unchanged, Arabic-Indic digits.
  - `combobox.test.tsx`: «احمد» finds «أحمد» and a name stored with harakat; «فاطمه» finds «فاطمة»; the live region text in RTL and LTR for 0, 1, 2 and 3+ results.
  - `select.gate.test.tsx` (or a new `select.test.tsx`): typing «ا» then «ح» moves to «أحمد…».
  - `command-palette.test.tsx`: existing cases still pass through `foldArabic`; one new ة/ه case.
