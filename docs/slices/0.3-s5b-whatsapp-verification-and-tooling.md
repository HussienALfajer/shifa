# 0.3-S5b WhatsApp spike: reverse verification, separation, manual-run tooling

Status: Planned (owner approved the plan, 2026-11-17) · Tier: T0 (phone verification is authentication; tenant and role separation of inbound messages) · Branch: `chore/0.3-s5b-whatsapp-verification-and-tooling`
Spec: [0.3-S5 WhatsApp](../specs/spikes/0.3-s5-whatsapp.md) criteria 9, 10, 11 (tooling) · Requirements: MSG-08, MSG-09, MSG-12, MSG-20, MSG-22, MSG-24 (rate limits), MSG-32 · Decisions: ADR-0016, ADR-0017, ADR-0023, ADR-0026, OD-23, OD-31, OD-45, OD-46
After [0.3-S5a](0.3-s5a-whatsapp-stack-and-sending.md); before [0.3-S5c](0.3-s5c-whatsapp-manual-day-and-result.md). Built in three checkpoints (A–C).

## Goal
A patient's phone is verified only by a code the patient sends to the platform number, never by a code sent to them; inbound messages never cross clinics or roles; and the owner has a page, a script and a checklist to run one day on real WhatsApp safely.

## Choices made by this plan
- **Code:** 6 characters from an alphabet without look-alikes (no `0/O`, `1/I/L`), after a fixed Arabic phrase in the prefilled text (`رمز التحقق في شفاء: K7Q4MX`); matching takes the first code-shaped token after folding digits and case, so extra text and Arabic-Indic digits pass. The lookup key is `HMAC(serverKey, normalisedCode)`; the plain code is never stored.
- **Nonce:** id of at least 128 random bits, bound to `deviceId` and the claimed E.164 number; returned with a device secret that `GET /verify/:nonceId` requires; 10-minute TTL; single use. A code from a sender other than the claimed number is refused (`sender_mismatch`) and does not consume the nonce. Edits, revokes and reactions never count as a code.
- **Rate limits:** 5 nonce requests and 5 failed matches per device and per number per hour, kept in the spike database. The per-number limit lets a stranger block a victim's number for an hour; the report states this trade-off.
- **Platform never initiates:** the platform session's only send function takes `replyTo: inboundMessageId` whose inbound arrived within 10 minutes on that session, and replies only on a successful verification (strangers cannot make it send); replies pass the MSG-32 allowlist. A test checks every outbound recorded on the platform session.
- **Forwarded-link attack:** a victim could be tricked into sending an attacker's prefilled code; the fixed phrase names Shifa and the action. The report and ADR-0036 record the residual risk.
- **Unresolvable `@lid`:** verification fails closed (`lid_unresolved`), resolved only through the container that received the event.
- **Device side:** `messaging/scripts/device.ts` plays the app: requests a nonce, prints the `wa.me` link (in tests, the fake delivers the message), polls until verified, refused or expired. No websocket in the spike.
- **Manual-run tooling:** a local admin page served on `127.0.0.1` only (QR proxied from WAHA on request, never written to disk or logs; session state; buttons for the checklist steps; "resume" after a breaker pause), plus `scripts/manual-run.ts` for the paced batch. The owner's two numbers live in git-ignored `spikes/s5-whatsapp/.env.local` and form the allowlist. During the run, raw webhook bodies and headers go only to git-ignored `.cache/s5/raw/`; `scripts/scrub-fixtures.ts` maps every number, LID, JID, message id, push name and body to stable placeholders, keeps a recomputed signature check result per fixture, writes `spikes/s5-whatsapp/fixtures/*.json`, and deletes the raw files. A check fails on any digit run of 8 or more in committed fixtures that is not a synthetic number.

## Plan

### A. Reverse verification (criterion 9)
1. `messaging/src/verify.ts`: `POST /verify/nonce {deviceId, phone}` → `{nonceId, deviceSecret, waLink, expiresAt}`; platform inbound handler matches code + sender, marks verified, replies "تم التحقق" in the same chat; `GET /verify/:nonceId` for polling.
2. Failure reasons (`expired`, `wrong_device`, `sender_mismatch`, `reused`, `rate_limited`, `lid_unresolved`) recorded per attempt without the number.

### B. Tenant and role separation (criterion 10)
1. Platform session in `waha-platform`, clinic sessions in `waha-clinics`; (container, session) → role and clinic is the only routing key.
2. A code sent to a clinic number is an ordinary inbound (opt-in for that clinic) and never verifies; inbound on clinic A never touches clinic B.

### C. Manual-run tooling and checklist (criterion 11, preparation)
1. Admin page, `manual-run.ts`, raw capture, scrubber and fixture check.
2. `docs/spikes/s5-manual-checklist.md`: the owner's steps with expected results and blanks for timestamps and error codes: link G as platform; P verifies (once plain, once with extra text and Arabic-Indic digits); unlink, link G as clinic; P opts in; 20–40 messages over the day with all controls on (real gaps, cap 30 per rolling hour, quiet hours); acks; P sends "إيقاف", then a normal message; restart `waha-clinics` with no new QR; G's phone offline for an hour while sending; unlink and re-link G; record any 463/475/warning; grep both WAHA containers' logs for G, P, codes and the QR before the scrub; run the scrub.

## Tests written first
- `messaging/test/verify.test.ts` (9): correct code + sender verifies and replies once; extra text and Arabic-Indic digits pass; expired, wrong device, sender mismatch, reused code, third-number code each fail with their reason; sender mismatch does not consume the nonce; polling without the device secret refused; edits and reactions never verify; sixth attempt in an hour rate-limited per device and per number; `@lid` resolved; unresolvable `@lid` fails closed.
- `messaging/test/platform-never-initiates.test.ts` (9, MSG-22): after the whole suite, every platform outbound replies to an inbound on that session under 10 minutes old and passed the allowlist; inbound without a valid code gets no reply; the platform send without `replyTo` is a type error and a runtime refusal.
- `messaging/test/separation.test.ts` (10): inbound on clinic A never changes B; a code sent to a clinic number opts in there and never verifies; an event naming the platform session posted with the clinics container's key is refused; unknown session refused.
- `messaging/test/scrubber.test.ts` (11): a raw capture with synthetic numbers, LIDs and Arabic text scrubs to consistent placeholders; the fixture check fails on an injected real-looking number; raw files are gone afterwards.
- `messaging/test/no-secrets-in-logs.test.ts` (extended): no code, nonce, device secret or QR payload in service or WAHA logs.
