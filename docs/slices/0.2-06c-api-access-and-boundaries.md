# 0.2-06c Fail-closed route permissions and route permission matrix

Status: In review · Tier: T0 (permissions) · Branch: `chore/0.2-06c-api-access-and-boundaries`
Spec: none (foundation tooling; [ADR-0003](../adr/0003-nestjs-modular-monolith.md), [platform-and-configuration](../domain/platform-and-configuration.md) §7 and §verification) · Requirements: PLT-42, PLT-45, PLT-46 (mechanism only)
Depends on: 0.2-06a (merged, #10). Module boundaries moved to [0.2-06d](0.2-06d-module-boundaries.md) at planning (2026-11-08) to keep this T0 diff small; the two slices touch different files and can run in parallel.

## Goal
Every API route is fail-closed: it must declare `@Public()` or `@RequirePermission(key)`, otherwise the app refuses to start and the matrix test fails. A route permission matrix test calls every route with every role and compares the status with a committed expected matrix. Real login (Better Auth) and real role tables stay in Phase A; here the principal comes from an `AuthPort` whose production adapter authenticates nobody.

## Plan
1. **Contracts / database.** None. No OpenAPI yet (0.2-07), no tables, no migration.
2. **Access model** (`apps/api/src/access/`, imported by modules, never the reverse):
   - `permissions.ts`: permission keys as a const union; empty except test keys (`test.read`, `test.sensitive`) that exist only under `NODE_ENV=test` or in a test-only catalogue file, decided at build so production code never grants them.
   - `roles.ts`: PLT-42 roles `owner`, `doctor`, `receptionist`, `assistant`, `accountant`, plus `platform_admin`; role → permission map with empty grants until Phase A.
   - `principal.ts`: `{ userId, tenantId, branchId | null, roles: { role, tenantId, branchId | null }[] }` per PLT-45 scope; `hasPermission(principal, key, scope)` pure function.
   - `decorators.ts`: `@Public()`, `@RequirePermission(key)` (one key per handler; metadata via `SetMetadata`).
   - `auth.port.ts`: `AUTH_PORT` token, `AuthPort.authenticate(request): Promise<Principal | null>`; `NoAuthAdapter` returns `null` always.
3. **API.**
   - `access.guard.ts`: global `APP_GUARD`. No metadata → 500 (`internal_error`, logged with `Controller.method`, never the URL); `@Public()` → pass; `@RequirePermission(k)` → `AuthPort.authenticate`; `null` → 401; principal lacks `k` in the route's tenant/branch scope → 403. Route scope in this slice = the principal's active `tenantId`/`branchId`; path-parameter scopes arrive with Phase A routes.
   - `access-check.ts`: at bootstrap (`OnApplicationBootstrap`), `DiscoveryService` + `MetadataScanner` list every controller handler; throws one error listing every unannotated handler and every handler with both decorators. Runs in `configureApp` so tests and production share it; the 0.2-06a boot check covers it in CI.
   - `access.module.ts`: provides the guard, the check and `AUTH_PORT` → `NoAuthAdapter`; imported by `AppModule`. Health controller gets `@Public()`.
   - Responses use the existing error envelope (401 `unauthorized`, 403 `forbidden`; the existing 401 code was kept); add the codes to `platform/errors.ts` if missing.
4. **Web / Flutter.** None.
5. **Matrix test** (`apps/api/test/architecture/route-matrix.test.ts` + `route-matrix.expected.ts`): builds the real `AppModule` plus a test-only `ProbeModule` (one public route, one `test.read` route, one `test.sensitive` route) and a test `AuthPort` that maps a header to a synthetic principal per role. Enumerates routes from Fastify (`onRoute` hook or `printRoutes`), fails if a route is missing from the expected matrix or the matrix lists a route that does not exist, then for each route × {anonymous, each role} asserts the expected status class (2xx/401/403). Production-only rows (health) are also asserted against `NoAuthAdapter`: every protected route is 401. The expected file is the review surface: a new route without a row fails CI.
6. **Instructions.** `/add-endpoint` skill (`.claude/skills/add-endpoint/`): controller in a module, decorator, matrix row, contract stub until 0.2-07, isolation case if it touches tenant data (link `/rls-policy` from 0.2-06b once merged), module boundary line added by 0.2-06d. `apps/api/CLAUDE.md` and `.claude/rules/api.md` gain the access rules. Roadmap: 0.2-06c row.
