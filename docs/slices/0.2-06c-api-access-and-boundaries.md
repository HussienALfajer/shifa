# 0.2-06c Route permission matrix and module boundaries

Status: Planned · Tier: T0 (permissions) · Branch: `chore/0.2-06c-api-access-and-boundaries`
Spec: none (foundation tooling; [ADR-0003](../adr/0003-nestjs-modular-monolith.md) boundaries, [platform-and-configuration](../domain/platform-and-configuration.md) §7 and §verification) · Requirements: PLT-42, PLT-45, PLT-46 (mechanism only)
Depends on: 0.2-06a merged.

## Goal
Every API route is fail-closed: it must declare `@Public()` or `@RequirePermission(key)`, otherwise the app refuses to start and the matrix test fails. A route permission matrix test calls every route with every role and compares the status with a committed expected matrix. Modules under `apps/api/src/modules/*` may import each other only through `index.ts`. Real login (Better Auth) and real role tables stay in Phase A; here the principal comes from an `AuthPort` whose production adapter authenticates nobody.

## Plan
1. **Access model** (`apps/api/src/access/`): `permissions.ts` (catalogue of permission keys as a const union, empty except test keys until Phase A adds real ones), `roles.ts` (PLT-42 roles `owner`, `doctor`, `receptionist`, `assistant`, `accountant`, plus `platform_admin`; role → permission map, empty grants until Phase A), `principal.ts` (`{ userId, tenantId, branchId, roles }` per PLT-45 scope).
2. **Guard.** Global `AccessGuard`: reads route metadata; no metadata → 500 and a startup check (`DiscoveryService` scan at bootstrap) that throws listing the unannotated handlers; `@Public()` → pass; `@RequirePermission(k)` → `AuthPort.authenticate(request)`; none → 401; principal lacks `k` in the route's tenant/branch scope → 403. Both decorators on one handler → startup error. `AuthPort` production adapter returns `null` always (every protected route is 401 until Phase A); tests override the provider.
3. **Matrix test** (`apps/api/test/architecture/route-matrix.test.ts` + `route-matrix.expected.ts`): builds the real `AppModule` (plus a test-only `ProbeModule` with one public route, one permission route and one sensitive-permission route), enumerates routes from Fastify, fails if a route is missing from the expected matrix or the matrix lists a route that does not exist, then for each route × {anonymous, each role} asserts the expected status (2xx/401/403). The expected file is the review surface: a new route without a matrix row fails CI.
4. **Module boundaries.** Custom ESLint rule in `tooling/eslint-config` (`shifa/module-boundaries`, ~80 lines, no new dependency): inside `apps/api/src/modules/<a>/`, an import resolving into `modules/<b>/` must target `modules/<b>/index.ts`; `src/platform/` and `src/access/` may be imported by modules, never the reverse. Also an architecture test that parses imports with the TypeScript compiler API, so the rule cannot be silenced by an inline disable (`eslint-disable` for this rule is itself banned via `@eslint-community/eslint-comments` or a grep check, decide at build). Cross-module table access becomes checkable once schema files exist per module; recorded in `docs/backlog.md`.
5. **Instructions.** `/add-endpoint` skill (controller in a module, decorator, matrix row, contract stub until 0.2-07, isolation case if it touches tenant data); `apps/api/CLAUDE.md` gains the access and boundary rules; roadmap checklist item "Architecture tests" ticked when 0.2-06b and this slice are merged.
