# 0.2-05 Database test harness and `packages/db`

Status: Planned · Tier: T0 (tenant context, roles, migrations) · Branch: `chore/0.2-05-db-test-harness`
Spec: none (foundation tooling; scope is the Phase 0.2 checklist in [roadmap](../roadmap.md), [ADR-0004](../adr/0004-postgresql-pooled-tenancy-rls.md), [ADR-0005](../adr/0005-drizzle-withtenant.md)) · Requirements: —

## Goal
Any package can run tests against a real PostgreSQL 18: one container per run (Testcontainers), one cloned database per Vitest worker, a guard that never touches a database it did not create. `packages/db` holds the Drizzle client, the migration runner, the two roles and `withTenant()`, proven against FORCE RLS with a test-only table. No product tables yet (tenants and `tenant_deployment` come with Phase A tenancy); no API (0.2-06); no PgBouncer (spike S2).

## Plan
1. **Pins (confirm at build time, record in the PR).** Drizzle ORM and drizzle-kit: exact versions; prefer 1.0 GA if released ≥ 24 h ago, otherwise the latest 1.0 RC (ADR-0005 caveat). Driver `pg` (node-postgres; one connection per transaction, works with PgBouncer transaction mode later). `testcontainers` + `@testcontainers/postgresql` exact. Image `postgres:18.<x>` (Debian, glibc/ICU parity with production) pinned by digest in one constant, `packages/db/test-harness/image.ts`.
2. **Roles (`packages/db/sql/roles.sql`, idempotent, cluster-level, run by the harness and later by deployment).** `shifa_owner` (owns schema, runs migrations, NOLOGIN in production) and `shifa_app` (LOGIN, NOSUPERUSER, NOBYPASSRLS, not owner of anything). Roles are not in Drizzle migrations because they are cluster-wide.
3. **Migrations.** `packages/db/migrations/` via drizzle-kit; `0000_baseline.sql`: `CREATE EXTENSION btree_gist`, `REVOKE ALL ON SCHEMA public FROM PUBLIC`, `ALTER DEFAULT PRIVILEGES FOR ROLE shifa_owner GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO shifa_app` (and sequences: USAGE). Runner `migrate(ownerUrl)` in `src/migrate.ts`. drizzle-kit `meta/*.json` added to `GENERATED` in `.claude/hooks/lib/policy.mjs` and `linguist-generated` in `.gitattributes`.
4. **Client and `withTenant`** (`src/client.ts`, `src/tenant.ts`). `createDb(url)` returns a pool-backed Drizzle instance whose raw handle is not exported. `withTenant({ tenantId, branchId?, userId }, async (tx) => …)`: opens a transaction, validates IDs (UUID), runs one `select set_config('app.tenant_id', $1, true), …` (never session `SET`), passes `tx`; rollback on throw. `src/admin.ts`: `withPlatformAdmin(reason, fn)` placeholder that is the only other path (audit lands with the audit slice; for now it requires a non-empty reason). SQL helper `current_tenant_id()` (`current_setting('app.tenant_id', true)::uuid`, NULL when unset) in the baseline migration, used by every future policy.
5. **Lint.** `tooling/eslint-config`: `no-restricted-imports` for `pg`, `drizzle-orm/node-postgres` and `drizzle-orm/pg-core` session APIs outside `packages/db/src/**` and `packages/db/test-harness/**` (ADR-0005 "raw pool access blocked by lint").
6. **Test harness** (`packages/db/test-harness/`, exported as `@shifa/db/testing`).
   - `globalSetup.ts`: acquires the guard, starts one container, applies `roles.sql` and migrations into `shifa_template` as `shifa_owner`, provides connection info to workers via Vitest `provide`; stops the container in teardown (Ryuk cleans up after crashes).
   - `setup.ts` (per worker): `CREATE DATABASE shifa_test_<VITEST_POOL_ID> TEMPLATE shifa_template` once; exports `testDb()` (connects as `shifa_app`) and `ownerDb()`; `resetTestDb()` truncates all non-migration tables between files.
   - **Guard:** never reads `DATABASE_URL` or any env URL; refuses any host/port other than the container it started and any database name not matching `^shifa_test_\d+$|^shifa_template$`. One DB test run per worktree at a time: a lock in `.verify/db-test.lock` (shared lock code moved from `scripts/verify.mjs` to `scripts/lib/lock.mjs`), waiting up to 5 min for another run before failing with a clear message, stale locks from dead PIDs removed.
   - `vitest.db.config.ts` preset other packages extend.
   - Fails fast with a setup message when Docker is not running.
7. **CI.** `verify` job: ubuntu-24.04 already has Docker; pre-pull the pinned image by digest; set `TESTCONTAINERS_RYUK_DISABLED` only if Ryuk's image cannot be digest-pinned (decide at build, keep zizmor clean). Timing of the DB test step recorded in the PR.
8. **Instructions.** `packages/db/CLAUDE.md` (≤ 4 KB: pattern for a query through `withTenant`, test command, never connect as owner from app code). `.claude/rules/db.md` (paths `packages/db/**`, `**/migrations/**`): expand → migrate → contract, every tenant table gets `tenant_id` first in indexes + FORCE RLS + policy on `current_tenant_id()`. Skill `/db-migration` (generate, review SQL, refuse destructive changes without an approved plan). `/rls-policy` waits for 0.2-06. Update `CLAUDE.md` Commands (Docker required for DB tests), roadmap checklist item, `docs/architecture/overview.md` if stale.

## Tests written first
- `packages/db/test/with-tenant.test.ts` (test-only table `rls_probe` with FORCE RLS created in the test, not in migrations): rows of tenant A invisible inside `withTenant(B)`; insert with a foreign `tenant_id` rejected by `WITH CHECK`; outside `withTenant` zero rows; context does not leak to the next transaction on the same pooled connection; throw inside the callback rolls back; invalid UUID rejected before any SQL.
- `packages/db/test/roles.test.ts`: `shifa_app` is not superuser, has no BYPASSRLS, owns no table; `shifa_app` cannot `CREATE TABLE` in `public`; `roles.sql` runs twice without error.
- `packages/db/test/harness.test.ts`: each worker sees its own database (`current_database()` = `shifa_test_<pool id>`); data written in one worker is absent in another; `resetTestDb()` empties tables.
- `packages/db/test/guard.test.ts` (unit, no Docker): refuses `postgres://prod-host/shifa`, refuses database `shifa`, accepts the container's own URL; lock waits then times out; dead-PID lock is reclaimed.
- `scripts/test/lock.test.mjs`: shared lock behaviour unchanged for `verify`.
- `.claude/hooks` cases: `packages/db/migrations/meta/_journal.json` blocked as generated; merged `migrations/0000_baseline.sql` blocked on `main`.
- ESLint fixture: `import { Pool } from 'pg'` in `packages/testing/src` fails lint.
- Negative checks recorded as evidence: Docker stopped → clear message; a session-level `SET app.tenant_id` in the wrapper fails the leak test.
