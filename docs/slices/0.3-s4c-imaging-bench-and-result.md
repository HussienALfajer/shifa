## Findings from 0.3-S4b the report must carry
- C-STORE rewrites the DICOM file meta group (group 0002); the dataset after it arrives byte for byte. Edge-path checks compare datasets against the source and files against the edge copy (owner decision, 2026-11-16).
- The Transfers plugin (1.7) has no `/transfers/info`; a push is `POST /transfers/push`, `PUT /transfers/push/{id}/{n}`, `POST …/commit` (`DELETE …/{id}` on failure). The edge credential lives up to 12 hours, as Orthanc's peer header is fixed at start.
- The OHIF release image is built for the origin root (webpack public path `/`); the gateway proxies OHIF's `/viewer` route and a strict pattern of its static files at the root, cookie-gated, instead of a `/viewer/` prefix.
- The viewer cookie is `Secure`; inside the spike the gateway is plain HTTP, so the test browser marks the gateway origin trustworthy (`--unsafely-treat-insecure-origin-as-secure`). Production serves TLS.
- Bulk data URIs are off in OHIF (frames only): the gateway does not expose `/bulk/`, and Orthanc's BulkDataURIs name its internal host.
- A Transfers push job is lost when the edge Orthanc restarts, although `SaveJobs` is on (Orthanc logs "Reloading the jobs" and lists none): the harness pushes the study again. A production edge box needs its own queue that re-sends after a restart.
- Scheduled P1 cuts drop the line (open connections end); a plain netem cut only stalls TCP and no request fails. In the fast suite STOW-RS (six requests at once) finished about twice as fast as the chunked upload (one chunk at a time on one connection): bench the chunked upload with two or three files in parallel before comparing.
- Recorded numbers to read carefully (0.3-S4b review N4): `cuts` in `upload-chunked.json` counts the link's events since the stack started, not per test; `interruptedFiles` counts interruptions; `wireRatio` in `edge-push.json` includes a whole study pushed again after the restart, so it is not Transfers' gzip ratio.

- Link shaper jitter: in the fast suite P3 (25 Mbit/s down, ±20 ms jitter) opened images slower than P2 (10 Mbit/s, no jitter) in every run (panoramic 100 s against 15 s). netem's jitter reorders packets and TCP throughput collapses. Before the bench, check the P1/P3 qdiscs (for example netem `rate`, or jitter without reordering) and record the choice.
- Transfers on P1: 4 MB buckets, four in parallel, never arrive whole between line drops every 60 s; the edge uses `BucketSize: 512` and `Threads: 2` (push in 190 s, 0.91 of the study bytes on the wire with a re-push). Bench the bucket size.
- The viewer cookie is `s4_viewer` in the spike: Chromium refuses the `__Host-` prefix from a plain-HTTP origin even when that origin is marked trustworthy. Production: `__Host-s4_viewer` over TLS.

## Decisions ADR-0035 must take (0.3-S4b security review)
- Edge LAN viewing: per-user authentication and audit on the edge box (the spike's edge OHIF proxies study reads with the edge Orthanc's only credential).
- The viewer session: revocable (jti, logout, deny list); separate origins for the viewer and the upload page with a CSP (`connect-src 'self'`, `frame-ancestors`).
- Push audit per study (instance ids from the create body, looked up on commit) and audit of create and abort.
- Staging of chunked uploads: TTL cleaner, per-tenant quota, encrypted or ephemeral volume ("encrypted at rest" does not cover staging); a finished session re-checked against the archive (QIDO) or expired.
- The upload transaction holds a row lock and a connection across hashing and STOW: commit a `storing` state before the STOW and record the outcome in a second transaction; `idle_in_transaction_session_timeout`.
- The edge credential over TLS (mTLS), bound to the box and revocable; one key per credential kind.
- The code exchange by POST or bound to a state value, and session issuance audited.
