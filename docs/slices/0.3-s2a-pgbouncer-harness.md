# 0.3-S2a PgBouncer in the test harness, pooled isolation suite

Status: Planned · Tier: T0 (tenant context, RLS, test infrastructure and CI) · Branch: `chore/0.3-s2a-pgbouncer-harness`
Spec: [0.3-S2 tenant isolation](../specs/spikes/0.3-s2-tenant-isolation.md) criteria 1–3 · Requirements: PLT-01, PLT-50

## Goal
Every DB test run starts PgBouncer (transaction mode, tiny server pool) next to PostgreSQL. `pooledTestDb()` gives the same `createDb()` view as `testDb()` but through PgBouncer, and the cross-tenant isolation suite runs in both modes. Slices 0.3-S2b and 0.3-S2c build their leak tests and measurements on this.

## Plan
1. **Contracts:** none (no API surface).
2. **Database harness** (`packages/db/test-harness/`):
   - `image.ts`: add `PGBOUNCER_IMAGE`, the latest stable PgBouncer, tag + digest, image at least 24 hours old. Choose a maintained image whose tag names the PgBouncer version; configure it only through our own mounted `pgbouncer.ini` and `userlist.txt` (no image-specific env vars), so the image can be swapped. Record the choice and why in the slice's "As built".
   - `container.ts`: start a Testcontainers `Network`; PostgreSQL joins it with an alias; PgBouncer starts on it after roles are applied. `pgbouncer.ini` is built in code: `pool_mode = transaction`, `default_pool_size = 2`, `max_prepared_statements = 200` (> 0), `auth_type = scram-sha-256`, `server_reset_query` left at the transaction-mode default (empty; S2b decides on `server_reset_query_always`), `ignore_startup_parameters` only as needed by `pg`, a wildcard `[databases] * = host=<alias> port=5432`, and one explicit entry with `pool_size = 1` for a fixed pooling database (`shifa_test_9996`, cloned like the pristine `9997`) that S2b uses to force reuse of one server connection. `userlist.txt` is generated per run from the random harness passwords (`shifa_app`, `shifa_owner` for the negative role test) and copied into the container; never written to disk in the repo or logged.
   - `context.ts` / `guard.ts`: `HarnessInfo` gains the pooler address; `urlFor(info, role, db, { via: 'direct' | 'pooler' })`; `assertTestTarget` accepts exactly the PostgreSQL address or the PgBouncer address the harness created, and nothing else (`OWN_DATABASE` unchanged).
   - `index.ts`: `pooledTestDb(options?)` (shared per file like `testDb()`), `rawPooledAppDb()` (negative tests only), `pooledHarnessUrl(role)`. Same closers, same reset.
   - `vitest.db.config.ts`: nothing new; one container pair per run.
3. **Isolation suite:** `isolation.test.ts` loops over `[['direct', testDb], ['pgbouncer', pooledTestDb]]` and runs the coverage test and every case in each mode (cases are empty today, so the probe proof below matters). `runner-gaps.test.ts` keeps its direct run and adds the pooled run for the uncovered-table and leaky-table cases.
4. **CI:** `.github/workflows/ci.yml` "Pull database test images" expects 3 digest-pinned images and its regex accepts the PgBouncer image name.
5. **Docs:** `packages/db/CLAUDE.md` Tests section: `pooledTestDb()`, `rawPooledAppDb()`, the pooling database; image pins line.
6. **Web / Flutter / end-to-end:** not applicable.

## Tests written first
- `test/guard.test.ts` (unit): the pooler address is accepted; another port on the same host, the pooler host with the PostgreSQL port, and an unknown host are refused (criterion 1).
- `test/pgbouncer.test.ts` (DB): `PGBOUNCER_IMAGE` matches `name:version@sha256:<64 hex>`; `SHOW CONFIG` / `SHOW DATABASES` through the PgBouncer admin console (or the generated ini, if the admin console needs a third login) show `pool_mode=transaction`, `default_pool_size=2`, `max_prepared_statements>0`, pool size 1 for `shifa_test_9996`; no userlist file exists under the repository after setup (criterion 1).
- `test/pgbouncer.test.ts`: `pooledTestDb().withTenant()` returns `current_user = shifa_app` and `inet_server_port()` of PostgreSQL (proves the pooler path); `createDb(pooledHarnessUrl('owner'))` is refused with the role error (criterion 2).
- `test/isolation/isolation.test.ts` and `runner-gaps.test.ts` in pooled mode: the `using (true)` probe is reported, the uncovered tenant table fails coverage (criterion 3).
- Negative evidence for the PR: point `pooledTestDb()` at the direct port → the "proves the pooler path" test fails.
