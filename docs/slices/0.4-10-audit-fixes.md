## Plan
No contracts, database, API or end-to-end changes. Four checkpoints, one per finding, each test first.

### Checkpoint 1 — F1: golden tests skip outside Linux
- Cause: `packages/shifa_ui/test/flutter_test_config.dart` turns on CI goldens only on Linux and platform goldens only with `SHIFA_PLATFORM_GOLDENS=1`. Elsewhere alchemist builds an empty variant, and `button_golden_test.dart` and `card_chip_golden_test.dart` fail with `'variant.values.isNotEmpty'`. Check why the other three files pass; all five must behave alike.
- Fix in one place: `shifaGoldenTest` (`test/goldens/support.dart`) passes alchemist's `skip:` when neither config is on (read from `AlchemistConfig.current()`), with a reason that names `node packages/shifa_ui/scripts/goldens.mjs`. Linux, CI and the Docker script still compare all 15 goldens.
- Test first: `scripts/test/shifa-ui-goldens-skip.test.mjs` checks the guard and its reason in `support.dart`, and that every file under `test/goldens/` calls `shifaGoldenTest`, never `goldenTest` directly.

### Checkpoint 2 — F2: generator phone numbers only
- Fixture: `phones(count, { seed })` in `packages/ui/test/fixtures.ts`, from `createRandom` and `generatePhone` (`@shifa/testing`), with a helper that shows a synthetic number in national format (for example `0930 012 345`).
- Replace by hand-typed or template-built numbers:
  - `packages/ui`: `data-table.stories.tsx:33` (eight `+963 9xx` numbers), `drawer.stories.tsx:52`, `form.test.tsx`; the design-system `preview.html` of Drawer, Form and OtpInput.
  - `packages/shifa_ui`: `text_field_test.dart`, `goldens/text_field_golden_test.dart`. Dart cannot import `@shifa/testing`, so they use a constant copied from a generated number, with a comment naming the seed.
  - Outside phase 0.4, caught by the new scan under the same rule (`.claude/rules/patient-data.md`): `apps/api/test/contract/validation.test.ts` (`0999000111`), `apps/api/test/telemetry/scrub-security.test.ts` and `stack-strict.test.ts` (`0944123456`), `scripts/test/obs-collector-scrub.test.mjs` (`+963 944 123 456`, `0944123456`). The scrub tests keep a mobile-shaped number (now marked), so they still prove the scrubber.
- Test first: `scripts/test/no-real-phones.test.mjs` reads every tracked text file under `apps/`, `packages/`, `scripts/`, `spikes/` and `design/` (not `docs/`, which quotes evidence). It finds full SY and TR mobile shapes (`+963`, `00963` or `0` then `9xx…`; `+90` or `0` then `5xx…`; spaces or dashes allowed; no digit or word character on either side), normalises each to E.164, and fails on any that `isSyntheticPhone` rejects. Exempt: `packages/testing/test/synthetic/phones.test.ts`, whose rejected cases are the point. It also proves itself on a planted number and a generated one.
- Baselines: refresh the screenshot baselines in Docker (`docs/process/ui-screenshots.md`) for every story whose numbers changed (DataTable patient list, Drawer, Form at least), and the text-field golden with `node packages/shifa_ui/scripts/goldens.mjs --update`. Look at each changed image.
- Design-system sync for Drawer, Form, OtpInput and DataTable once the tree is final; the owner starts it (`docs/process/ui-screenshots.md` step 2).

### Checkpoint 3 — F3: direction fonts renamed
- `scripts/design-directions-build.mjs`: `PAGE_CSS` (line ~41) and `fontFaces()` (line ~62) use `family.webFamily`. The sources `design/directions/source/*.dc.html` name `'Shifa Sans Arabic'`. Rebuild the four directions: the build copies the renamed product subsets from `packages/tokens/fonts`. The briefs (`design/directions/briefs/*.md`) may keep naming the upstream font in prose.
- Test first, in `scripts/test/design-directions.test.mjs`: no woff2 under `design/` has a name record matching `/plex/i` (reuse `readFontInfo` from `scripts/test/fonts.test.mjs`, moved to a shared helper if needed), and no built page or `fonts.css` sets `'IBM Plex Sans Arabic'` as a font family. This closes the backlog item "direction prototypes still carry the upstream-named Plex subsets".

### Checkpoint 4 — F4: shell guard
- `.claude/hooks/lib/policy.mjs`: `fetchesAndRuns` treats `pnpx` like `bunx`. `commandSegments` unwraps runners: `corepack` is skipped, and after `pnpm exec`, `pnpm x`, `yarn exec` and `bun x` (with runner options before them, such as `--filter ui` or `-r`) the next word becomes the program, checked again by `fetchesAndRuns` and `installsOutsidePnpm`.
- Tests first, in `scripts/test/claude-hooks.test.mjs`. Refused: `pnpx skills add x`, `pnpm exec npx -y skills`, `yarn exec npx skills@latest`, `corepack npm install x`, `pnpm --filter ui exec npx -y x`. Still allowed: `pnpm exec tsc`, `pnpm exec npx tsc -p tsconfig.json`, `corepack pnpm install`, `corepack enable`.

Tests written first: as named in each checkpoint.
