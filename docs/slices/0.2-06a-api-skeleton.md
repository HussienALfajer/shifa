## Goal
`apps/api` exists as a NestJS 12 + Fastify modular monolith that builds to plain JavaScript, starts with validated config, connects to PostgreSQL as `shifa_app` only, answers liveness/readiness, shuts down cleanly and never logs a database value. CI builds it and boots the built output against a real database. No auth, no permissions, no product modules (0.2-06c, Phase A).

## Plan
1. **Pins (confirm at build, record in the PR, all ≥ 24 h old).** `@nestjs/core`, `@nestjs/common`, `@nestjs/platform-fastify` 12.x exact; `reflect-metadata`; `zod` 4 (config only here; contracts are 0.2-07); `pino` via Fastify's logger. Build: Nest needs legacy decorators + `emitDecoratorMetadata`, which Node type stripping and esbuild do not support. Prefer SWC (`@swc/core` + `@swc/cli`) emitting `dist/`; workspace packages export `.ts`, so either bundle them (SWC/`tsdown` with decorator metadata) or compile them with `rewriteRelativeImportExtensions`. Pick the smallest option that makes `node dist/main.js` run with no TS loader; record why.
2. **Layout** (`apps/api/`): `src/main.ts` (bootstrap only), `src/app.module.ts`, `src/config/` (Zod-validated env: `API_PORT`, `API_HOST`, `DATABASE_URL` for `shifa_app`, `LOG_LEVEL`; unknown or missing → exit 1 with the key name, never the value), `src/platform/database.module.ts` (one `createDb()` per process, closed on shutdown), `src/platform/logging.ts`, `src/platform/errors.ts`, `src/modules/health/` (`index.ts` public surface, controller, service). `modules/<context>/` is the pattern 0.2-06c enforces.
3. **Health.** `GET /health/live` → 200 without touching the database. `GET /health/ready` → 200 when `select 1` succeeds through `withPlatformAdmin('health-check', …)`, 503 otherwise; body carries no host, version or error text.
4. **Errors and logging (backlog L6).** One global exception filter: known HTTP errors → minimal envelope `{ error: { code, message } }` (moved to `packages/contracts` in 0.2-07); everything else → 500 `internal_error`. Database errors (`pg` `DatabaseError`, `DrizzleQueryError`) are logged as `{ sqlstate, constraint, table, column }` only. Pino `redact` for `authorization`, `cookie`, `set-cookie`, request body never logged; request id per request (`x-request-id` accepted only if it matches a strict pattern, otherwise generated).
5. **Hardening defaults.** Fastify `bodyLimit` 1 MB, `trustProxy` off (deployment decides later), no `x-powered-by`, `enableShutdownHooks()` with a 10 s drain, unhandled rejection → log and exit 1.
6. **Boot check.** `apps/api/scripts/boot-check.ts` (run with Node type stripping, no decorators): starts the pinned PostgreSQL image through the `@shifa/db` harness context helpers (guard still applies), applies `roles.sql` + migrations as owner, spawns `node dist/main.js` with the `shifa_app` URL, polls `/health/ready` (30 s timeout), sends SIGTERM and asserts exit 0 within 15 s; second run with the owner URL must exit non-zero (createDb refuses owners). `verify` gains a `build+boot` step in full mode only; CI already pulls the images. Turbo `build` task with `dist/**` outputs.
7. **Instructions.** `apps/api/CLAUDE.md` (≤ 4 KB: module layout, how to run, test command, logging rule), `.claude/rules/api.md` (paths `apps/api/**`: no `console.*`, errors through the filter, DB only via `@shifa/db`). Update `docs/architecture/overview.md` if stale, roadmap checklist (boot check), remove the backlog item.

## Decisions made while building
- **Pins** (all exact, ≥ 24 h old on 2026-11-08): `@nestjs/{common,core,platform-fastify,testing}` 12.4.0, `fastify` 5.12.8 (the version Nest pins; types and `frameworkErrors`), `pino` 10.4.0, `zod` 4.6.7, `reflect-metadata` 0.2.2, `rxjs` 7.8.2, `tsdown` 0.23.7.
- **Build: tsdown, not SWC.** One dev dependency; its Oxc transform reads `experimentalDecorators`/`emitDecoratorMetadata` from `tsconfig.json` (verified: `design:paramtypes` in `dist/main.js`). It bundles `src/` and the `.ts`-exporting `@shifa/*` packages into `dist/main.js`; npm packages stay external, so `pg` and `drizzle-orm` are also `apps/api` dependencies. Vitest needs no extra plugin. Injection uses explicit `@Inject()` tokens anyway.
- **Unknown config keys:** refused only when they are near-misses of a known key (same first three letters, edit distance ≤ 2), because real hosts carry unrelated `API_*` variables (this machine has `API_TIMEOUT_MS`).
- **Startup:** `select 1` through `createDb()` before listening; any failure (owner/member role, DB down) → exit 1. `createDb()` now times out connecting after 5 s.
- **Windows:** `child.kill('SIGTERM')` terminates immediately there, so the boot check asserts exit 0 on Linux/macOS only (CI).
- **Locked test edit (owner-approved):** `health.test.ts` `res.headers['server']` → `res.headers.server` (lint only); Biome reordered the imports of `test/support.ts`.
