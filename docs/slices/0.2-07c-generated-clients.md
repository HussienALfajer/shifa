## Plan
1. **Contracts.** Read-only input: `packages/contracts/generated/openapi.json`.
2. **TypeScript client** (`packages/api-client-ts`):
   - `openapi-typescript` → `src/generated/schema.ts`; hand-written `src/client.ts` (~20 lines) creates an `openapi-fetch` client with base URL and `credentials: 'include'`; no auth logic yet.
   - Registered with the drift runner as `api-client-ts`.
3. **Dart client** (`packages/api_client_dart`, added to the pub workspace in `pubspec.yaml`):
   - `swagger_parser` (pure Dart, no Java; pin ≥ 24 h old) with `json_serializable` + `retrofit`/`dio`, output under `lib/src/generated/`; `build_runner` outputs committed. String enums exhaustive, required/nullable as in the contract.
   - Generation runs through `node scripts/dart.mjs`; registered with the drift runner as `api-client-dart` with `full: true` if it takes more than a few seconds.
   - `analysis_options.yaml` excludes `lib/src/generated/**` from `very_good_analysis`; `lib/api_client_dart.dart` exports only the client and models (ADR-0013: the app maps them into its own models later).
4. **Guards.** Generated paths sit under `generated/`, which the edit guard already refuses. Add a size budget to the drift entry: fail if the Dart output exceeds a file/line ceiling set from today's output × a margin (fox-drop lesson: 553 model files), so an unnamed schema shows up as a budget failure, not a 10k-line diff.
5. **API / database / web / Flutter app.** None.
6. **Fixtures.** `packages/api-client-ts/test/fixtures.test.ts` and `packages/api_client_dart/test/fixtures_test.dart` decode the same JSON fixtures (health ok, error envelope per code) and validate them against `openapi.json` (TS with a JSON Schema validator; Dart by round-tripping through the generated models).
