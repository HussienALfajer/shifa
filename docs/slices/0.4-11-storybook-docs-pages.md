# 0.4-11 Storybook docs pages (F5)

Status: PR open (plan approved by the owner, 2026-11-23) · Tier: T1 · Branch: `feat/0.4-11-storybook-docs-pages`
Spec: [0.4 Design system foundations](../specs/design-system/0.4-design-system-foundations.md) criterion 9 · Audit: [0.4, 2026-11-23](../audits/0.4-2026-11-23.md) F5 · Requirements: none · Decisions: ADR-0039, ADR-0040

After the phase audit. Independent of [0.4-10](0.4-10-audit-fixes.md); either may land first (if 0.4-10 lands first, rebase: it changed `data-table.stories.tsx` and `drawer.stories.tsx`). No new component and no visual change to an existing one: the slice adds docs pages, accessibility text and text-state stories of already approved components, so no sheet is needed and nothing is synced to the design system (the producer does not read stories; ADR-0040).

## Goal
A reviewer opens Storybook and finds, for every one of the 37 components, a docs page that shows its usage notes and an accessibility section (keyboard and screen reader), and every text-bearing component shows the four text states (long Arabic label, mixed direction, 200 % zoom, reduced motion). Tests keep all three true.

## Plan
No contracts, database, API, Flutter or end-to-end changes. Three checkpoints, each test first.

### Checkpoint 1 — addon-docs and autodocs
- Add `@storybook/addon-docs` at `10.6.7` (exact pin, the version of the other Storybook packages; it is older than `minimumReleaseAge`) to `packages/ui` devDependencies and to `addons` in `.storybook/main.ts`. Turn on autodocs once in `.storybook/preview.tsx` (`tags: ['autodocs']`), not per file. No MDX files.
- Docs page and the matrix: each story renders the eight combinations of `withMatrix`; on a docs page every story of the component renders at once. Check, in the built Storybook, that a docs page loads, that axe has no violation on it, and that ids made with `useId` do not collide between stories on one page (each inline story is its own React root). If they collide or the page is too heavy, render docs stories in iframes (`parameters.docs.story.inline: false`) and say so in the slice's As built.
- `screenshots/stories.spec.ts` already keeps only `type === 'story'` entries, so docs pages get no baseline. Add one assertion there: the built `index.json` has exactly one `docs` entry per stories file (37).
- Update the comment in `main.ts` and the Storybook row of `docs/process/ui-screenshots.md` if it names the addons.

### Checkpoint 2 — an accessibility section in every stories file
- Format, in `parameters.docs.description.component` of each meta: the usage paragraph, a blank line, then a paragraph that starts `**Accessibility.**` and says (a) the native element or ARIA role, (b) the keys that work, (c) what a screen reader announces, and (d) any rule for the caller (an `aria-label`, `<bdi>` around Latin text). Components with no keyboard interaction (avatar, badge, empty state, icon, skeleton, spinner) say so in (b) instead of leaving it out.
- Write it for all 37 files. The facts come from each component's code and its browser tests, not from memory; the twelve files with none today (avatar, badge, checkbox, date-picker, empty-state, icon-button, icon, number-input, radio, switch, textarea, time-input) need the most, the other 25 mostly move existing sentences into the section. Button's existing `Accessibility:` sentence becomes the same format.
- Test first: `packages/ui/test/stories-docs.test.ts` (node project, `verify` fast). For every `src/**/*.stories.tsx` it reads the source text and checks that the meta has a `docs.description.component`, that it contains an `**Accessibility.**` paragraph, and that the paragraph mentions the keyboard (`key`, `Tab`, `Enter`, `Space`, `Arrow`, `Escape` or "no keyboard") and the screen reader (`screen reader`, `announce`, `aria-` or `role`). It also checks `main.ts` lists `@storybook/addon-docs` and `preview.tsx` sets the `autodocs` tag. Fails today on 36 files.

### Checkpoint 3 — text states in the six files
- Add `...storyStates(render)` to the stories of data table (a long Arabic column header and cell), form (field label and submit), toolbar (action labels), pagination (the page summary), avatar (the name it is drawn from and its accessible name) and icon button (its `aria-label` and tooltip). Labels use `TEXT_STATES`, which use synthetic names only.
- Exempt, with the reason recorded in spec 0.4 Edge cases: `icon` and `skeleton`, which carry no text.
- Test first, in the same `stories-docs.test.ts`: every stories file calls `storyStates(` unless it is in the exempt list, and the exempt list matches the spec line. Fails today on the six files.
- Baselines: 24 new stories, so 24 new screenshot baselines, made in Docker (`pnpm ui:screenshots --update`, `docs/process/ui-screenshots.md`); look at each new image and restore any untouched baseline that `--update` rewrote with anti-aliasing noise (as in 0.4-10). The Storybook test run checks the new stories with axe.

Tests written first: `packages/ui/test/stories-docs.test.ts` (criterion 9: docs addon and autodocs, accessibility section, text states); the docs-entry count in `screenshots/stories.spec.ts`.
Estimated hand-written lines: ~600 (37 description edits ~300, six storyStates renders ~120, test ~130, config and docs ~50; baselines are generated and not counted).

## As built
- Docs stories stay inline (`docs.story.inline` unchanged). Checked on all 37 docs pages of the built Storybook (Playwright, 1280 × 800): every page loads in under 2 s, no id repeats between stories (the `useId` ids are unique across the inline roots; only addon-a11y's own vision-filter SVG ids repeat), every page shows its `**Accessibility.**` paragraph, and axe finds no WCAG violation in the stories (the only story finding is best-practice `heading-order`, below).
- One change the check called for: the matrix (`.storybook/matrix.tsx`) chose two columns by the viewport (`lg:`), so on a docs page (about 1000 px of content) each copy got half of it and the data table's pagination overlapped (axe `target-size`). It now uses a container query (`@container`, `@6xl:grid-cols-2`, 72 rem): two columns on the 1280 px story canvas as before (616 px each, no baseline moved), one on a docs page.
- Axe on docs pages beyond a story's own run: best-practice `heading-order` on the accordion, card and empty-state pages (a story's first heading follows the page's `h1`; in story mode it is the first heading and passes), and Storybook's own controls panel failing `listitem` on two pages; both in `docs/backlog.md`.
- Accessibility paragraphs: written from each component's source and browser tests; where a key comes from the UI SDK and no test of ours proves it (menu Home/End, toast F6 and Escape), it was confirmed in the installed UI SDK source. The test's "no keyboard" match is lower-case, so those components say "It has no keyboard interaction".
- Text states: data table (a long header and the same text in a cell), form (field label and submit), toolbar (first button), pagination (the summary and «الصفحة 248 من 494» of 12,345 rows, in the compact form, since the numbers form does not fit a 256 px column or 200 % zoom), avatar (drawn from the label, the label beside it; mixed direction is a Latin name with `<bdi>`) and icon button (`tooltip` on, the label shown beside it, since a tooltip opens one at a time). Gaps they show are in `docs/backlog.md` for the walkthrough.
