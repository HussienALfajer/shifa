# 0.4-02 Three design directions, the owner's choice, and fonts

Status: Planned · Tier: T1 (sets the token values every component reads; synthetic names only) · Branch: `feat/0.4-02-design-directions`
Spec: [0.4 Design system foundations](../specs/design-system/0.4-design-system-foundations.md) criteria 4–5, 12 (project, token output, guide) · Requirements: none · Decisions: ADR-0039, ADR-0040, OD-57, OD-58, OD-56, OD-20

After [0.4-01](0.4-01-tokens-pipeline-and-contrast.md). Five checkpoints (A–E); B and C need the owner.

## Goal
The owner has opened three interactive design directions on the same three screens, picked one, and the choice is recorded: its rationale in the design doc and its values (type scale, radius, elevation, motion, icon style) in the tokens. The two font families are self-hosted, subsetted and licensed in the repository.

## Choices made by this plan
- **Shifa design project (ADR-0040):** the three directions are drawn in a Design canvas of the project, on the Shifa Design System created here from the tokens and the logo. The static builds below are their exports and stay the repository's record.
- **Design-system token output:** a fourth output of the tokens build, `packages/tokens/generated/design-system/tokens.json`, in the Design System type's list format (colours per theme with usage notes, type styles, spacing, radius, shadows), under the `tokens` drift check. Usage notes come from `$description`; a semantic token without one fails the schema test.
- **Values the choice must fill** (missing after 0.4-01): named type styles (title, label, paragraph), elevations named by job (card, input, dropdown, modal) with the focus ring, icon and disabled-text colours, the overlay colour, a selection tint scale, an avatar palette, the icon set.
- **Guide page:** one artboard set in a "Shifa Guide" canvas drawn from the output above: the layer flow, then 01 Foundations, 02 Theme, 03 Tokens, 04 Effects, 05 Typography, 06 Rules.
- **Where the builds live:** `design/directions/<a|b|c>/` at the repository root, each a static build exported from Claude Design (HTML, CSS, JS, no network at run time), marked `linguist-generated` and excluded from Biome, ESLint and the file-length check. `design/directions/README.md` says how to open them and which one was chosen. The two not chosen stay as the record of the decision.
- **Who makes them:** the session writes one brief per direction (`design/directions/briefs/<id>.md`: the seven principles, the palette, the three screens, synthetic data from `@shifa/testing`); the directions are produced in Claude Design with the owner, exported, and committed by the session.
- **Screens (same in each):** reception queue (desktop), doctor visit (desktop and 10-inch tablet), patient booking (phone); each with RTL, a light/dark switch and a density switch; Western digits only (OD-20 closed, see below).
- **Fonts:** source files in `packages/tokens/fonts/`: WOFF2 subsets for the web (Arabic, Latin, digits, punctuation) and TTF for Flutter, with `OFL.txt` per family and a `fonts.json` manifest (family, weights, version, source URL, SHA-256). Subsetting by a pinned tool run through `scripts/`; outputs committed.
- **Budget:** each WOFF2 subset ≤ 60 KB; the test holds the number.

## Owner's decisions before the build (2026-11-20)
- **Four directions, not three.** After web research (clinical design systems, Arabic UI fonts, RTL practice) the owner approved three directions and asked for a fourth of the session's own design. Builds live in `design/directions/<a|b|c|d>/`:
  - **a. Precise (الدقيق):** clinical ledger. Radius 2/4/6, 1 px borders, shadow on overlays only, type ratio 1.125, thin outline icons, motion 70/110/150 ms.
  - **b. Calm (الهادئ):** quiet professional tool. Radius 4/6/8/12, tonal cream layers, soft separators, ratio 1.2, motion 100/150/200/240 ms.
  - **c. Warm (الدافئ):** welcoming cards. Radius 8/12/16, small soft shadow, ratio 1.25, body 16–18 px, duotone icons with gold.
  - **d. Courtyard (أرض الديار):** one lit focal surface per screen (the current patient, the current step) with everything else receding; a day thread with a gold "now" mark; ablaq banding for table rows; an arch-topped focal card; Naskh for the human voice (patient name, note text), Plex for the system; an eight-point star as the only ornament. Radius 6/10/16, border-first, ratio 1.2, motion 100/160/220 ms.
- **Fonts confirmed:** IBM Plex Sans Arabic (UI) and Noto Naskh Arabic (long text, print).- **Icons:** Phosphor (MIT) with Healthicons (CC0) for medical glyphs, to be confirmed on the builds.
- Research notes to apply: compact density for pointer devices only (32 px rows are below the 44 px touch target); a sub-100 ms motion step for hover and press; light theme by default, dark for the waiting-room display.

**Digits (owner, 2026-11-20, OD-20 closed):** IBM Plex Sans Arabic has no tabular Arabic-Indic digits (widths 263–630 units, no `tnum`, no stylistic set changes them); Western digits are tabular (600). The owner chose Western digits only, and left the consequence to the session: Plex stays as it is, no digits font is made, the builds have no digit switch. Both locked tests were changed for this decision and locked again: the width test checks Western digits only, and the switches test no longer asks for `data-digits`. The fonts still cover the Arabic-Indic digits so typed text renders.

Directions test: 1 of 17 passes; the rest wait for the four builds.

**Checkpoint B (2026-11-20):** the four directions are drawn in one Design canvas of the owner's account ("Shifa Design Directions", link not committed): sixteen artboards, four per direction (reception queue, doctor visit, doctor visit on the tablet, patient booking), each with theme and density as tweaks and one working action.
