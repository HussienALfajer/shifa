## Goal
A screen can show records and waits: cards, status marks, people, loading and empty states, a toolbar and page controls, and a dense table that stays fast with thousands of rows and is fully usable by keyboard in RTL.

## Components (9)
Avatar, badge, card, skeleton, spinner (loading indicator), empty state, toolbar, pagination, data table.
- UI SDK 0.1.0-beta.13 ships `avatar`, `toolbar` and `pagination`; those three are built on it.
- Badge, card, skeleton, spinner and empty state are presentational (no interactive role): our own markup on tokens.
- UI SDK has no table (ADR-0039): the data table is built on `@tanstack/react-table` and `@tanstack/react-virtual` with our own grid keyboard model. `role="grid"` is not among the roles the `/ui-component` skill forbids hand-rolling; the model follows the APG data grid pattern.

## Choices made by this plan
- **Spinner (owner's request, 2026-11-20):** Shifa's own loading indicator as a public component, drawn on this batch's sheet and approved there; it replaces the internal `Spinner` that Button uses since 0.4-03 (`packages/ui/src/icons/spinner.tsx`, a faint track and an arc). Sizes from the icon tokens (and a large one for full-panel waits), colour from its text; `role="status"` with an Arabic label ("جارٍ التحميل") when it stands alone, hidden when a control already says it is busy (`aria-busy`); still under reduced motion; a short delay before it shows so quick loads do not flash. Skeleton stays for content whose shape is known; the spinner is for waits without a shape (a button, a panel, a page). The sheet may give it a Shifa character (for example the jasmine-cross motif of the logo), within the motion rules (120–240 ms easing, no GPU effect). Button keeps its tests; its busy screenshots change only if the sheet changes the drawing.
- **Badge** has two families: neutral/brand (themable) and status (locked tokens, always icon or label with the colour, principle 7). A count form (digits, a cap such as `99+`) for tabs and menus.
- **Avatar** on UI SDK `avatar`: image with a fallback of initials from the first Arabic letters (first letter of the first and last names; Latin names isolated); fallback colour from the avatar palette of 0.4-02b, chosen by a stable hash of the name; sizes from the tokens; the image's `alt` or the name is the accessible name; an avatar group with an overflow count. Stories use `@shifa/testing` names only.
- **Card:** a surface with optional header (title, description, actions), body and footer; not interactive by itself; a link or button card puts one real control inside with the whole card as its hit area (no nested interactive elements).
- **Skeleton:** blocks, text lines and a circle on the token surface; a soft pulse that stops under reduced motion; hidden from assistive technology, with the busy state carried by the container (`aria-busy`).
- **Empty state:** icon or illustration slot, title, description and up to two actions; two sizes (panel, page); text is caller text or i18n keys, never built by the component.
- **Toolbar** on UI SDK `toolbar`: one tab stop, arrows move in reading direction, Home and End; groups with separators; overflow onto our Menu (0.4-04) when narrow.
- **Pagination** on UI SDK `pagination`: previous and next with mirrored arrows in RTL, page numbers with ellipses, the current page announced (`aria-current="page"`), an optional page-size select (our Select) and a "showing 1–25 of 312" line with Western digits (OD-20) and grouping (OD-61). Controlled (`page`, `onPageChange`); no data fetching.
- **Data table dependencies:** `@tanstack/react-table` and `@tanstack/react-virtual`, the current stable versions older than 24 hours, exact pins, MIT entries in `dependency-licences.json`, `test/dependencies.test.ts` updated. A short check before table code that both work with React 19.3 (no warnings in the browser tests); if one does not, stop and ask the owner.
- **Data table API:** column definitions and rows in, no data fetching inside; controlled or default state for sorting, selection and column visibility; server-side paging and sorting are callbacks (`manualSorting`, `manualPagination`), and Phase A wires them to the API. The public API never shows TanStack types (`test/public-api.test.ts`): our own `DataTableColumn` type maps onto them.
- **Data table features:** sorting, row selection (checkbox column from 0.4-05, select-all on the visible page with its mixed state), column visibility (a menu in the table's toolbar), sticky header, first column pinned on the logical start, row virtualisation, both densities (32 px compact rows, 44 px comfortable), loading (skeleton rows) and empty states (this batch's empty state), numeric columns with tabular digits and end alignment, Latin cells isolated (`<bdi>`), this batch's pagination below the table.
- **Table keyboard model:** `role="grid"` with one tab stop (roving `tabindex` on the active cell); arrows move the active cell in reading direction (Left moves to the next column in RTL); Home/End to the row's first and last cell, Ctrl+Home/End to the first and last cell; PageUp/PageDown by a visible page; Space selects the row; Enter triggers the row action; a control inside a cell is reached with Enter and left with Escape. Sort headers are buttons, with `aria-sort` on the column header.
- **Not in this slice:** column resize and reorder, grouping, inline cell editing, export. They join when a Phase A screen needs them.
- **Performance check:** 5,000 synthetic rows render with a bounded number of DOM rows and scroll without layout thrash (a test counts rendered rows; no timing assertion in CI). Virtual rows keep `aria-rowcount` and `aria-rowindex` so a screen reader knows the full size.
- **Open decisions for the sheet (OD-64):** spinner delay and look; badge sizes and the count cap; avatar sizes and initials rule; pagination form (numbers or "page 3 of 12") and page sizes; empty-state illustration style; the table's default density, row action (Enter and click open the record, or an action column), the look of the pinned column and sticky header over scrolled content, and the selected-row tint. They go to the owner with the sheet and into `docs/open-decisions.md`.
- Files stay under 400 lines: the table, its keyboard hook, its column mapping and its parts in separate files.
- Follows the `/ui-component` skill; the 0.4-04 fallback procedure applies where a UI SDK part fails in RTL.

## Differences from the sheet and the plan (explained, not fixed)
- The data table's «الأعمدة» menu sits under the table at the logical end, beside the pagination, not in the bar above it: the grid is then the first Tab stop (its locked test), and the caller's own tools keep the bar above.
- Comfortable table rows are 48 px (the `table.row-height` token), not the 44 px the plan named.
- The spinner's still frame (reduced motion) has the fading trail behind the lit petal in the clockwise direction it moves (top-left lit, then bottom-left, bottom-right, top-right fading); the sheet's still drawing had the trail on the other side (review N8).
- The toolbar fills the width of its row (so it can measure what fits); the selected-rows bar of the sheet («2 محددان» with actions) is the caller's, through the table's `toolbar` slot.
- Badge sizes and paddings use token steps (12 px icon in sm, 16 px in md; 8 px inline padding in sm) for the sheet's 14 px and 10 px.
