## Goal
A screen can show records: cards, status marks, loading and empty states, and a dense table that stays fast with thousands of rows and is fully usable by keyboard in RTL.

## Components (8)
Avatar, badge, card, skeleton, empty state, toolbar, pagination, data table.

## Choices made by this plan
- **Badge** has two families: neutral/brand (themable) and status (locked tokens, always icon or label with the colour).
- **Avatar** shows initials from the first Arabic letters when there is no image; stories use `@shifa/testing` names only.
- **Data table** (`@tanstack/react-table` and `@tanstack/react-virtual`, exact pins): column definitions in, no data fetching inside; sorting, row selection, column visibility, sticky header, start-pinned first column, row virtualisation, both densities (32 px compact rows, 44 px comfortable), loading (skeleton rows) and empty states, numeric columns with tabular digits and end alignment, Latin cells isolated.
- **Table keyboard model:** `role="grid"`; arrows move the active cell in reading direction; Home/End, PageUp/PageDown; Space selects the row; Enter triggers the row action. Server-side paging and sorting are callbacks; Phase A wires them to the API.
- **Not in this slice:** column resize and reorder, grouping, inline cell editing, export. They join when a Phase A screen needs them.
- **Performance check:** 5,000 synthetic rows render with a bounded number of DOM rows and scroll without layout thrash (a test counts rendered rows; no timing assertion in CI).
- Follows the `/ui-component` skill.
