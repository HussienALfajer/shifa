The spike is split in four by the ~4,000-line budget of [ADR-0032](../adr/0032-slice-size-budget-4000-lines.md) and by the two points where the owner's time is needed (the design pick, the doctor sessions): this slice holds the design exploration and everything that does not depend on the chosen direction; [0.3-S8b](0.3-s8b-charts-shell-and-odontogram.md) builds the test shell and the odontogram; [0.3-S8c](0.3-s8c-charts-perio-skeleton-and-session-kit.md) adds perio entry, the skeleton chart and the session kit; [0.3-S8d](0.3-s8d-charts-sessions-and-result.md) holds the sessions, the revision round and the report. ## Goal
The owner compares two live Arabic RTL design directions per chart in one Claude Design project and picks one each. The rules the three charts must obey, the eleven scripted tasks with their expected final states, the scorer and the session-log schema exist as a tested pure TypeScript package, so the UI slices only draw and wire.

## Choices made by this plan
- **Claude Design work is done by the session** through the app's design artifact tooling; the project stays private to the owner's account and holds designs only (no doctor or clinic names, synthetic patient only). If the session cannot create or edit the project, it writes the six prompts into this file and the owner runs them. No Figma file is created (OD-47).
- **What the two directions vary** (so the pick decides something): odontogram: where the "existing" and "planned" palettes sit (two fixed side panels vs one panel with a layer switch that recolours the whole toolbar) and how surfaces are picked (enlarged five-surface tooth vs surface chips); perio: full-arch grid vs focused tooth with an arch strip; skeleton: side chip proposed from the tapped side and confirmed vs always blank until chosen. Rules fixed by the spec (anatomical orientation, tooth first, Missing ≠ Extracted, mandatory chip) are the same in both.
- **Rules live in `spikes/s8-charts/rules`** (`@shifa-spike/s8-rules`), no DOM, no React: written to be lifted into Phase B and C (spec, verification contract).
- **Surfaces:** canonical {M, O, D, B, L}; display alias I for O on anteriors (13–23, 33–43), F for B on anteriors, P for L on upper teeth. V is out of scope (spec lists five).
- **Scoring is on final state only** (spec 8): a task's expected state is a set of chart items; extra items fail it. D5 passes with at most 3 wrong cells over depths, margins and bleeding together. Skeleton pain marks are scored by symptom type, kind, intensity and the set of body regions (with side) the mark starts and ends in, not by pixels.
- **Wrong-tooth and wrong-side counters:** an applied action on a tooth outside the task's expected teeth, or a committed side chip or level different from the expected one, counts once each, even when undone later.
- **Log schema has no free-text field:** every string is an enum or a fixed pattern (participant code `D1`–`D3`, `O1`–`O2`; experience band; current-software list with "other"); a test walks the schema and fails on an unconstrained string. Free comments stay in the moderator's notes (0.3-S8d).
- **Digits:** Western digits in every rule output and label (spec 3).
