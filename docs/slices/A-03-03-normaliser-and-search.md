# A-03-03 Name normaliser and patient search

Status: Built, in review · Tier: T0 · Branch: `claude/focused-hamilton-fpulsm` (the cloud session's branch; planned as `feat/A-03-03-normaliser-and-search`)
Spec: [A-03](../specs/patients/A-03-patients.md) criteria 4–6; from A-03-01: criteria 21, 24 · Requirements: CLN-40 · Decisions: ADR-0030, ADR-0034, OD-40, OD-42, OD-145

Second API slice of A-03, after A-03-02. Three checkpoints: normaliser, search, benchmark and ADR.
Contract: delivers the rows of the A-03 screen contract that name this slice, each proven by a contract test (ADR-0047).

## Goal
One search box finds a clinic's active charts by name however it was spelled, by phone, by file number and by previous file number, inside the tenant's RLS, within 150 ms at p95 at 50,000 charts per clinic.

## Plan
### Checkpoint 1 — the normaliser in production
- The ADR-0034 normaliser moves from `spikes/s3-arabic-output` into a shared package (`@shifa/contracts` `name-key.ts`) and a Dart port (`packages/shifa_testing` or a small `shifa_name_key` package used by the offline clients), with `name-search-vectors.json` moved beside it as the contract.
- The backlog gaps as the owner decided them (OD-145, 2026-11-27): U+061C, U+2060 and every other format character (Cf) removed like the bidi controls; Latin letters lower-cased over the whole Latin range without locale rules (backlog "Normaliser gaps", "Search folding loose ends"; amends OD-40's ASCII-only rule, recorded in the ADR); the vectors gain those cases and ؤ, digit and NFC variants, vectors first, then every port. CI runs the vectors on both ports; the SQL port stays a drift check in tests only.
### Checkpoint 2 — tokens and search
- **Database** (`/db-migration`, `/rls-policy`; expand + migrate): `patient_name_token` (tenant_id, patient_id `(tenant_id, patient_id)` FK, token, key version; FORCE RLS, isolation case), written by the chart repository on every create and edit in the same transaction, and backfilled for charts made in A-03-02; a `(tenant_id, token)` btree for equality matching under RLS (no `LEAKPROOF`, no superuser, no extra service, OD-42). Phone search: digits stored normalised with an index usable for the last 7 or more digits (reversed-digits key or a suffix column, chosen by the plan check). `pg_trgm` similarity ranks the matched rows only.
- **Contracts** — `PatientSearchRequest` (term in the body only, `includeArchived` honoured for the owner), `PatientSearchResult` (at most 20, best first: display name, file number, age fields, sex, contact phone, family size, `state`, `matchedBy`).
- **API** — `POST /patients/search` (`patients.view`); order: exact file or previous number, then phone, then name rank; a merged chart's number answers the chart it was merged into, marked `merged` (A-03-08 makes the state reachable; tested here with a fixture row); a per-member rate limit (429 `rate_limited`); search writes no read audit; the term is never logged (leak test).
### Checkpoint 3 — benchmark and ADR
- Benchmark test at 50,000 synthetic charts in each of two clinics, under `shifa_app` behind PgBouncer (the 0.3-S2 pooling harness): search by name, phone tail, file number, and the duplicate-check query shape A-03-04 will use, p95 ≤ 150 ms; `EXPLAIN` asserts the token index is used.
- ADR-0052 "Patient name search on a token table" amending ADR-0034 (closes its OD-42 consequence).
Searchable custom field values join this search in A-03-06.

Tests written first: vectors on TypeScript and Dart, the new gap cases (6); one test per search path: name variants from the vectors, any part order, phone formats and last 7+ digits, file number, previous number (4); archived only for the owner with the flag, merged number leads to the kept chart, the 20 cap and the order (4); tokens rewritten on edit and backfilled; isolation case for the token table; term absent from logs, spans and URLs; rate limit; the benchmark and plan check (5).

### Decisions taken during the build (reported to the owner)
- **Latin range (OD-145):** Dart's case tables predate Latin Extended-C and -D (the vector listing every capital found 49 letters the ports disagree on), so the rule lower-cases Basic Latin, Latin-1, Extended-A and -B, Extended Additional and full-width Latin only; Extended-C and -D stay as typed. Turkish and every Azaz name are in the covered blocks.
- **Format characters:** every Cf character is removed except ZWSP, ZWNJ, ZWJ and BOM, which stay word breaks as before (their vectors unchanged).
- **Vectors:** the new file lives in `@shifa/contracts`; spike S3 keeps its version-1 file and ports as they were (its manual suite would fail on version 2). `foldArabic` (UI word-start matching, stored place keys) keeps OD-40's rules: changing it would change stored place keys.
- **Matching:** a typed word matches a stored word's start (tokens are every prefix of 2–24 letters); every distinct typed word of 2 letters or more must match (at most 6 are read); words of one letter are ignored. The charts holding all words come from intersecting each word's index-only scan (one word alone: whole-word holders first); at most 1,000 are ranked, and a cut answers `truncated`. Ranking: whole-word matches, then trigram similarity of the stored key, then file number. A typed start that folds to a particle («آم» → «ام») joins the next word; the search then retries word by word (found by the benchmark). Each search statement has a 2 s `statement_timeout` (transaction-local).
- **Typos (owner, 2026-11-27, after review finding 3):** when the tokens find nothing, a trigram fallback keeps the charts where every typed word is a token or has similarity ≥ 0.25 with one of the chart's whole words; candidates are the charts holding every typed word some chart holds (else every word's first three letters). Marked `name_variant`, `matchedParts` empty.
- **Order across paths:** exact file number, previous number, exact phone, phone tail, names; a chart appears once, at its first path. Digits-only terms never search names; 1–9 digits are a file number (leading zeros allowed), 7 or more also a phone tail. Any term holding a digit also looks up a previous number, as typed or in either digit system («123/2019», «٢٢٠٧»); a term with no digit and no 2-letter word is 400.
- **Contract change (reported to the owner):** each result also carries `givenName`, `fatherName` and `familyName`, so the screen can mark the words of `matchedParts` (review finding 4); the contract row says so. No drawing changes (the row's fields, not the screen, changed).
- **Merged charts** never appear by name or phone; their file or previous number answers the kept chart with `mergedFileNumber`.
- **Rate limit:** 60 searches a minute per member of a clinic, counted in the API process (one instance today; ADR-0052 notes the second instance); a member past it is logged by tenant and user id (security L3). The number is mine; tell me if reception needs more.
- **Backfill:** charts with key version 0 (A-03-02's) or an older version are written by the clinic's next searches, at most 3 batches of 200 per request, each in its own transaction with `SKIP LOCKED` (security L1); a support session's READ ONLY search skips it.
- **Token table key:** `patient_name_token` has a uuid `id` primary key (every table's key is a uuid, `schema-keys` test) and a unique `(tenant_id, patient_id, part, word, token)`; both unmerged migrations were regenerated for it (`20261127211025_a03_name_tokens`, `20261127211026_a03_name_token_policies`).
- **Dart package budget:** none needed; the new package is small. `pnpm-lock.yaml` also re-resolved one spike's vitest peer (`esbuild`) when the new importer was added.
- **Locked tests:** two assertions in `search-rules.test.ts` forgot that the test helper adds a random father's name; the owner unlocked the file for that fix (`fatherName: null` in two registrations, no assertion changed) and it was relocked. The owner also unlocked the leak test to add the 403 and 429 paths and a typo term (review 6); relocked.
