## Goal
The owner can follow one guide to get Ubuntu 26.04 in WSL2 with Node 24, pnpm 12, FVM Flutter, Docker and the Claude Code sandbox working, and any developer or session can run `pnpm env:check` to see in one table what is ready and what to fix. Windows (`D:\shifa`) keeps working as the unsandboxed fallback.

## Build location and acceptance
- The slice is built in the Windows checkout (WSL2 does not exist yet). Every script it adds must pass there (criterion 6).
- Criteria 3 and 5 need the owner's machine in WSL2. Because every PR auto-merges on green CI (ADR-0028), the PR merges with the guide, the script and the tests; the slice stays `In review` on the roadmap until the owner runs the acceptance steps below and the output is recorded in this file by a small docs PR (or by the first commit of 0.2-09b, which is built in WSL2). ## Plan
1. **Contracts / database / API / web / Flutter.** None (developer tooling, no product endpoints).
2. **Environment check** (Node ESM, `node:` built-ins only, no shell syntax, `node:path` for paths):
   - `scripts/lib/env-check.mjs` — pure core: `runEnvChecks(probes, { platform, repoRoot })` returns `{ rows: [{ item, status: 'ok' | 'warn' | 'fail', detail }], exitCode }`; `formatRows(rows)` prints one aligned line per item. Probes are injected (`nodeVersion()`, `pnpmVersion()`, `packageManager()`, `fvmFlutterVersion()`, `pinnedFlutter()`, `dockerReachable()`, `gitConfig(key)`, `lsFilesEol()`, `which(cmd)`), so tests never spawn tools.
   - Items and rules (spec criterion 2): Node major = 24 (else `fail`); `pnpm --version` = `packageManager` version (else `fail`); Flutter version from the FVM SDK (`readPinnedVersion` / `resolveFlutterRoot` in `scripts/lib/flutter-sdk.mjs`) = `.fvmrc` (missing SDK → `fail` with `fvm install`); Docker: `docker info --format {{.ServerVersion}}` with a timeout (`fail` naming "Docker Desktop → Settings → Resources → WSL integration"); `git config core.autocrlf` = `true` → `fail`; `git ls-files --eol` entries with `i/crlf` → `fail` listing up to 10 paths; on Linux: repo root under `/mnt/` → `fail` (slow I/O, file watching, permissions; fix: clone into `~/src/shifa`), `bwrap` and `socat` on PATH (else `fail` with `sudo apt install bubblewrap socat`); on `win32`: one `warn` "sandbox unavailable on Windows; use WSL2 (docs/process/wsl2-setup.md)".
   - Privacy: detail strings carry versions, the tool name and repo-relative paths only; the module never reads `process.env` values or `.env*` files, never prints the home directory or absolute tool paths.
   - `scripts/env-check.mjs` — CLI wiring the real probes (`spawnSync` with `process.execPath` / argument arrays; `pnpm` through the same Windows shim handling as `scripts/verify.mjs`), prints the table, exits 1 on any `fail`.
   - `package.json`: `"env:check": "node scripts/env-check.mjs"` (not `doctor`, a pnpm built-in).
3. **Sandbox settings** (`.claude/settings.json`): keep `sandbox.enabled: true` and the exact-domain allowlist. Confirm in acceptance what `pnpm install`, `fvm install`, `pub get` and `gh` need; add only exact domains that are proven necessary (candidates: `codeload.github.com` for `gh`/git archives) and record why in the commit. Testcontainers talks to the Docker socket and to mapped `localhost` ports. ~~If `verify:full` fails inside the sandbox, add the Docker socket to `sandbox.network.allowUnixSockets`~~ — dropped after the security review: on Linux the only option is `allowAllUnixSockets`, which opens the Docker socket (a container mounting `/`) and the WSL interop socket (Windows programs outside bubblewrap). Instead (owner, OD-24): `allowUnsandboxedCommands: false`, Docker-backed tests run in CI and the owner's terminal. Owner decisions OD-25 (WebFetch stays) and OD-26 (`filesystem.denyRead` for `~/.ssh`, the Claude credentials file, `/mnt/c`, `/mnt/d`; fine-grained gh token). `scripts/test/sandbox-policy.test.mjs` pins the keys, the weakening keys that must stay unset and the exact domain list. No `excludedCommands` and no wildcard domains.
4. **Guide** `docs/process/wsl2-setup.md` (criterion 1, edge cases): `wsl --install -d Ubuntu-26.04`; `%UserProfile%\.wslconfig` memory limit and `/etc/wsl.conf` `systemd=true`; Docker Desktop WSL integration; Node 24 from `.nvmrc` (fnm or nvm, `--use-on-cd`) and pnpm from `packageManager` via Corepack; `dart pub global activate fvm 4.3.2` + `fvm install`; `sudo apt install bubblewrap socat git`; git identity, `core.autocrlf false`, `gh auth login`; `git clone` into `~/src/shifa` (never `/mnt/d`); `.env` files created fresh from `.env.example` where one exists (never copied from Windows, never production values); opening the folder in the Claude desktop app and VS Code (Remote - WSL); `pnpm install`, `pnpm env:check`, `pnpm verify:full`; two checkouts are independent clones (push from one, pull in the other, never share a working tree); a troubleshooting table matching every `env:check` failure.
5. **Doc updates** (criterion 7): root `CLAUDE.md` Commands (`pnpm env:check`) and Gotchas (WSL2 primary, Windows unsandboxed fallback, link the guide); `docs/README.md` links the guide; `docs/process/development-workflow.md` §10 Environment line; `docs/compliance/data-handling.md` §1 (Windows fallback row: synthetic data only, no sandbox); roadmap line (checked after acceptance).

## Risks
- Docker socket or `localhost` ports blocked by the sandbox break Testcontainers inside a sandboxed session (plan step 3 fallback).
- The Claude desktop app's support for a WSL folder may differ from the CLI; the guide gives the CLI path (`claude` inside the Ubuntu shell) as the fallback.
- `fvm install` may fetch from a host not on the list; acceptance step 2 shows it.
- Sandboxed writes are limited to the project, so installs that write home-folder caches fail inside a session; acceptance step 3 records which, and `allowWrite` entries are added only with evidence.
- WebFetch is outside the sandbox (OD-25, accepted); the sandbox limits egress of shell commands to the listed hosts, it does not stop every way data can leave.
- The installed Claude Code reports a native Windows sandbox (Git Bash); the docs' "no sandbox on Windows" premise is not re-checked here (backlog).
