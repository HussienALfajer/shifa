# 0.4-08 Flutter theme and base widgets (`packages/shifa_ui`)

Status: Planned · Tier: T1 · Branch: `feat/0.4-08-flutter-theme-and-widgets`
Spec: [0.4 Design system foundations](../specs/design-system/0.4-design-system-foundations.md) criterion 10 · Requirements: none · Decisions: ADR-0011, ADR-0012, ADR-0039, OD-56

After [0.4-02](0.4-02-design-directions-and-fonts.md) (needs the chosen values; independent of the web slices, so it may run in parallel with 0.4-03 to 0.4-07 in its own worktree).

## Goal
The patient app can be built from `shifa_ui`: a light and a dark theme generated from the same tokens as the web, and eight base widgets that look like the chosen design language in RTL.

## Choices made by this plan
- **Design sheet first (ADR-0040):** the eight widgets are drawn on phone artboards (390 × 844, RTL, light and dark, all states) in the proposals canvas and approved by the owner before the first widget is coded. The sheet is a visual reference, not a pixel contract: the goldens are the check. Flutter widgets are not synced to the design system (it holds web components); the approved sheet stays as their reference.
- **`flutter_test` in the workspace:** the conflict with the Dart client's `build_runner` (backlog, 0.4-01) must be solved before this slice starts; goldens need `flutter_test`.
- **Theme:** `ThemeExtension`s (`ShifaColors`, `ShifaTypography`, `ShifaSpacing`, `ShifaShapes`, `ShifaMotion`, `ShifaStatusColors`) built from `tokens.g.dart` (0.4-01); `ShifaTheme.light()` and `.dark()` return a `ThemeData` carrying them; `context.shifa` gives typed access. Status colours come only from `ShifaStatusColors` (locked).
- **Widgets on Flutter's own widget layer**, not Material defaults (design doc): `ShifaButton` (primary, secondary, ghost, danger; loading), `ShifaTextField` (label, hint, error; both digit styles on input), `ShifaCard`, `ShifaChip`, `ShifaListItem`, `ShifaAppBar`, `ShifaBottomSheet`, `ShifaSnackbar`. Touch targets at least 48 dp; `Semantics` labels; text scales to 200 %; implicit animations from the motion tokens, off when the platform asks for reduced motion.
- **Fonts:** TTF files copied from `packages/tokens/fonts` into `packages/shifa_ui/fonts/` by the tokens build, as a generated output under the same drift check; declared in the package `pubspec.yaml`.
- **Goldens:** alchemist (exact pin), each widget in RTL × light and dark with its states in one `GoldenTestGroup`; CI goldens (platform-independent text rendering) are committed and compared in `verify`; readable platform goldens are git-ignored and for local viewing only.
- **Not in this slice:** queue position card, doctor card, appointment card, record items and Rive animations (design doc list): they come with the patient app in Phase A. `/flutter-screen` skill: with the first Flutter app slice.

## Plan
1. Contracts, database, API, web: none.
2. **Tokens build:** font copy output; drift check covers it.
3. **Flutter:** theme extensions and `ShifaTheme`; then the eight widgets, each with its failing golden and widget tests first; `packages/shifa_ui/CLAUDE.md` (pattern to copy, golden update command through `scripts/dart.mjs`).
4. **Docs:** design doc "Flutter design system" (what ships now, what waits for Phase A); roadmap; Phase 0.4 exit line.
