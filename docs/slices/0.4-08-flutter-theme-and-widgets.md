## Goal
The patient app can be built from `shifa_ui`: a light and a dark theme generated from the same tokens as the web, and eight base widgets that look like the chosen design language in RTL, tested with `flutter_test` in the same pub workspace as the Dart client.

The only `test` release on `test_api` 0.7.12 is 1.31.1, which needs `analyzer` < 14. `build_runner` 2.17.1 (and `json_serializable`, `retrofit_generator`, `swagger_parser`) need `analyzer` ^14 (locked today: 14.7.0). - `test` 1.33.0 (today's lock) needs `test_api` 0.7.15, so the members' `test: ^1.33.0` becomes `test: 1.32.0` until a Flutter release pins 0.7.15.

- **Design sheet first (ADR-0040):** the eight widgets are drawn on phone artboards (390 × 844, RTL, light and dark, all states) in the Shifa design project with the Shifa Design System and the Shifa Guide, and approved by the owner before the first widget is coded. The sheet is a visual reference, not a pixel contract: the goldens are the check. Flutter widgets are not synced to the design system (it holds web components); the approved sheet stays as their reference.
- **Theme:** `ThemeExtension`s (`ShifaColors`, `ShifaTypography`, `ShifaSpacing`, `ShifaShapes`, `ShifaMotion`, `ShifaStatusColors`) built from `tokens.g.dart` (0.4-01); `ShifaTheme.light()` and `.dark()` return a `ThemeData` carrying them; `context.shifa` gives typed access. Status colours come only from `ShifaStatusColors` (locked).
- **Widgets on Flutter's own widget layer**, not Material defaults (design doc): `ShifaButton` (primary, secondary, ghost, danger; loading), `ShifaTextField` (label, hint, error; Arabic-Indic digits typed are shown and returned as Western, OD-20), `ShifaCard`, `ShifaChip`, `ShifaListItem`, `ShifaAppBar`, `ShifaBottomSheet`, `ShifaSnackbar`. Touch targets at least 48 dp; `Semantics` labels; text scales to 200 %; implicit animations from the motion tokens, off when the platform asks for reduced motion.
- **Fonts:** TTF files copied from `packages/tokens/fonts` into `packages/shifa_ui/fonts/` by the tokens build, as a generated output under the same drift check; declared in the package `pubspec.yaml`.
- **Goldens:** alchemist (exact pin), each widget in RTL × light and dark with its states in one `GoldenTestGroup`; CI goldens (platform-independent text rendering) are committed and compared in `verify`; readable platform goldens are git-ignored and for local viewing only.
- **Not in this slice:** queue position card, doctor card, appointment card, record items and Rive animations (design doc list): they come with the patient app in Phase A. `/flutter-screen` skill: with the first Flutter app slice.

## Differences from the plan (explained)
- **No `ThemeData`:** Flutter 3.50.1 deprecates `package:flutter/material.dart` (Material moves to the `material_ui` package), and the design doc builds `shifa_ui` on the widgets layer, not on Material. So `ShifaTheme` is `shifa_ui`'s own inherited theme (`ShifaTheme(data: ShifaThemeData.light(), child: …)`, `context.shifa`) holding the same six parts (colours, typography, spacing, shapes, motion, status colours), each with `lerp`; there is no `ThemeExtension` and no dependency on `material_ui`. An app that also uses `material_ui` can wrap the same data later.
- **Touch target 48 dp, not the 44 px token:** `size.target.min` is 44 (the web rule); the sheet and `ShifaSpacing.touchTarget` use 48 (`space.12`), Android's minimum, as the plan says.
- **Two locked tests corrected in the red phase** (before any implementation passed them): `theme_test.dart` compared a `Cubic` with `==` (Cubic has no value equality; now its four control points) and caught a `FlutterError` inside a builder (`avoid_catching_errors`; now `throwsA(isA<FlutterError>())`). Neither change weakens what is checked.
- **Fonts output is binary:** `build()` stays the four text outputs; `flutterFonts()` returns the TTF and OFL copies and the CLI writes both. The `tokens` drift check now takes the whole `packages/tokens/fonts` as input and `packages/shifa_ui/fonts` as output; the edit hook refuses edits there (generated).
- **Two helpers beyond the eight widgets:** `ShifaIconButton` (the app bar's back and actions, the sheet's and the error snackbar's close button) and `ShifaSpinner` (the busy button's mark, the web Spinner's petals), with `ShifaGlyph` (Phosphor glyphs painted in code; no Material icons). `ShifaPressable` (shared press, focus and semantics behaviour) is internal.
- **Snackbar and sheet API:** `ShifaSnackbar.show(context, …)` needs one `ShifaSnackbarHost` around the screens (one message at a time on a phone; 4 s, an error stays until closed); `showShifaBottomSheet` pushes a route on the nearest `Navigator` (scrim named «إغلاق اللوحة», so it does not share the close button's name).
- **More locked-test corrections in the red phase:** imports (`dart:ui` for `SemanticsValidationResult` and `Tristate`, unused ones removed), `Tristate` flags compared with `Tristate.isTrue`/`isFalse`, a `pumpAndSettle` after a theme switch (the fill animates 150 ms), golden scenario names in English (alchemist's caption font has no Arabic) and focus goldens one theme at a time (one widget holds focus). No assertion was loosened.
- **Harness bug found in checkpoint E:** the `pumpPhone` overlay kept its first child when a test pumped twice; it now gets a new key per pump. The tests that pump twice (button variants, primary fill per theme, list item heights) pass with it.
- **Sheet differences:** the sheet's list row with a status pill is a plain trailing text in the golden (the pill is the web Badge; a Flutter badge waits for Phase A); the light card's pressed tint (`selection.subtle`) is faint next to white, as on the web.
- **Spike pubspecs:** the `flutter:` constraint of the two Flutter spike probes moved to 3.50.1 with the pin (otherwise their workflows refuse the SDK); nothing else in the spikes changed.
