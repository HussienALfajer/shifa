## Goal
The super admin posts plain-text announcements to all or selected clinics and every targeted member sees and dismisses them; the platform keeps a daily counter per clinic and the clinics list shows last activity and sign-ins.

## Plan
1. **Contracts** — `Announcement` (body ≤ 280 plain text, level `info | warning`, starts_at, ends_at, target `all | selected` with clinic ids, status `scheduled | active | ended`), create, edit and end requests; `ActiveAnnouncements` for clinic web; `UsageDay` (day, key → value), `ClinicUsage` (today, 30 days, last activity); `ClinicSummary` gains `lastActivityAt` and `signIns7d` (additive); codes `announcement_body_invalid`, `announcement_ended`.
2. **Database** (`/db-migration`, `/rls-policy`; expand only)
   - `announcement` (platform table) and `announcement_target` (tenant_id, FORCE RLS; `shifa_app` reads its own); `announcement_dismissal` (user id, announcement id; per person across devices and clinics; `shifa_app` inserts and reads only the current user's rows).
   - `usage_daily` (tenant_id, day in Asia/Damascus, key, value; unique per tenant, day, key): FORCE RLS; written by an upsert on the paths that count; `shifa_platform` reads all for the console.
   - `tenant.last_activity_at` (or a `usage_daily` read; the slice picks the cheaper and says why).
3. **API**
   - Announcements: platform `GET /platform/announcements?status=`, `POST`, `PATCH /:id`, `POST /:id/end`; the body refuses links (URL and domain patterns) and markup, stored and returned as plain text; clinic `GET /announcements/active` (`@SignedIn` with an active clinic, support sessions included) and `POST /announcements/:id/dismiss` (allowed for the person, never in a support session: 403 as every write).
   - Usage keys in code (`USAGE_KEYS`, later specs add theirs): `sign_ins`, `members_signed_in` (distinct per day, no list of people kept beyond the day), `active_members`, `active_branches`; counted on sign-in (auth path, the sign-in's clinic) and when members or branches change; last activity on the principal's request touch (at most once a minute, as `membership.last_active_at`).
   - Platform: `GET /platform/clinics/:id/usage` (30 days); clinics list gains the two columns.
   - Audit: `announcement.created`, `announcement.edited`, `announcement.ended` (ids, level, target count; never the body).
4. **Web, Flutter** — none (UI code slices A-02-08, A-02-09, A-02-10).
5. **End-to-end** — none.

Tests written first: body rules (length, a link, markup refused) (16); targeting all and selected, scheduled not shown, ended not shown (16); dismissal per person across two sessions and kept across clinics (16); end early and edit (16); usage counters against seeded sign-ins, the Damascus day boundary on a fake clock, distinct members (17); clinics list columns and 30-day series (17); audit rows without the body (18); isolation cases for `announcement_target`, `announcement_dismissal`, `usage_daily`.

## As built (changes from the plan, reported to the owner)
- **Contracts** (`packages/contracts/src/announcements.ts`, `usage.ts`): `Announcement` (`id`, `version`, `body`, `level`, `startsAt`, `endsAt`, `status`, `endedEarly`, `endedByName`, `target`, `clinics[]`, `createdByName`, `createdAt`, `dismissedCount`, `targetedMembers`), `AnnouncementList` (`counts`, `announcements`), `CreateAnnouncementRequest`, `UpdateAnnouncementRequest`, `MyAnnouncements`, `DismissAnnouncementRequest` (`version`); `ClinicUsage` (`today`, `hasData`, `todayCounts`, `members`, `branches`, `lastActivityAt`, 30 `days`, `previousTotals`); `ClinicSummary` gains `lastActivityAt` and `signIns7d` (`ClinicDetail` does not). Codes 400 `announcement_link`, 409 `announcement_ended` (the contract's names; the plan's `announcement_body_invalid` is not used). `hasAnnouncementLink()` (hardened after security review S1): matched on a copy folded by NFKC, with dot look-alikes turned into a dot and invisible characters removed; refuses a bidirectional override, a scheme (`x://`), `www.`, an e-mail, a host (a name in any script, a dot, an ASCII top-level domain or an Arabic country one), an IPv4 address, a tag or an entity; Arabic sentences joined by a full stop, decimals and abbreviations pass. A phone or WhatsApp number passes: OD-133, open, for the owner. Arabic texts of the two codes in `packages/i18n/src/locales/ar/errors.json` for the owner's review. The only field beyond the contract rows is `Announcement.version` (the banner's dismissal needs it); additive.
- **Routes:** `GET /platform/announcements?status=`, `POST /platform/announcements`, `PATCH /platform/announcements/:id`, `POST /platform/announcements/:id/end` (`@PlatformAdmin`, one `withPlatformAdmin()` each, 404 for an unknown id); `GET /me/announcements`, `POST /me/announcements/:id/dismiss` (204; 404 when not active for the clinic or the version is above the current) on `clinic.capabilities.view`, which every clinic role and the support session's synthesised owner hold: no new permission key; the guard refuses the dismissal in a support session (403 `support_read_only`). `GET /platform/clinics/:id/usage` (`clinic.usage_viewed`, 404 for an unknown clinic); `GET /platform/clinics` gains the two columns.
- **Rules:** a new version only when the body or the level changes (an edit of the period or the clinics keeps dismissals). Cancelling a scheduled announcement is ending it: `endsAt` = now (before its start), `endedEarly`, `endedByName`. The end must be after the start and not past (400 `body.endsAt`); `selected` needs existing clinics (400 `body.clinicIds`: `custom` when empty or given with `all`, `invalid_value` for an unknown one). Status is never stored: the API's clock decides it.
- **Database:** `20261127101855_a02_announcements_usage` (expand: `announcement`, `announcement_target`, `announcement_dismissal`, `usage_daily`, `membership.last_sign_in_on`) and `20261127101856_a02_announcement_usage_policies` (RLS, grants, policies, the two functions); rollback notes in the SQL header. `announcement` (global): shifa_platform reads it in announcement actions, inserts only in `announcement.created` as its own author, updates by column only in edited and ended (an end names the acting super admin); the trigger `announcement_change_guard()` keeps each action to its columns (security review S2: an end sets only the end, now or earlier, and who ended it, once; an edit never touches who ended it and moves the version by one at most); shifa_app reads seven columns (never the authors) of the ones aimed at its clinic, never a cancelled one (`ends_at > starts_at`, security N1). `announcement_target` (tenant, read-only for shifa_app): shifa_platform reads across clinics in announcement actions, writes in created and edited, deletes in edited only (restrictive). `announcement_dismissal` (global, a person's own): shifa_app inserts and updates the signed-in person's row for an announcement its clinic can see, a version not above the current; every role reads app.user_id's rows only; nobody deletes. `usage_daily` (tenant): shifa_app reads and writes its own; shifa_platform reads every clinic's in `clinic.listed` and `clinic.usage_viewed` only. No announcement is ever deleted.
- **The clinic read policy filters by target only, not time** (changed in the first test draft, before any code): the API's injected clock decides active, scheduled and ended, as every other time rule of the API; a database `now()` filter would disagree with it. shifa_app can read the seven columns of a scheduled or ended announcement aimed at its clinic; the routes never show them.
- **Usage keys** (`USAGE_KEYS`): `sign_ins`, `members_signed_in`, `active_members`, `active_branches`, plus `last_activity_minute` (the clinic's last request, minutes since the epoch, kept with `greatest()`). **Last activity is a `usage_daily` row, not `tenant.last_activity_at`:** cheaper, because it is written in the same clinic transaction as the request's `membership.last_active_at` touch (at most once a minute per member), needs no UPDATE grant on `tenant` (A-02-06 had just removed shifa_app's) and is read in the same grouped query as `signIns7d`. **Members signed in** count once a day through `membership.last_sign_in_on` (the member's last sign-in day only, no list of people; a shifa_app column grant). A sign-in counts in its clinic at `POST /auth/sign-in`; a session that starts without a clinic counts on its first `POST /me/switch`; a switch between clinics does not (the session row's clinic decides, not the principal's: a suspended clinic leaves the principal without one). A setup link's first session counts in its clinic (OD-134, reviewer finding 1: otherwise a clinic onboarded today shows as inactive for seven days). `active_members` (accepted, not deactivated) and `active_branches` (non-archived) are written with each sign-in and when a member is deactivated or reactivated, an invitation accepted, a branch added, archived or restored; the usage view reads today's two figures live from `clinic_member_counts()`.
- **Counts (criterion 22, ADR-0051):** `announcement_counts(ids[], versions[], all[], tenants[])` → `(ord, targeted, dismissed)`: for each clinic passed (every clinic, from `tenant`), under its own policies, the non-deactivated members (pending included) of the announcements aimed at it, and those with an account who hid the current version (read with app.user_id set per member); settings restored; announcement actions only; arrays capped at 10000. `clinic_member_counts(tenant)` → `(members, active_members, branches)` in `clinic.usage_viewed` only. Both in `COUNT_FUNCTIONS`, pinned by `privileges.test.ts`.
- **Audit (criterion 18):** `announcement.created`, `announcement.edited`, `announcement.ended` (target the announcement; data `level`, `target`, `clinics` = the number of clinics; never the body), `announcement.listed`, `clinic.usage_viewed` (target the clinic).
- **Contract rows proven:** `A02Announcements` list (`list`, `scheduled`, `ended`, `empty` counts), create (`form`, `formSome`, `linkError`, `created`), edit, end early and cancel (`endAsk`); clinic web banner and `dismissed`; usage (`use`, `useMembers`, `useEmpty`) and the clinics list columns. No drawing changes.
- **Existing tests changed:** privilege and column-privilege pins, the route matrix (the A-02 console samples moved to `route-matrix.samples.ts`: the file had passed 400 lines), table-access, the OpenAPI path list, the contracts' `ClinicSummary` fixture, the clients' response fixtures and Dart decoders, web-shell's screen world (`lastActivityAt: null`, `signIns7d: 0`).
